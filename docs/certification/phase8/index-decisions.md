# Phase 8 query/index decisions

The prior read-only production catalog is retained in `docs/tasks/phase8-evidence/`. Its table statistics are estimates, not exact counts or a timed usage interval. Production has no pg_stat_statements; this task neither installed it nor enabled SQL logging, reset counters, or ran production ANALYZE/load tests.

The named contacts assigned-to, enrollment contact/status and deals pipeline/stage indexes already exist and are valid. The old roadmap missing-index hypotheses are closed; no speculative duplicate index is added. Audit history is keyed through `audit_logs.entity_type/entity_id` (and text entity_key for other readers), not an invented contact_id column; see contacts route communication-event history and current native schema.

The local experiment (`scripts/certification/test-phase8-indexes.ts`) populates 160,000 synthetic contacts, 1,600 deals and 1,900,000 audit rows. It mirrors the four observed production alias/retained pairs explicitly: one historical contact index is not installed by the fresh journal, so the test creates the observed catalog before comparing. Native pg_index checks include key/include count, expressions, predicates, access method, opclass, collation, order, uniqueness, validity, constraint and pg_depend ownership. Each query uses five warmups and thirty measured samples plus EXPLAIN ANALYZE BUFFERS; IDs and ordering are compared. Both alias removal and write trials are rolled back in the disposable database. No customer data is copied.

**Decision: retain all four installed production aliases for this release.** Native equivalence and returned-fact parity passed locally, but a single shared-host timing run is insufficient to justify DDL. The first experiment's contact write trial was 38.24 ms before / 57.98 ms after; empty-query relative p95 percentages were noisy at fractions of a millisecond. This is not a repeatable improvement, cold-cache qualification, workload-wide proof or production SLA. The enrollment workload was empty and is explicitly not a populated enrollment performance claim. Full raw plans/parameters/rows/buffers/timings are retained in the private run output `generated-artifacts/phase8/index-workload.json`; a sanitized copy is included with final evidence.

The confirmed source defect is that post-merge replayed `server/add-indexes.sql` and an old journal outside the journal owner. That replay is removed; four alias definitions are removed from the historical manual file. The remaining SQL is marked historical/manual, never a startup or deployment instruction. Existing production objects are preserved. A future consolidation requires a bounded real workload/usage interval, repeatable cold/warm/write evidence, fresh dependency checks, exact recreation SQL and managed migration review. No permission for that future production action is implied here.
