## Verdicts by layer

- **Application and review functionality — PASS at fixture and browser layers.** The real wizard payload is accepted by the real finalize route; protected values are stored encrypted; review confirmation gates Submit; the confirmation page shows the saved reference and states truthfully when the agreement has not been sent. Underwriting, conditions and override journeys pass.
- **Protected data and security — PASS at fixture layer.** `test-merchant-application-security` 273/0 (three source-pattern assertions were updated to the new shared per-kind dispatcher; they were not weakened), responses never echo protected values, agent/merchant/partner roles are denied on operator, registry and create routes (handler layer and browser), capability/token handling unchanged. `compliance-scan` passes (96 call sites); the underwriting chase call site's reviewed entry was re-pointed to the new call shape.
- **Processor/MID command integrity — PASS at fixture layer; provider denied.** Unknown outcomes are held and never auto-retried; idempotency key bound to one deal/application/processor; kill lines 18/18; no provider call was made in any run (`externalCalls() === 0`).
- **UI, roles, accessibility and performance — PASS for the focused journeys.** Browser: Underwriting (1280 light/dark, 768 dark, 390 light, paging, real-pointer override), Merchant Applications list and detail, MID registry (1280 light, 768 dark, 390 light, status filter, Close MID dialog), agent/merchant/partner denials, BoardingPanel (blockers with disabled submit at 1280 light and 390 dark; a ready deal queues exactly one outbox row and shows the Queued state), public wizard (390 dark missing-field guidance with focus movement; 1280 light full journey). Targets are 44px and no horizontal overflow was found at 390px. No load/performance benchmark beyond the >500-fixture read-model run was performed.
- **Installed schema, release and rollback — fixture only.** Migrations `0380` and `0381` apply cleanly on the disposable database and `check-migration-integrity` passes (1009 checks; two historical duplicate-timestamp warnings predate Stage 5). The journal entries are text-appended and `0380` was not edited after it was applied. **Production does not have `0381` installed**: production serves the earlier build and migrations run only when the owner publishes. Rollback: `0381` is additive and the old code ignores the new columns, so reverting the application does not require reverting the schema. `0380` is not reversible: it cleared `created_by`/`updated_by` on `underwriting_conditions` because they held contact ids, not actors; the real actor evidence for later commands is in `audit_logs` and the string actor columns. Restoring the cleared values is not possible.
- **Native / production — NOT RUN.** No production write, activation snapshot, boarding submission, e-sign, backfill, form, decision, MID edit or publish. `native-packet.md` lists the read-only queries and the proposed, unexecuted steps (snapshot base-URL correction, `boarding.policy.matrix.v1` shape). The policy matrix is unrecorded, so real boarding fails closed until the owner records it.
- **Release — not published.** The final candidate is the working tree described above; outbound pauses (epoch 1), outgoing GHL (disabled, epoch 16) and incoming GHL were not touched.
