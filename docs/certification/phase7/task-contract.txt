2163 - Phase 7 Conversion Optimization
What & Why
Build all of Phase 7 (conversion optimization) in one task by extending the experiment, content, reporting and public-site systems that already exist. It has four tracks: (P7-1) trustworthy A/B experiments, (P7-2) a vertical copy audit with three refreshed verticals, (P7-3) one authoritative seven-stage funnel report with attribution, and (P7-4) public mobile completion.
Why now: a preflight against live code and read-only production data confirmed the external audit's main findings. A/B infrastructure already exists but cannot be trusted for decisions. Winner adoption bypasses frozen assignment, results can be written through generic step edits, experiment samples are arbitrary counters, frozen rules are not enforced, and no real exposure data exists yet. The existing "funnel" is an event-count chart, not a cohort funnel. Replacing these systems would duplicate them, so the work repairs and connects them.
This task authorizes engineering, draft content, isolated-database migrations and certification, and a publish-ready result. It does not authorize any send, outbound unpause, enrollment/campaign release, provider spend, native GHL workflow install, Gmail connection, production reclassification, historical replay, or automatic winner promotion. Real campaign results, the 90-day observation requirement, owner-supplied evidence and real-device checks keep their true status as separate acceptance rows.
Preflight verdict: APPROVED FOR BUILD — CORRECTIONS INCORPORATED. No conflicting authority, unsafe provisioning assumption or missing prerequisite blocks building. The verified findings and corrections are under "Preflight verification" below. The full controlling specification (the attached audit with corrections applied) follows it and must be treated as part of this plan.
Done looks like
Every generic step create/update/full-editor path refuses result, counter, approval and actor fields. A forged payload changes no stored result and no sender choice.
One canonical experiment owner: a frozen, canonically hashed two-arm design bound to approved content versions (subject-only for the first tests). Stable business-level allocation. Frozen minimums per arm, minimum duration, maturity window and guardrails are enforced. A stopped, cancelled, revoked or superseded experiment can never produce a winner handoff.
Exposure is recorded only from a definitive sent/accepted receipt tied to the final rendered content hash. Failed-then-retried sends count exactly once without rewriting history. Verified outcomes (reply, click, open, bounce, complaint, opt-out) attach to real message/provider IDs, never to a caller-supplied key.
One evaluator path (scheduler, manual and SLA callers all enter it) with writes fenced by lease and experiment revision. A fixed-horizon statistical method with independent calculation fixtures. A recommendation only: a human accepts it through a version-bound decision, which creates a NEW draft version through the existing content owner and changes no live recipient.
Complete installed-copy inventory with IDs, versions and hashes, and review-ready drafts for the top three verticals (ranked from verified data, or labelled as a volume-based pilot selection if evidence is insufficient). Three complete subject-test designs exist as drafts with previews of both arms, a dry-run population report, no admissions and no sends.
One versioned cohort-funnel read contract (Lead → Engaged → Statement Requested → Statement Received → Proposal Sent → Application → Closed Won) with drilldown, breakdowns by vertical/rep/source/campaign, protected full export, honest unknown/unlinked/unavailable states, and America/New_York day boundaries. Existing Today, Growth, Operations, SDR and Outreach readers are reconciled or relabelled so no two panels claim the same metric with different hidden populations.
Reports and Sequences UI extended inside the existing eleven-entry workspace with namespaced URL state, branded layouts, all read/error/permission states, and certified widths and modes.
Public mobile residual checks re-run on the final build across all inspected public routes, with truthful provenance and image records. A real-device/WebKit pass is either done or left as NOT EXERCISED with an exact checklist.
Every P7-01–P7-48 row has a disposition with failing-before/passing-after evidence and negative controls. Required gates are registered in both pre-deploy and CI manifests. The Phase 7 certification record is complete, with engineering, merged, published, schema-verified, live-readback, copy-review, live-experiment, measurement and device acceptance kept as separate states.
Zero unauthorized sends, admissions, automatic winner promotions, provider spend or unrelated production changes. The owner receives one precise publish/approval handoff.
