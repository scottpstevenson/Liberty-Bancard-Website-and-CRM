# Offline conversion integration

Authorized scope: complete the offline integration and disable Ads auto-apply, with campaigns off, outbound paused, cap unchanged and no publication.

Chosen approach: a first-party durable outbox and Google Data Manager v1, the supported API for new integrations. CSV-only reporting cannot provide delivery or crash recovery; the legacy Ads upload API is restricted for new integrations. Use click-only events, no email/phone hashing, no inferred monetary value. One event per provider request makes diagnostics unambiguous. Google accepted-for-processing and processed-success are distinct states; neither proves ad attribution.

Capture a new explicit advertising-measurement preference with accepted inbound requests, freeze encrypted click attribution against the request and its contact, and never infer historical consent from email/SMS permissions. Preserve old preferences without silently enabling this additional sharing. Anonymous revocation uses an unguessable first-party capability and blocks future dispatch. Derive Closed Won from existing append-only canonical conversion evidence, pinned to the deal's own inbound request. Record qualified leads through an explicit staff review command; enrichment scores and broad recipient eligibility are not sales qualification. No historical backfill or automatic publication.

Admin controls expose readiness, counts, qualification, validation and bounded processing. A dedicated opt-in non-sending worker runs the same owner. The upload flag stays off by default; Google authorization and destination verification remain separate from outbound. Persist source/event uniqueness, frozen destination, claim fencing, request receipt and diagnostics. Never blindly resend uncertain dispatches. Retry only explicit transient rejection; interrupted dispatch becomes uncertain, interrupted polling retains its request ID and only polls.

Checks: real disposable PostgreSQL sessions/routes and migrations, source lineage, consent denial/revocation, concurrent claims, duplicate qualification, canonical Closed Won recovery, payload contract, validate-only isolation, asynchronous success/failed/partial/warning states, timeout recovery, authorization and preservation of pause/budget. Production Google receipt requires credentials, the published candidate and an eligible real ad click; none is invented for setup.
