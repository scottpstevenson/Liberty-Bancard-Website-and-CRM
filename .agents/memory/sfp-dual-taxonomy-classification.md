---
name: SFP dual-taxonomy vertical classification
description: How the South Florida Prospecting classifier supports two vertical taxonomies (v1 legacy five-package, v2 five broader groups) side by side without cross-contamination.
---

- `sfp-vertical-classifier.ts`'s `classifyVertical(rawVertical, targetIds, taxonomyVersion)` takes an explicit `taxonomyVersion` (1|2, default 1) and picks a fully separate alias/synonym/ambiguous/non-target table set per version. Omitting the param preserves legacy v1 behavior byte-for-byte.
- Keep taxonomy identity separate from classifier ruleset identity. Never interpret a classifier version as a taxonomy version or let evidence from another taxonomy establish admission.
  **Why:** the two supported taxonomies must coexist without cross-contaminating business qualification.
- Evidence rows also carry `resolved_vertical_id` (which of the target groups) and `admission_tier` (`resolved_high` | `resolved_medium` | null). Only `resolved_high` — the classifier's own deterministic exact-alias tier — may be used by a selector to admit a business on evidence alone. `resolved_medium` and anything reached via website-evidence promotion or OpenAI escalation leave `admission_tier` null, even though `outcome` may still be `'target'`.
- **Why:** the user explicitly required that evidence-only admission never trust anything short of the highest-confidence deterministic tier, and that a later non-deterministic promotion (website scrape, OpenAI escalation) never be mistaken for that tier.
- `roi-cohort-selector.ts`'s vertical gate, when `taxonomyVersion===2`, independently classifies the *live* `businesses.vertical` text AND looks up the latest completed evidence row at the program's current `(policy_version, classifier_version)`. Decision table: live+evidence agree → admit; live resolves but evidence exists and disagrees/doesn't corroborate → review (never admit on live text alone once evidence exists); evidence alone qualifies (resolved_high) with no live match → admit; neither resolves → excluded per evidence's outcome; no evidence row at all → live-text-only (unchanged pre-evidence behavior).
- **How to apply:** thread the same taxonomy through classification and selection; scope current evidence by policy, ruleset and taxonomy together. Missing any dimension can admit stale or foreign-taxonomy evidence.
- Moving an *already-existing* SFP program from v1 to v2 is a separate explicit, audited action (`migrateProgramToTargetVerticalsV2` in `south-florida-prospecting.ts`) that also bumps `policy_version` so old v1-scored cohort members never silently reappear as v2-admissible. Brand-new program creation (`ensureProgram`) defaults straight to v2.
