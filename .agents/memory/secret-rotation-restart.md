---
name: Secret rotation requires workflow restart
description: New/changed env secrets are not picked up by an already-running server process
---

Setting or changing a secret/env var (e.g. via task-agent merge or the environment-secrets flow) does not affect a process that is already running — it only takes effect for processes started after the change.

**Why:** After a dedicated `UNSUBSCRIBE_TOKEN_SECRET` was added (replacing a `SESSION_SECRET` fallback), the live server kept verifying HMAC tokens against the old secret it loaded at boot, causing valid tokens generated by a fresh script (which saw the new env var) to fail live HTTP verification with 400 instead of 200. Restarting the workflow fixed it immediately.

**How to apply:** Whenever a task/merge changes a secret that a long-running workflow depends on (auth secrets, token signing keys, API keys read once at startup), restart the affected workflow before re-running verification/smoke tests. If a live-HTTP check fails right after a secret-related merge but a library-level/local check passes, suspect a stale in-process secret first, not a real regression.
