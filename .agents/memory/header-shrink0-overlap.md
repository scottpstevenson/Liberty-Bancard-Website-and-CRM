---
name: Dashboard header shrink-0 sibling overlap on mobile
description: Why the sidebar toggle / navbar buttons became untappable on narrow viewports, and the fix pattern.
---

The dashboard header (`DashboardLayout.tsx`) is a flex row with two children: a left group (sidebar toggle + page title, `min-w-0`) and a right group (search + notification/theme/compose icons, previously `shrink-0`). On narrow (mobile) viewports the right group's natural content width (search bar + 3 icon buttons) exceeded the available header width. Because the right group had `shrink-0` and the left group had `min-w-0` with no floor, ALL of the negative space was forced onto the left group, collapsing it to a computed width of 0 — even though its child (the sidebar toggle button) still rendered visually via CSS overflow. The right group's search input then painted on top of that 0-width box in normal document flow, silently swallowing all taps intended for the sidebar toggle and any other left-side controls, on every dashboard page (not page-specific).

**Why:** Playwright's `elementHandle.click()` actionability check ("element intercepts pointer events") is what surfaces this reliably — visually the overlap can be invisible/subtle since the covering element is the same background color as the header, so a plain screenshot alone did not reveal it; only interaction testing (or `document.elementFromPoint` at the target's bounding-box center) caught it.

**How to apply:** When a header/toolbar has one shrink-0 group and one min-w-0 group and the shrink-0 group can overflow at small viewports, share the shrink burden — remove blanket `shrink-0` from the group as a whole, wrap only the truly fixed-size icon buttons in their own inner `shrink-0` div, and let the flexible element (search input, title, etc.) carry an explicit `min-w-0` + a mobile-appropriate `max-w-[…]` cap so it shrinks first instead of forcing its sibling to zero. Give the truly-fixed element (e.g. the sidebar toggle button itself) an explicit `shrink-0` too, don't rely on the parent group's shrink-0 alone. To reproduce/verify this class of bug when no interactive browser tool is preinstalled: `npx --yes -p playwright@<pinned-version>` downloads playwright to the npx cache, and a nix-provided chromium binary is often already present at `/nix/store/*-playwright-browsers-chromium/chromium-*/chrome-linux/chrome` — launch with `executablePath` pointing there plus `args:['--no-sandbox']` to avoid needing `playwright install --with-deps` (which fails in Replit's sandboxed nix environment).
