name: Stage 5 application-to-MID patterns
description: Non-obvious rules and traps from repairing the application → underwriting → boarding → MID chain
---
- Provider sends: write a dispatch-started marker BEFORE network I/O; a marker without sent/skipped evidence = held for operator, never re-sent. Resolved `{success:false}` is not "sent"; only provably-unsent (`outcome:"unsent"`) retries.
- Processor contract: snapshot base URL exactly `https://{testapi|api}.payarc.net/v1`; never follow redirects; 429 retryable, other 4xx permanent, 5xx/408/3xx/network on POST ambiguous.
- MIDs: `merchant_mids.mid` globally unique; many per deal; `deals.mid` is only the primary alias; closed MIDs are history. Policy matrix unrecorded → boarding fails closed; certs use a synthetic recorded policy.
- Underwriting override: pin to the reviewed revision, one tx for decision+stage+audit+durable effect intents; GHL tasks run in the effect worker behind the pause authority (no GHL call in the route; allowlist entries removed).
- Chases: pin recipient/obligation versions at claim; durable next_check_at cursor so a stuck head cannot starve the batch.
- **Strict DTO + browser tracking record:** finalize is `.strict()`; the wizard must send only the five utm* fields. Spreading `getStoredUTMParams()` (landingPage, gclid, *Present) made every real submission a 400 while HTTP certs passed because they sent no tracking data. Add a cert with a realistic stored record.
- Public wizard raw fetches need `getCsrfToken()` header (signed-in operators 403 otherwise); autosave must omit null booleans (zod rejects null).
- E-sign request is refused for any not-yet-submitted status (draft AND in_progress).
- Source-pattern security asserts (`test-merchant-application-security`) break when worker code is refactored to template strings; update them to the new shape, don't loosen. That suite is DB-less: run it directly with NODE_ENV=test and a random 64-hex MERCHANT_DATA_ENCRYPTION_KEY (not registered in the disposable runner).
- Changing where a GHL/SMTP call lives requires updating `scripts/ghl-route-mutation-allowlist.ts` / `scripts/compliance-scan.ts` lineContains entries; run compliance-scan after moving send code.
- Disposable runner is in provider deny mode: NO BullMQ workers (per-suite BACKGROUND_JOB_PROFILE overrides do nothing). `test-forms.ts` therefore asserts owed states (503 + recoverable command; durable unconsumed outbox row) and reports worker steps NOT EXERCISED; it still exits 1 because estimate/get-started 400 at source: deal-linked inbound acceptance needs production-class contact+deal, but fresh public contacts/deals are `unknown` (route's outer catch hides it as a generic 400; production unverified).
- Any edit under scripts/ invalidates the browser-suite candidate identity: rebuild (background, log with EXIT=) before rerunning. Confirmation page test ids are `text-thanks-application-*` (ThanksApplication.tsx), not the in-wizard success section.
- Claim-fenced handlers (`withOwnedClaim`) need a real `processing` outbox row; certs that pass hand-built rows get a SQL syntax error (undefined `attempts` param) that makes "refused" assertions pass vacuously. Typed unsent/confirmed/unknown/wait outcomes must survive helper→outbox; clear reversal marker on re-approve; empty recipient fails closed; application→deals lock order is shared by bridge and submit; final fence runs on the lock-holding tx.
- `ci-suite-manifest --check` must also accept scripts declared in `CERTIFICATION_FIXTURE_SUITES` (public-journey lives there). Registry list state (`midStatus`/`midPage`/`midDeal`) is URL-owned. Production schema objects can exist while the Drizzle ledger lacks the migration (Publish diff); verify objects and ledger separately.

- One retry owner: outbox-owned callers of the compliant GHL workflow wrapper pass `_callerOwnsDeferral: true` (else a 429 creates a second deferred-enrollment retry). The wrapper needs `GHL_WORKFLOW_VERIFIED_CHANNELS_<ID>` env and an `email_status='valid'` contact in fixtures. Fire-and-forget callers (SDR, routes) rightly rely on the deferred path.
- Fresh public sales forms create `unknown` contact+deal. Only an actual assignment decision is immutable; review-required decisions are superseded by a later different evaluation (deduped when unchanged). Unknown deal on the same unknown contact stays inside class review; explicit nonproduction/archived/foreign-linked contexts are retained as INBOUND_CONTEXT_UNAVAILABLE (never a generic 400). Forms bind the deal via `inboundRequestId`; later review continues the SAME task via `resumeInboundSalesRequestAfterReview`. **Why:** do not promote records to production to fix the 409.
- Registry Open/Back: contact URL carries validated `from` (registry URL incl. view/status/page/deal) and `dealId`; unsafe `from` falls back to People Back; foreign deal ids show a notice, never select.
- Disposable `test-forms` exits 0 with 30 assertions after F01 (workers NOT EXERCISED); run directly against the dev server it exits 1 by design (GHL kill line when the token is set).

## Public sales-form recovery (estimate / get-started / callback)
- Bind an existing contact to the occurrence BEFORE mutating it; recovery reads only occurrence-keyed immutable evidence (source event keyed by request id, deal.inbound_request_id, the occurrence's consent fact) — never email/phone/name. A failed link bind is not fatal: evidence alone is enough to resume.
- Answer 202 `recoverable` only when real committed rows exist; otherwise the real 400. Post-accept effects (notification, tracking) run only after the authority accepts, and the notification needs a per-occurrence command key so a recovery never creates a second.
- Fault-injection triggers must not decrement or mutate inside the failing transaction; arm around one real request and disarm after. Callback has no server validation, so it cannot produce a real 400 in tests.
- Chromium silently re-sends a POST on a reset keep-alive connection; with the same Idempotency-Key that becomes a 200 replay, so browser "lost response" tests must accept a confirmed replay as well as an unresolved notice.
- Browser candidate identity covers scripts/: every edit to a browser/test script needs `npm run build` again before the browser suite; run the long browser suite in the background (>5 min with build).
