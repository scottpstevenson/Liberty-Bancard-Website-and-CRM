Here’s a polished Replit Agent prompt you can paste directly in:

Production Cleanup & Go-Live Deployment

Prepare the entire application for production launch.

The objective is to remove all development/testing artifacts, clean the database and UI, verify production functionality, and leave the application in a clean, professional, deployment-ready state.

1. Remove Demo & Test Data

Audit the entire application and database and remove all non-production data, including:

* Demo data
* Seed/demo records that are not required for production
* Smoke-test records
* QA/testing records
* Dummy records
* Fake contacts
* Fake companies/accounts
* Fake leads
* Fake opportunities/deals
* Fake support tickets
* Fake tasks
* Test activities
* Test notes
* Test conversations/messages
* Test notifications
* Test users, where safe to remove
* Old development tasks
* Placeholder records
* Sample dashboard data
* Sample analytics
* Fake revenue/performance data
* Temporary import records
* Duplicate records created during testing
* Orphaned records left from deleted test entities

Search for obvious test indicators such as:

test, demo, sample, dummy, fake, smoke, qa, sandbox, example, placeholder, seed, and similar development terminology.

Do not delete legitimate production/business data merely because a field happens to contain one of these words.

2. Protect Real Data

Before deleting anything:

1. Inspect the database schema and relationships.
2. Determine which records are clearly test/demo data versus legitimate records.
3. Preserve all legitimate contacts, companies, users, deals, tickets, communications, financial information, configurations, and integrations.
4. Preserve required system records, lookup tables, permissions, configuration tables, and production seed data.
5. Respect foreign-key relationships and dependencies.
6. Do not perform destructive schema changes unless absolutely necessary.

For ambiguous records, preserve them rather than guessing.

Create a database backup/snapshot before destructive cleanup if the environment supports it.

3. Clean Tasks & Activity

Remove:

* Smoke-test tasks
* Demo tasks
* Completed development/test tasks that should not appear in production
* Fake reminders
* Fake follow-ups
* Test calendar/activity records
* Placeholder assignments
* Test notifications

The production task system should launch cleanly without historical QA clutter.

4. Clean CRM / Business Records

Review all CRM-style entities and remove irrelevant fake records from:

* Contacts
* Companies
* Accounts
* Leads
* Opportunities
* Deals
* Pipelines
* Tickets
* Support cases
* Notes
* Activities
* Communications

Preserve legitimate pipeline configuration and workflow stages.

After cleanup, ensure relationships between real contacts, companies, tickets, deals, and activities remain intact.

5. Remove Demo UI

Audit the frontend for:

* Hard-coded demo numbers
* Fake charts
* Sample contacts
* Sample companies
* Placeholder tickets
* Fake dashboard metrics
* Hard-coded revenue
* Fake notifications
* Demo usernames
* Lorem ipsum
* Development banners
* Debug buttons
* Test controls
* Temporary navigation items
* Placeholder pages

Replace hard-coded demo content with actual database/API-driven states.

If no production data exists, show a professional empty state instead of fabricated data.

Example:

“No activity yet”

rather than displaying fake activity.

6. Production Configuration Audit

Review the application for production readiness.

Verify:

* Environment variables
* Database configuration
* Production database connection
* Authentication
* Authorization / role permissions
* API routes
* API keys and secrets
* Webhooks
* Email integrations
* External integrations
* CORS configuration
* Session/cookie security
* Error handling
* Logging
* Rate limiting where appropriate
* File storage
* Background jobs
* Scheduled jobs
* Production URLs
* Redirect URLs
* OAuth callback URLs

Never expose secrets or API keys in frontend code or logs.

7. Remove Development Artifacts

Remove or disable production-inappropriate:

* Console debugging
* Debug endpoints
* Development-only API routes
* Temporary scripts
* Smoke-test scripts that run automatically
* Test buttons
* Seed-on-start behavior
* Development authentication bypasses
* Mock API responses
* Hard-coded credentials
* Temporary admin overrides

Keep legitimate test infrastructure in the repository if useful, but ensure it cannot accidentally execute against production.

8. Validate Database Integrity

After cleanup:

* Check for orphaned records.
* Check broken foreign-key references.
* Check duplicate production records.
* Confirm migrations are current.
* Confirm required indexes exist.
* Confirm production tables initialize correctly.
* Confirm application startup does NOT recreate demo data.

Do not wipe or recreate the entire database simply to perform cleanup.

9. Production UX Audit

Review every major page as an actual user.

Check:

* Dashboard
* Contacts
* Companies/accounts
* CRM
* Deals/pipelines
* Tickets/support
* Tasks
* Notifications
* Settings
* Users/team
* Integrations
* Reports/analytics
* Search
* Forms
* Modals
* Navigation
* Mobile/responsive layouts

Fix obvious:

* Broken links
* Dead buttons
* Empty dropdowns
* Incorrect redirects
* Loading-state problems
* Error-state problems
* Overflow
* Alignment issues
* Duplicate UI elements
* Placeholder content
* Console errors

10. Authentication & Permissions

Test:

* Login
* Logout
* Session persistence
* Password/reset flows if applicable
* Protected routes
* Admin access
* Standard-user access
* Role restrictions
* Unauthorized API requests

Users must not be able to access records or administrative functionality outside their permissions.

11. End-to-End Production Smoke Test

After cleanup, run a fresh production-style smoke test.

Test the primary workflow using newly created temporary test records.

Verify:

* Create
* Read
* Update
* Delete
* Search
* Filtering
* Sorting
* Relationships
* Forms
* Notifications
* Integrations
* Authentication
* Permissions
* Error handling

After testing, delete all temporary smoke-test records created during this final test so the production environment remains clean.

12. Deployment

Once validation passes:

1. Run the production build.
2. Fix all blocking build/runtime errors.
3. Deploy using the application’s existing Replit deployment configuration.
4. Verify the deployed production URL.
5. Run a post-deployment smoke test.
6. Remove any temporary records created during that test.
7. Confirm the production application and database are clean.

13. Do Not

Do NOT:

* Rebuild the application from scratch.
* Replace working architecture unnecessarily.
* Delete legitimate business data.
* Delete required system configuration.
* Reset the entire production database unless absolutely required.
* Introduce fake data simply to make dashboards look populated.
* Change established business logic unless necessary to fix a production blocker.
* Expose secrets.
* Leave smoke-test records behind.
* Claim something was tested unless it was actually tested.

Final Deliverable

When complete, provide a concise Go-Live Report containing:

Cleanup

* Demo/test records removed
* Old tasks removed
* Fake contacts/companies/tickets removed
* Placeholder UI/data removed
* Any ambiguous records intentionally preserved

Production Validation

* Build status
* Database status
* Authentication status
* Permissions status
* Integrations status
* Core workflow status
* Responsive/UI status
* Deployment status

Issues Fixed

List every production issue discovered and corrected.

Remaining Issues

List anything that still requires attention and classify it:

* Critical
* High
* Medium
* Low

Deployment

Provide:

* Production deployment status
* Production URL
* Build/version identifier if available
* Database migration status
* Final smoke-test result

Definition of Done: The application contains no obvious demo, smoke-test, placeholder, or fake business data; no development-only UI is exposed; production configuration is secure; core workflows have been tested; the application successfully builds and deploys; post-deployment testing passes; and temporary test records have been removed.

Work carefully and systematically. Preserve real data whenever there is uncertainty.

This version tells Replit to clean the app without blindly wiping legitimate production data, then validate and deploy it.
