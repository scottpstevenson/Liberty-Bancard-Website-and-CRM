That is fine only if it has dry-run, caps, cost guards, resumable progress, and existing enrollment gates. The biggest issues to fix before build:

- Do not run 151k scoring through OpenAI without cost/rate-limit controls.
- Bulk enroll must use the same enrollment authority as single enrollment.
- Campaign enrollment path is not proven.

835 — Batch Score Contacts + Controlled Bulk Enroll Hot Leads by Vertical

What & Why

The lead scoring engine exists, but only a small portion of contacts have been scored. Most CRM contacts still have default scores, which makes hot/warm lead views unreliable.

This task adds:

1. Admin-triggered batch scoring for unscored contacts.
2. Progress/status/cancel controls for scoring.
3. Dry-run preview for bulk enrollment by vertical + score threshold.
4. Confirmed bulk enrollment into one selected sequence or campaign.
5. Strict reuse of existing enrollment/contactability gates.

This is not an outreach send task. It must not send messages directly.

Critical Safety Rules

Scoring must not create deals.
Scoring must not enroll contacts.
Scoring must not call autoEnrollFromTrigger.
Scoring must not trigger GHL sync.
Bulk enrollment must not bypass existing enrollment/contactability gates.
Bulk enrollment must not send messages directly.

If an active sequence/campaign later sends through the normal worker, that must remain governed by:

global outbound pause
sequence/campaign status
contactability
DNC/opt-out suppression
daily caps
CAN-SPAM footer injection
channel feature flags

Required Preflight Before Build

Before implementation, inspect and report:

Does scoreContact() call OpenAI or paid AI?
Can scoreContact() run deterministically from existing contact fields?
Does POST /api/lead-intelligence/score-batch already support batching?
Where are campaign enrollments implemented, if at all?
What existing endpoint/service performs single sequence enrollment?
What existing endpoint/service performs campaign enrollment?
How do sequence steps expose channels/action types?
How do campaign steps expose channels/action types?

If scoring 151k contacts would call paid AI per record, add a hard cost/rate-limit plan before apply.

Done Looks Like

Scoring

* Admin can start Score All Contacts.
* Job processes contacts with last_scored_at IS NULL by default.
* Optional rescore: true exists but requires confirmation.
* Job runs in batches, default batch size 50.
* Progress persists to system_settings.
* Job can be cancelled.
* Only one scoring job can run at a time.
* Progress shows:
    * total
    * processed
    * hot
    * warm
    * cold
    * unqualified
    * errors
    * lastProcessedContactId
* LeadCommandCenter / OutreachCommand counts reflect updated scores after job completes.

Bulk Enrollment

* Admin/manager can select:
    * vertical
    * minimum score threshold
    * sequence or campaign
* Preview runs first and creates no enrollments.
* Preview returns:
    * total matching
    * eligible
    * already enrolled
    * DNC/opt-out blocked
    * contactability blocked
    * missing contact method
    * PEWC/channel blocked
    * skipped breakdown
* Confirm step is required.
* Large runs require typed confirmation: ENROLL.
* Apply runs in batches and persists progress.
* Re-running does not create duplicates.
* DNC contacts are not enrolled.
* Contacts lacking PEWC are not enrolled into SMS/voice/ringless steps.
* No deals are created.
* No GHL sync is triggered directly.
* No outbound send is triggered directly.

Apply

  confirmed: true;

  rescore?: boolean;
  batchSize?: number;

For rescore: true or large runs, require typed confirmation:

SCORE CONTACTS

Scoring Job Requirements

Use a new service:

server/services/contact-scoring-job.ts

It should:

select contacts where last_scored_at IS NULL unless rescore=true
process in batches of 50 by default
call existing scoreContact()
persist progress after every batch
check cancel flag between batches
avoid one giant transaction
avoid one blocking HTTP request

System setting keys:

contact_scoring_job_progress
contact_scoring_job_cancel_requested

Payload:

{
  vertical: string;
  minScore: number;
  sequenceId?: number;
  campaignId?: number;
}

Exactly one of sequenceId or campaignId must be present.

Bulk Enrollment Authority

Do not direct insert enrollment records.

For sequences, use the same service/path as single-contact enrollment.

Required per contact:

load target sequence
confirm target is enrollable under existing sequence policy
check already enrolled
run canEnrollContactInSequence/contactability gates
create enrollment only if gates pass

For campaigns, first verify an existing campaign enrollment service exists.

If no safe campaign enrollment service exists, do not build campaign enrollment in this task. Return:

Campaign enrollment unsupported until a safe campaign enrollment service exists.

Do not invent a raw campaign enrollment insert that bypasses gates.
