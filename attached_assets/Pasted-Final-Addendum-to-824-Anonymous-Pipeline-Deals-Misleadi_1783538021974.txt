Final Addendum to #824 — Anonymous Pipeline Deals & Misleading Hot Lead Badges

Approved to build.

Core rule

Fix the source-of-truth conversion data first.

Do not solve this only by changing Pipeline display fallbacks.

Required order:

1. trace source prospect → contact/deal conversion
2. unify conversion mapping
3. prevent future blank/anonymous contacts
4. backfill recoverable existing broken contacts
5. add display safety net
6. clarify Lead Command Center / Prospects badges

⸻

Critical correction — placeholder emails

Do not create or preserve fake placeholder emails as usable contact emails.

Existing pattern:

lead-${id}@placeholder.com

is dangerous if it is stored in the normal contacts.email field and treated as contactable.

Required behavior:

real email exists → store real email
no real email → leave email null/empty OR store placeholder only in explicit non-contactable metadata

If schema requires an email, then placeholder emails must be:

visibly marked as placeholder
emailStatus = invalid / missing / placeholder / not_contactable
blocked by contactability
hidden from “email available” badges
excluded from outreach eligibility
excluded from dedupe as a real merchant email

Kill line:

STOP if a fake placeholder email can make a lead appear email-contactable.

⸻

Shared conversion mapper

Create one shared mapping function and use it in all three paths:

manual single convert
bulk Convert Hot Leads
sunbiz-cron autoPromoteProspects

Suggested location:

server/services/prospect-conversion.ts

Suggested function:

buildContactFromProspect(prospect, options)

It should normalize and preserve:

companyName / businessName
contact name / principal name if actually available
email
phone
address
city/state/zip
source tags
leadSource
source prospect id / metadata
owner/principal fields if present

Do not fabricate owner names. If the source has principalName, registeredAgent, or officer data, label it honestly. Do not call it “owner” unless the source actually supports that.

Kill line:

STOP if routes/prospects.ts and sunbiz-cron.ts still maintain separate prospect→contact mapping logic after this task.

⸻

Promotion guard

A prospect should not convert into a contact/deal with zero identifying information.

Minimum acceptable identity:

companyName/businessName
OR real email
OR phone

Preferred for business leads:

companyName/businessName required unless explicitly converting an individual contact

If companyName exists on the prospect, it must survive conversion.

Kill line:

STOP if a prospect with companyName can produce a contact with blank companyName.

⸻

Existing broken contact backfill

Do a dry-run first.

Required:

identify broken contacts/deals showing Contact # / N/A
join back to source prospect if source id, metadata, note text, or import reference exists
preview exact backfill rows
apply only recoverable values
verify after update

Allowed:

restore companyName from source prospect
restore real email/phone from source prospect
restore tags/source metadata
restore deal title/company label from corrected contact

Not allowed:

guessing business names
fabricating owner names
inventing emails
using placeholder emails as real emails
overwriting good existing contact fields with weaker prospect fields

Pipeline display safety net

After the data fix, add graceful fallback.

Bad:

Contact #153988
Company: N/A

Good:

Unnamed contact
Company unavailable

But if source/company data exists, the card should show the real company.

Kill line:

STOP if Pipeline only changes labels while newly converted contacts still store blank company data.

⸻

Lead Command Center enrichment stat

Clarify the stat semantics.

If enrichment_status = enriched means “attempted,” then label it as:

Enrichment Attempted

Add a separate contactability metric if feasible:

Contact Info Found
Has email or phone
Contactable leads

Do not imply 285K leads are ready to contact unless they actually have usable contact info.

⸻

Hot lead contactability badge

Keep scoring thresholds unchanged.

Add a secondary indicator based on actual usable contact fields:

Hot · Contactable
Hot · Not yet contactable

Contactable should mean at minimum:

has real email OR has phone

Do not count placeholder email as contactable.

⸻

STOP if existing good contact data is overwritten by weaker source data.
