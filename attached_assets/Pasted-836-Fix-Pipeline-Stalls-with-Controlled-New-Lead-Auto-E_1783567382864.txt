836 — Fix Pipeline Stalls with Controlled New Lead Auto-Enrollment

What & Why

967 deals are stuck in New Lead because bulk-imported deals have no activity signals and are not enrolled in SDR outreach. The stage progression sweep depends on downstream signals like email activity, call tasks, statement upload, booking, or rep action. Without enrollment, those signals never start.

This task adds:

1. Stage progression sweep observability.
2. Stage Health visibility.
3. Controlled backfill enrollment for existing New Lead deal contacts.
4. Future auto-enrollment for newly created New Lead deals, gated by an explicit setting.
5. Audit visibility for every enrolled/skipped contact.

This solves the actual issue: eligible New Lead deal contacts begin SDR outreach, which can generate the activity needed for pipeline progression.

Critical Principle

Do not globally convert all 94 seeded sequences to automatic.

Instead, create a controlled New Lead deal enrollment policy:

New Lead deal + eligible contact + configured SDR sequence mapping + explicit enable flag
→ enroll through existing sequence gates

Done Looks Like

* Stage progression sweep writes a heartbeat audit/log entry.
* Operator Dashboard shows Stage Health:
    * New Lead total
    * New Lead deals stuck 7+ days
    * New Lead deals without sequence enrollment
    * last progression sweep run
    * last sequence worker tick
* Admin can preview which existing New Lead deal contacts would be enrolled.
* Admin can run a confirmed backfill enrollment for existing New Lead deals.
* Future auto-enrollment exists but is gated by a system setting:
    * autoEnrollNewLeadDeals
    * default false
* When enabled, newly created eligible New Lead deals enroll into the mapped SDR sequence within one orchestrator/SLA cycle.
* Enrollment uses the existing single-contact sequence enrollment gates.
* DNC, opted-out, missing-email, already-enrolled, inactive-sequence, and channel-ineligible contacts are skipped with reasons.
* Audit log records which sequence was selected and why each contact was enrolled or skipped.
* No deals are created.
* No GHL sync is triggered directly by this task.
* No outbound is sent directly by this task.
* The sequence worker/global pause/daily cap/contactability/CAN-SPAM gates still control actual sends.

Out of Scope

Do not:

change stage names

create new deals
auto-advance deals to Closed Won
globally convert all sequences to automatic
modify GHL sync

Step 6 — Future Auto-Enrollment Hook

Add a future hook in the safest existing place where new deals or deal-linked contacts are evaluated, likely the SLA/orchestrator cycle.

Required behavior:

if autoEnrollNewLeadDeals !== true:
  record/report candidate only
  do not enroll
if autoEnrollNewLeadDeals === true:
  for New Lead deals with linked contact and no active/completed enrollment:
    select mapped sequence
    run existing enrollment gates
    create enrollment only if gates pass
    audit enrolled/skipped reason

Do not call this for Closed Won, onboarding, support, or transactional flows.

Do not call GHL sync.

Do not create deals.

Enrollment Authority

Do not direct-insert enrollments.

Each contact must reuse the same gate path as single-contact sequence enrollment.

Required gates per contact:

load sequence
reject if sequence.status !== active
check existing active/completed enrollment
run canEnrollContactInSequence(contactId, sequence)
create enrollment only if gates pass

Worker-time gates remain untouched:

global outbound pause
daily cold email cap
bounce/invalid email guard
full contactability Gate A/Gate B
CAN-SPAM footer injection
channel feature flags

Sequence TriggerType Rule

Do not convert all sequences to automatic.

Allowed:

admin-selected sequence mapping for New Lead deal enrollment

Not allowed:

migration changing all cold outreach triggerType values
automatic enrollment from every contact_created event
