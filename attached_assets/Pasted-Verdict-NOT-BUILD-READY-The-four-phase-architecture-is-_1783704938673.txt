Verdict: NOT BUILD-READY

The four-phase architecture is now mostly correct, but Phase 1 introduces a duplicate-generation window.

Before the historical backfill, existing SLA tasks have source = NULL and automation_key = NULL. If the worker pre-check immediately switches to identity-only matching, it will not see those legacy active tasks and can create a new task for every qualifying deal.

The proposed getTasksByDeal() inside the deal loop also creates an N+1 query pattern.

Corrections to send back

Fix the Phase 1 transition before implementation:
1. Use a transitional dedup guard until backfill is complete.
During Phase 1, an active incomplete task must block creation when either:
A. It has canonical identity:
   source = 'sla'
   AND automation_key = 'stalling-deal-follow-up'
OR
B. It is a confirmed legacy SLA task:
   title matches the exact historical stalling-task format
   AND the embedded deal ID equals tasks.deal_id
Both cases must require:
- deleted_at IS NULL
- completed_at IS NULL
Do not switch to identity-only pre-check until Phase 2 backfill has completed and a verification query confirms zero active legacy rows remain without identity.
2. Do not query getTasksByDeal() once per deal.
That creates an N+1 query inside the SLA generation loop.
Add one bounded bulk query for the current qualifying deal IDs that returns all blocking tasks, then build a Set/Map keyed by dealId.
The title heuristic may remain only for legacy rows during transition.
3. Define the transition removal point.
After Phase 2, verify:
zero active+incomplete rows matching the historical SLA pattern
with source/automation_key missing or incorrect.
Only then remove the legacy-title branch and retain canonical identity matching as the pre-check optimization.
4. Protect server-owned fields at the storage boundary too.
Keeping source/automationKey out of Zod request schemas is necessary but not sufficient.
Confirm generic updateTask() cannot receive arbitrary unvalidated objects from another internal caller and mutate provenance fields.
Prefer:
- public task update type excludes provenance fields;
- dedicated internal insert type includes them;
- createStallingDealFollowUpTask hardcodes them.
5. Do not rely only on “silently ignored” unknown Zod fields.
Verify the actual schema mode:
- strip,
- strict,
- or passthrough.
Required behavior may be either:
- reject source/automationKey with 400, or
- strip them.
But tests must prove the fields cannot be persisted.
6. Clarify completion normalization.
If an update sets status back from completed to open, determine whether completedAt is cleared.
The index and worker use completedAt as authority. A reopened task with completedAt still set would not block a replacement SLA task.
Define and test:
- complete → completedAt set;
- reopen → completedAt cleared, if reopening is supported.
7. Make GHL cleanup completion observable.
propagateTaskDeleteToGhl() is described as fire-and-forget in the route.
For migration cleanup, do not soft-delete locally before an asynchronous GHL operation has produced a confirmed result when GHL deletion is required.
Use an awaitable canonical operation or explicitly exclude the row until GHL outcome is known.

Kill lines

STOP if Phase 1 identity-only matching ignores historical SLA tasks with NULL source/automation_key.
STOP if one task query is executed per qualifying deal.
STOP if the legacy-title compatibility branch is removed before backfill completeness is verified.
STOP if internal generic update paths can mutate source or automationKey.
STOP if reopened tasks retain completedAt and therefore evade the active-task constraint.
STOP if required GHL deletion is fire-and-forget while local cleanup proceeds immediately.

Validation additions

- Legacy active SLA task with NULL identity blocks Phase 1 creation.
- Canonically identified active SLA task blocks creation.
- Completed legacy or canonical task does not block creation.
- Worker performs a constant number of blocking-task queries per cycle, not one per deal.
- After backfill, zero active legacy tasks remain without canonical identity.
- Public and generic update paths cannot alter provenance.
- Reopening a completed task restores the correct blocking behavior.
- GHL-backed cleanup waits for or records a definitive GHL outcome.

Final status: NOT BUILD-READY

The permanent index design is correct. The remaining blocker is safe transition-state ownership: Phase 1 must recognize both legacy and newly identified SLA tasks without introducing N+1 queries or a temporary duplicate wave.
