Final Addendum to #882 — Show Opt-Out Protection Counts in CSV Import History UI

Approved to build.

Goal

Expose CSV import opt-out protection counters in the admin UI so operators can see when imports preserved existing opt-outs or applied new opt-outs.

Backend already returns:

optOutPreserved
optOutApplied

UI must surface those values in:

client/src/pages/dashboard/ImportContacts.tsx

Required UI behavior

Import history table

For each import row, show opt-out protection counts only when either value is greater than zero.

Example display:

Opt-outs: Preserved 12 / Applied 4

or compact:

Preserved: 12 · Applied: 4

If both values are zero or missing:

show nothing

Do not show noisy 0 / 0 badges.

Upload result summary

After an upload/import completes, include opt-out protection in the summary toast/modal/result card when applicable.

Example:

Opt-out protection:
12 existing opt-outs preserved
4 new opt-outs applied

Hide the section when both are zero.

Field normalization

Support both API/schema naming styles if needed:

optOutPreserved
optOutApplied
opt_out_preserved
opt_out_applied

Normalize in the client model so the UI does not break if the route returns snake_case in history but camelCase in immediate upload response.

Copy requirements

Use clear safety-oriented labels:

Preserved = existing opt-out/DNC state protected from overwrite
Applied = CSV row newly marked the contact opted-out/DNC

Tooltip text, if added:

Preserved: contacts that were already opted out and stayed protected during import.
Applied: contacts newly marked opted out by this import.

Scope protection

Do not change backend import logic in this task unless the fields are not actually returned.

Do not change:

CSV parsing
contact upsert rules
consent merge rules
suppression helper
GHL sync
sequence enrollment
outbound sending
import accounting

This should be UI-only unless the API response is missing the fields.

Kill lines

STOP if optOutPreserved/optOutApplied are double-counted as additional imported rows.
STOP if the UI shows 0/0 noise for every import.
STOP if preserved/applied labels are reversed.
STOP if this task changes CSV consent merge behavior.
STOP if this task weakens opt-out preservation.
STOP if this task triggers enrollment, GHL sync, or outbound sends.
STOP if import totals become visually inconsistent with backend accounting.

Validation

Manual checks:

1. Import history row with optOutPreserved > 0 shows Preserved count.
2. Import history row with optOutApplied > 0 shows Applied count.
3. Row with both values 0 shows no opt-out badge/text.
4. Upload completion summary shows opt-out breakdown when values are > 0.
5. Upload completion summary hides opt-out section when values are 0.
6. Counts match backend API response exactly.

Run:

npx tsx scripts/smoke-role-guards.ts

If there are frontend checks available, also run the targeted client build/typecheck normally used for dashboard UI changes.
