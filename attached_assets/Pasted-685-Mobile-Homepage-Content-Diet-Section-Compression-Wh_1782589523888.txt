685 — Mobile Homepage Content Diet + Section Compression

What & Why

The homepage mobile architecture is still too dense after the rhythm repair. Background treatments now alternate better, but the mobile page still renders desktop-depth content as long stacked sections: review contents, “Yours to Keep,” dual timelines, calculator fallback, strategy accordion, verticals, rate comparison, and full Why Liberty cards.

This creates a 20+ screen mobile page that feels like a documentation page instead of a premium conversion page.

This task is a mobile-only content compression pass. The goal is not to shrink text, cram cards, or make content harder to read. The goal is to replace desktop-depth modules with mobile-native summaries.

Compact means:

* fewer words
* fewer repeated modules
* flatter rows
* clearer hierarchy
* no giant report tables unless necessary
* no oversized cards stacked endlessly

Desktop must remain unchanged.

⸻

Done Looks Like

At 390px mobile:

* Homepage reads as a clear conversion story, not a documentation page.
* Page requires roughly 10–14 meaningful screenshots, not 20+.
* No mid-page section consumes more than ~1.25 mobile screens, except hero/sample-review/final CTA if needed.
* “What Your Liberty Review Includes” is a compact summary card, not a 6-row report table plus separate “Yours to Keep” card.
* “How The Liberty Analysis Works” is one compact mobile process card, not a 3-step analysis plus full 5-step onboarding timeline.
* Rate Calculator is CTA-only on mobile — no form fields, no estimate preview, no rate-range cards.
* Choose Path accordion remains, but the expanded item is not taller than one mobile screen.
* Verticals section uses one consistent compact pattern — not mixed accordion plus large standalone cards.
* “Why Merchants Switch” does not render the full rate-comparison card with multiple rate cards on mobile.
* Why Liberty feature cards are compact mobile rows/cards, not large full-width padded blocks.
* StickyMobileCTA remains navy and keeps existing IntersectionObserver trigger logic.
* Upload/book CTA destinations and tracking calls are unchanged.
* Desktop layout at md: and above is unchanged for all affected sections.

Out of Scope

* Backend/API/GHL/analytics changes
* Upload flow changes
* Booking URL changes
* CTA tracking changes
* StickyMobileCTA IntersectionObserver logic
* Hero H1 copy changes
* New routes
* New homepage sections
* Desktop redesign
* Testimonial claim rewriting unless unsafe claims are rediscovered
* Services section copy rewrite, except mobile truncation/summary treatment
* CSS file changes unless absolutely required for a local class fix

⸻

Non-Negotiable Rule

Do not solve mobile density by making typography smaller, reducing padding until cards feel cramped, or forcing long content into 2-column cards.

If content does not fit cleanly on mobile, reduce the copy or change the pattern.

⸻

Steps

1. Compress “What Your Liberty Review Includes” on mobile

Current problem: mobile renders a full 6-row report-style table, then an additional “Yours to Keep” card. This repeats the same idea and consumes multiple screens.

Desktop:

* Keep existing desktop version unchanged.
* Wrap desktop markup as hidden md:block if needed.

Mobile:

* Add a new md:hidden compact summary card.
* The mobile version should summarize the six review outputs in one compact module.

Mobile content structure:

The Liberty Review Includes
A clear line-by-line look at your current processing costs.
✓ Effective rate
✓ Fee drivers
✓ Downgrades
✓ Add-ons
✓ Funding timeline
✓ Options summary
You keep the breakdown either way.
[Upload Statement — Free]

Requirements:

* Use one compact card.
* Use checkmark rows or a 2-column bullet grid only if it remains readable.
* Do not use long paragraphs for each item.
* Do not preserve the six large desktop rows on mobile.
* Remove the separate “Yours to Keep” card from mobile.
* Preserve compliance language, but attach it as small text inside or directly under the compact card.

Kill line:

STOP if mobile still renders six large full-width review rows plus a separate keep-the-breakdown card.

⸻

2. Compress “How The Liberty Analysis Works” on mobile

Desktop:

* Wrap desktop markup as hidden md:block if needed.

Mobile:

* Add a new md:hidden compact process card.
* Do not show giant numbered circles.
* Do not show the full 5-step onboarding timeline.

How It Works

Requirements:

* Desktop timeline remains unchanged.

Kill line:

STOP if mobile still shows both the 3-step analysis timeline and the full 5-step onboarding timeline.

⸻

* No estimate preview.
* No industry selector.
* No rate-range cards.

Kill line:

STOP if mobile renders calculator inputs, estimate preview cards, industry selector buttons, or rate-range cards inside the homepage calculator section.
