4. P0 blockers and exact corrections

P0-01 — Git metadata cannot prove that the nine statement files are no longer runtime dependencies

Evidence:

statement-command-worker.ts:103-116 writes the file first, then persists the absolute path in the command context and enqueues the command.

Recovery at statement-command-worker.ts:82-88 re-enqueues in_progress commands. Removing a still-referenced file causes durable_upload_unreadable instead of recovery.

The nine filenames embed UUID command identities and were created by the production writer path, not a standalone fixture directory.

Required correction:

Before deleting or untracking any of the nine explicit paths, run a narrowly authorized, read-only reference census against every database/deployment whose commands could rely on the deployed repository copy.

Query only the nine command IDs/path basenames and return aggregate/status/reference disposition; do not return request context, contact data, file content, or other PII.

A file may be deleted from the current tree only when its command is absent, conclusively synthetic/test and terminal, or has another verified durable copy that recovery actually reads.

If any command is in_progress, recoverable, leased, or otherwise still dependent, stop deletion and repair/migrate that command under the statement-command owner.

If database access remains prohibited, preserve the nine current paths and mark the task blocked; metadata-only evidence is not enough to meet “no confirmed artifact remains tracked.”

Record tip removal and reachable-history containment separately. Current-tree removal does not delete the blob from the public repository's history.

Acceptance: every removed statement path has a reference disposition showing that removal cannot change an accepted command's recovery outcome.
