## Blocking corrections to the submitted #1852 draft

1. `staff` is already a supported text audience. Add validation/constraints only after a data census; do not add an enum value blindly.
2. Use an immutable `knowledge_source_revisions` table, a `knowledge_sources.current_published_revision_id` pointer, and revision-bound chunks. A revision table without retrieval pinning is not authority.
3. Do not add `effective_status` beside the existing `status`; that would create parallel lifecycle truth.
4. Change `assistant_sessions.user_id` to the canonical varchar user ID and enforce session ownership, audience immutability, history isolation, and feedback-message membership.
5. Reuse `authorizeContactAccess(req, res, contactId)` at the route boundary. Do not invent `resolveContactContext(contactId, requestingUserId)` as a parallel authorization policy.
6. Do not log raw contact prompts/responses containing PII. Add structured, redacted audit metadata and hashes.
7. Fix the broken filtered knowledge-source query, the unescaped regex keyword fallback, and the first-1,000-chunks retrieval cap as part of making governed retrieval authoritative.
8. The training importer must read `client/src/pages/dashboard/Training.tsx`; source location assumptions in the submitted prompt were stale.
9. Call Assist must work for any exactly assigned, currently manual-call-eligible canonical contact. It must not inherit the existing SDR-only Sales Prep gate accidentally.
10. All new certification tests must hard-refuse the production/shared database and use fake OpenAI transport. Existing server-required scripts are not sufficient proof.
