Part A — Blaze Test Connection

Required behavior

The Blaze “Test Connection” button must stop returning unconditional success.

It should return one of:

connected
not_configured
auth_failed
workspace_not_found
webhook_unreachable
request_failed

The UI must show the real result.

Safety guard

Before implementing the check, inspect what Blaze configuration exists:

webhook URL
workspace ID
API key/token if present
integration settings storage

Do not send a mutating production event just to test connectivity.

Preferred test behavior:

non-mutating auth/reachability check
or provider-supported test endpoint
or safe validation of configured webhook/workspace

If Blaze only exposes a mutating webhook endpoint and no safe test endpoint exists, return:

Configured, but no safe live test endpoint available.

Do not fake success.

Kill lines

STOP if Test Connection still always returns success.
STOP if the test sends a real lead/event into Blaze without explicit approval.
STOP if missing Blaze config is reported as connected.
STOP if this task adds a new third-party integration beyond Blaze.
STOP if Blaze credentials or secrets are logged.

⸻

Part B — Workflows page truthfulness

Required preflight

Before coding, determine whether /dashboard/workflows has an existing backend workflow model/route that can safely be reused.

Inspect:

server/routes/workflows.ts
shared/schema.ts
existing stage-rules automation
existing sequence automation
existing workflow-like storage

Allowed outcomes

Pick one based on what exists.

Option 1 — Real persisted workflows exist or can be minimally reused

If existing backend infrastructure exists, wire Workflows.tsx to it.

Required behavior:

load workflows from backend
create workflow persists to database
toggle active/inactive persists to database
delete/archive persists if supported
refresh reloads real state
no hardcoded example data shown as live data

Option 2 — No real workflow engine exists

If the page is only hardcoded examples and no safe backend workflow model exists, do not build a new engine here.

Instead:

remove fake create/toggle success behavior
label page as Preview / Not live
disable live-looking controls
or route users to real Stage Rules / Sequences where applicable

The page may keep examples only if clearly labeled as examples.

Not allowed

Do not create a parallel workflow automation system with new trigger/action semantics in this task.

Kill lines:

STOP if Workflows still shows hardcoded examples as if they are live workflows.
STOP if create/toggle appears successful but does not persist.
STOP if this task builds new workflow trigger/action types.
STOP if this task duplicates Stage Rules, Sequences, or existing automation engines.
STOP if this task changes existing automation execution semantics.

⸻

Out of scope

Do not:

build new workflow trigger types
build new workflow action types
