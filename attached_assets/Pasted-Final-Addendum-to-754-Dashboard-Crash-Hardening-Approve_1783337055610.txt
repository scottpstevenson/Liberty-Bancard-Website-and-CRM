Final Addendum to #754 — Dashboard Crash Hardening

Approved to build.

This is a defensive reliability task only. Do not redesign page layouts or change product behavior beyond making edge cases safe and visible.

⸻

Part A — Contacts safety fixes

Date rendering

Contacts must render safely when date fields are:

null
undefined
empty string
invalid date string
legacy malformed value

Use a safe relative-time helper.

Expected fallbacks:

missing date → Never / No date
invalid date → Unknown date

Do not let formatDistanceToNow, new Date(...), or equivalent date formatting throw during render.

Bulk merge

Bulk merge must not create silent partial state.

Use either:

sequential awaited merges with per-item result reporting

or:

Promise.allSettled with per-item success/failure reporting

The UI must tell the user:

merged count
failed count
failed contact IDs/names if available
reason if available

Kill line:

STOP if bulk merge fires requests without awaiting/collecting their results.

⸻

Part B — Pipeline / Kanban safety fixes

Currency formatting

Pipeline must not crash when a deal value is:

null
undefined
NaN
empty string
non-numeric legacy value

Expected fallback:

$0

or:

Value unknown

Use whichever is more truthful based on existing UI semantics.

Do not coerce unknown values into fake revenue totals if the total is used analytically. If uncertain, display Value unknown.

Proposal Accepted badge

The Proposal Accepted badge must degrade safely if proposal data is missing, null, or fails to load.

Expected behavior:

deal accepted but proposal missing → Proposal accepted
proposal details unavailable → Details unavailable

Do not crash and do not hide the deal.

⸻

Part C — Calendar date grouping safety

Calendar must not crash or corrupt grouping when event dates are malformed.

Guard:

invalid start date
invalid end date
missing start date
timezone parse failure
legacy malformed date string

Expected fallback:

valid events group normally
invalid events appear in an Ungrouped / Invalid date section

or are safely skipped with a visible warning/count.

Do not let one malformed event break the whole calendar.

⸻

Part D — Document Vault bulk delete resilience

Bulk delete must process each selected document independently.

Required response shape should include:

{
  attempted: number;
  succeeded: Array<{ id: string | number; filename?: string }>;
  failed: Array<{ id: string | number; filename?: string; reason: string }>;
}

The endpoint should return a handled response even if some files fail.

Allowed status behavior:

all succeeded → 200
partial success → 207 or 200 with partial_success status
all failed → 400/500 with per-file reasons

Do not abort the entire batch because one file path/delete operation fails.

Kill line:

STOP if one failed file deletion prevents all other selected files from being attempted.

⸻

redesign Contacts, Pipeline, Calendar, or Document Vault UI
