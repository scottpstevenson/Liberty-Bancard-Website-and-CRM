Final Addendum to #869 — Speed Up Nightly New Lead Auto-Enroll Check

Approved to build.

Goal

Optimize:

server/services/new-lead-enrollment-job.ts
runNewLeadAutoEnrollCheck()

so it does not perform thousands of serial DB calls during each SLA/nightly auto-enroll cycle.

Current problem:

~1,400+ New Lead deals
× sequence lookup
× sequence steps lookup
× contact enrollments lookup
× PEWC check
× contactability check
= thousands of sequential awaits inside a periodic worker

Required approach

Use the same bulk-map pattern as the optimized preview path:

bulk-fetch contacts/deals
bulk-fetch sequences
bulk-fetch sequence steps
bulk-fetch existing enrollments
cache PEWC/channel requirements by sequenceId
reuse maps inside the loop

Do not call these inside the per-deal loop:

storage.getFollowUpSequence(seqId)
storage.getSequenceSteps(seqId)
storage.getContactEnrollments(contact.id)
_requiresPewc(seqId)

Required bulk helpers

Use existing helpers if already added:

getContactEnrollmentsForContacts(contactIds, sequenceIds?)
getFollowUpSequencesByIds(sequenceIds)
getSequenceStepsForSequences(sequenceIds)

If missing, add them to:

server/storage/automation.ts
server/storage.ts

Use chunking for large IN queries.

Recommended chunk size:

500–1000 IDs

Preserve final correctness

runNewLeadAutoEnrollCheck() is not just a preview. It may create enrollments when:

autoEnrollNewLeadDeals=true

Therefore, bulk maps may be used for screening, but final write must still be safe.

Before creating an enrollment, the code must still confirm:

sequence exists
sequence is active
contact is not already enrolled
DNC/opt-out state is still blocked
contactability gates still pass
PEWC/channel requirements still pass
createSequenceEnrollment() is idempotent / duplicate-safe

If #871 has landed, rely on the idempotent enrollment write as the final race protection.

Candidate mode behavior

When:

autoEnrollNewLeadDeals=false

the optimized path must still:

write new_lead_auto_enrollment_candidate_detected audit entries
create zero enrollments
not call sequence worker
not send outreach

Do not remove candidate-mode audit coverage.

Auto mode behavior

When:

autoEnrollNewLeadDeals=true

the optimized path may create enrollments, but only through the existing gated enrollment authority.

Do not direct-insert enrollment rows.

Do not bypass:

canEnrollContactInSequence()
evaluateContactability()
existing enrollment duplicate checks
PEWC/channel checks

Sequence/step cache

Build once per run:

const sequencesById = new Map<number, Sequence>();
const stepsBySequenceId = new Map<number, SequenceStep[]>();
const enrollmentsByContactId = new Map<number, Enrollment[]>();
const pewcRequiredBySequenceId = new Map<number, boolean>();

If vertical mapping is used, resolve all needed sequence IDs first, then bulk-load them.

If no sequence is mapped for a vertical, skip with:

no_mapped_sequence

without making per-deal sequence calls.

Contactability guard

If evaluateContactability() cannot be safely bulk-evaluated, keep it as the final authoritative per-contact gate only for contacts that pass cheap prefilters.

Cheap prefilters:

no contact
no mapped sequence
sequence inactive
already enrolled from enrollment map
missing email
DNC/opt-out/suppressed from already-loaded contact fields
PEWC missing for mixed-channel target

Then call deeper contactability only for the remaining candidate set.

Do not weaken contactability just to improve speed.

Performance instrumentation

Add one summary log/audit per run, not one row per deal.

Example action:

new_lead_auto_enrollment_check_completed

Include:

dealCount
contactCount
sequenceCount
eligibleCount
enrolledCount
candidateCount
skippedCount
durationMs

Do not spam audit logs for every skipped non-candidate unless the existing behavior already does.

Scope protection

Do not change:

manual apply path _runAsync
lead scoring
stage progression rules
sequence worker send execution
GHL sync
CAN-SPAM/unsubscribe logic
SMS/voice/ringless flags
deal creation
autoEnrollNewLeadDeals default
sequence triggerType

Manual/confirmed apply may remain more conservative and per-deal at write time.

Kill lines

STOP if runNewLeadAutoEnrollCheck() still awaits getContactEnrollments(contact.id) inside the per-deal loop.
STOP if runNewLeadAutoEnrollCheck() still fetches the same sequence/steps repeatedly inside the loop.
STOP if optimization bypasses canEnrollContactInSequence or contactability gates.
STOP if DNC/opted-out/suppressed contacts become eligible due to stale/missing map data.
STOP if candidate mode creates enrollments.
STOP if auto mode direct-inserts enrollments instead of using the existing safe enrollment path.
STOP if duplicate enrollment protection from #871 is bypassed.
STOP if this task changes _runAsync manual apply behavior.
STOP if this task sends outbound directly, creates deals, or triggers GHL sync.
STOP if this task creates one massive unbounded IN query.

scripts/test-new-lead-auto-enroll-performance.ts

Required tests:

1. auto-enroll check creates no enrollments when autoEnrollNewLeadDeals=false
