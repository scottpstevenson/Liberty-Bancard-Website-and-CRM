Helmet’s documented form is:

## P0 blocking corrections

### 1. The source-of-truth claim is wrong

Independent HTML/script producers include:

* [`server/ssrShared.ts`](https://github.com/scottpstevenson/Liberty-Bancard-Website-and-CRM/blob/55343b2d7a9babd459774c76875fa19f9a2c37f2/server/ssrShared.ts)
* `server/ssr/location-html.ts`
* `server/ssr/competitor-ssr.ts`
* `server/routes/glossary.ts`
* `server/routes/ssr-routes.ts` 404 HTML
* `server/routes/widget.ts` preview HTML
* `server/routes/public.ts` unsubscribe HTML
* `client/index.html`
* `server/static.ts`
* `server/vite.ts`

Restricting work to `index.ts`, `ssrShared.ts`, and the five named SSR callers does not cover the site.

### 2. `nonce?: string` must not be optional

An optional nonce allows missed callers to compile and silently emit noncompliant HTML.

Use a required context:

```ts
interface HtmlSecurityContext {
  cspNonce: string;
}
```

Request-handling routes own that context. Renderers must receive it explicitly. Do not generate a second nonce in `ssrShared.ts`.

### 3. Do not blindly post-process HTML to add nonces

Several JSON-LD objects contain database-backed blog titles, descriptions, and FAQs. They currently use raw `JSON.stringify()` inside `<script>` elements.

A value containing `</script>` can break out of the data block. A global regex that subsequently nonces every discovered `<script>` could accidentally authorize an injected script.

Add one canonical safe JSON serializer that escapes at least `<`, `>`, `&`, U+2028, and U+2029. Use it in every server-rendered JSON-LD block.

### 4. Nonces and shared HTML caching are incompatible

`server/routes/ssr-routes.ts` currently emits public CDN caching for up to two hours; glossary HTML is cached for up to a day.

If HTML contains a nonce and remains share-cacheable, the same nonce can be replayed to multiple visitors. Choose one architecture:

* Recommended: production has no inline executable scripts, so remove production `'unsafe-inline'`, retain external exact-host scripts, and use nonces only where a genuine inline executable script exists.
* If every JSON-LD block must be nonced, all affected HTML must become `private, no-store`, or the design must change to CSP hashes/external assets.

Do not use a fixed build-time nonce.

### 5. Current CI cannot enforce completion

The latest commit deleted the only workflow. GitHub reports no checks or workflow runs for current `main`.

#1576 cannot be considered complete until the canonical BT-05 workflow is restored and requires:

* `npm run check`
* `npm run build`
* CSP/CORS regression tests
* build-artifact secret scanning
* the existing pre-deploy/static gates

## P1 corrections

### GAESA

Live evidence strongly indicates that `GAESA` is a Google hosting/session-affinity cookie:

* It is set on `/`, `/api/health`, `/api/csrf-token`, and `/robots.txt`.
* It is present before any page JavaScript runs.
* Responses identify `server: Google Frontend`.

Cloud Run and App Engine use platform-generated cookies for session affinity. [Google documents this behavior](https://cloud.google.com/blog/topics/developers-practitioners/improve-responsiveness-session-affinity-cloud-run).

Correction:

* Remove it from Express/GHL implementation scope.
* Do not call it an analytics cookie.
* Verify whether deployment session affinity is actually required.
* Disable affinity if unnecessary; otherwise document a hosting-platform exception or escalate missing flags to the platform provider.

### CORS handling

A denied but syntactically valid origin is “forbidden,” not “malformed.” Return `403`, not `400`.

Avoid brittle string matching:

```ts
class CorsOriginDeniedError extends Error {
  code = "CORS_ORIGIN_DENIED";
  status = 403;
}
```

Handle it immediately after CORS middleware so it is not reported as an internal server error. Test both `GET` and `OPTIONS` preflight requests.

Middleware should be ordered:

1. Request security context/nonce, if used
2. Helmet
3. CORS
4. CORS-specific error handler
5. Parsers and routes

That also ensures rejected responses receive the normal security headers.

### GHL regression risk

The GHL tag at `ssrShared.ts:146` is external. Adding a nonce to that tag does not automatically authorize inline code that the third-party loader might later create.

Before enforcement:

* Run the strict policy in report-only mode on staging.
* Open, interact with, and submit the chat widget.
* Capture console CSP violations and loaded hosts.
* Do not restore global `'unsafe-inline'` merely to accommodate the widget; use the vendor’s supported CSP configuration or sandboxed iframe approach.

### Secret scanning

The proposed command is wrong and insufficient:

* Client assets are emitted under `dist/public/assets`, not `dist/assets`.
* It ignores `dist/index.cjs`, HTML, CSS, JSON, and possible maps.
* It misses many credential formats and can generate false positives.
* `scripts/scan-tracked-files.ts` checks prohibited file types, not secret contents.

Use a pinned, redacting scanner such as Gitleaks against:

* The Git repository/history under BT-01 ownership
* `dist/index.cjs`
* `dist/public/**`

Never print matched secret values into CI logs.

### Wildcard CSP hosts

Code shows exact script loads for:

* `www.googletagmanager.com`
* `connect.facebook.net`
* `widgets.leadconnectorhq.com`

`fonts.googleapis.com` is not a script source, and Facebook share URLs do not require `*.facebook.com` in `script-src`.

Measure GHL runtime traffic before narrowing its domains, but do not describe the current wildcards as permanently unshrinkable.
