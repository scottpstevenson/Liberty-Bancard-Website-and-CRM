Approved to build with these scope guards.

⸻

Part A — Referral Program Add Partner

Required behavior

The admin “Add Partner” form must submit fields the backend actually accepts, and the created partner must persist correctly.

Before changing code, compare:

ReferralProgram.tsx submitted payload
server/routes/partners.ts expected body fields
shared/schema.ts partner/referral partner table fields
existing stored partner records

Fix the mismatch at the smallest safe layer:

frontend payload rename
or backend alias support

Prefer preserving backward compatibility if existing callers use the old field name.

Kill line

STOP if Add Partner appears successful but the new partner is not persisted or reloadable.

⸻

Part B — Review Complete cost-driver notes persistence

Required behavior

All notes entered in Review Complete, especially cost-driver notes, must persist and reload.

Before adding schema, inspect:

ReviewComplete.tsx submitted payload
server/routes/deals.ts review-complete/update route
shared/schema.ts deal/proposal/review fields
existing JSON metadata fields, if any

Preferred fix order:

1. Wire to an existing notes/metadata JSON field if one already exists and is appropriate.
2. Add minimal schema support only if no suitable persistence field exists.

Do not silently drop unknown note fields.

Do not store cost-driver notes only in component state.

Required manual proof

After saving Review Complete:

refresh page
reopen same deal/review
confirm cost-driver notes are still visible

Kill lines

STOP if cost-driver notes save in the UI but disappear after reload.
STOP if this task changes review scoring/business logic.
STOP if this task adds broad review-versioning/audit history.

⸻

Part C — LinkedIn Enrichment stats panel

Required behavior

Settings Integrations must not call a missing endpoint and show a broken request as if the feature is live.

Allowed outcomes:

1. Implement the real stats endpoint if backend data already exists.
2. Hide/remove the stats panel if the feature is not ready.
3. Show a clearly labeled “Not configured / Not live yet” state.

Not allowed:

fake stats
hardcoded success
console/network 404 treated as okay

If implementing the endpoint, it must be dashboard-auth guarded and return real backend counts only.

Kill lines

STOP if Settings Integrations still calls a missing LinkedIn stats endpoint.
STOP if fake LinkedIn enrichment stats are displayed as real.
STOP if this task builds a new LinkedIn enrichment provider.

⸻

Part D — Merchant Portal decline data labeling

Required behavior

If decline reason data is synthesized/estimated, the UI must clearly label it as estimated.

Use explicit wording near the chart/table, for example:

Estimated decline breakdown

and tooltip/helper copy such as:

This breakdown is estimated from available merchant activity and is not exact processor-level decline reason data.

Do not imply exact processor data unless the backend has real processor-supplied decline reasons.

Kill lines

STOP if estimated/synthesized decline data is still presented as exact processor data.
STOP if this task attempts to build real per-transaction decline tracking.
STOP if financial totals or processor analytics logic are changed.
