## Major issues Task #1577 missed

1. This is not genuine React SSR.

[`client/src/main.tsx`](https://github.com/scottpstevenson/Liberty-Bancard-Website-and-CRM/blob/55343b2d7a9babd459774c76875fa19f9a2c37f2/client/src/main.tsx) calls `createRoot`, not `hydrateRoot`. Express sends independently handwritten HTML, then React replaces it. Sharing two H1 constants does not fix this architecture.

2. The existing “single SEO source of truth” is not actually consumed.

[`shared/seo-routes.ts`](https://github.com/scottpstevenson/Liberty-Bancard-Website-and-CRM/blob/55343b2d7a9babd459774c76875fa19f9a2c37f2/shared/seo-routes.ts) contains 67 route definitions, but public React pages continue hardcoding their own metadata. Its client re-export is unused.

3. The SEO test deliberately accepts empty SPA responses.

[`scripts/seo-audit.ts`](https://github.com/scottpstevenson/Liberty-Bancard-Website-and-CRM/blob/55343b2d7a9babd459774c76875fa19f9a2c37f2/scripts/seo-audit.ts) detects a bare SPA shell and then validates declared constants instead of the response or rendered DOM. It also treats dynamic 404s as warnings unless `STRICT=1`. This can report success while production has the failures above.

4. Blog coverage is severely split.

* React contains 92 static posts.
* Server crawler rendering contains only 14.
* `shared/blog-slugs.ts` contains 72.
* The live blog sitemap contains only 14 posts plus the hub.

Therefore 78 real React articles are absent from the sitemap and return the generic empty shell to Googlebot.

5. Industry registries disagree.

React supports 14 industries; the server supports eight. The six extra React slugs are nevertheless inserted into the sitemap, producing six of the 11 404s.

6. Competitor registries disagree.

Alternatives/switch pages support 12 competitors; `/compare` supports seven. The sitemap incorrectly generates comparison URLs for all 12.

7. City hubs break after client boot.

Express serves `/locations/:city`, but `App.tsx` has no matching client route. The server city page can be replaced by the React 404 screen after JavaScript loads.

8. Noindex enforcement is incomplete.

Server `X-Robots-Tag` is missing from routes such as:

* `/partner-login`
* `/statement-upload/:token`
* `/co-branded-proposal/:token`
* `/packet/*`
* `/partner/:slug`
* `/partner-org/:slug`
* `/quiz/*`
* `/sales/*`

Several apply client-side `noindex`, but non-JavaScript crawlers receive no protection.

9. Title construction can duplicate the brand.

`SEO.tsx` always appends `| Liberty Bancard`, while at least 24 callers already include the brand in their title. Hydrated titles can become `… | Liberty Bancard | Liberty Bancard`.

10. Sitemap dates are misleading.

Core, location, and comparison sitemaps set `lastmod` to the current date on every request regardless of content changes. Google advises using `lastmod` only when it accurately represents a significant page update. [Google sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/overview)

## Corrected build plan

### P0 — Restore authority and crawl correctness

1. Restore a required GitHub workflow before implementation. SEO tests must block merges and deployments.

2. Deploy only from the audited SHA; require `/api/health.sha` to match.

3. Upgrade existing `shared/seo-routes.ts` into the canonical public-route manifest. Do not create competing `server/ssr/home-content.ts` files.

4. Generate sitemap membership from that manifest and shared dynamic content registries.

5. Resolve the 11 sitemap errors correctly:

   * Build server rendering for the six valid React industry pages, or temporarily remove them from the sitemap.
   * Remove the five nonexistent `/compare/*` URLs. Do not redirect Shopify, Fiserv, or Worldpay comparisons to unrelated Square pages.

6. Return true HTTP 404 for unknown public URLs.

7. Generate `X-Robots-Tag` from the canonical route manifest for every private, tokenized, authentication, dashboard, partner-dashboard, and sales-only route.

8. Redirect `/contact` to canonical `/about-contact`.

9. Redirect `/sitemap-index.xml` to `/sitemap.xml` or remove it; it currently acts as a competing stale sitemap index.

10. Use real content modification dates rather than request time.

### P1 — Replace the dual renderer

1. Move pure public content into shared modules:

   * All 92 blog posts
   * All 14 industries
   * Comparison/alternative competitor data
   * Location/city data
   * Glossary content
   * Route metadata

2. Render indexable React routes with actual React SSR or SSG.

3. Replace `createRoot` with `hydrateRoot` for server-rendered public routes.

4. Keep CRM/dashboard routes client-rendered and noindexed.

5. Remove crawler-only blog branching. Bots and users should receive semantically identical content; Google now classifies dynamic rendering as a deprecated workaround. [Google Search documentation update](https://developers.google.com/search/updates)

6. Add a real React city-hub route or make those pages server-only without booting the React application.

7. Retire handwritten page generators as each route moves to shared React rendering.

### P1 — Metadata and social previews

1. Make route-manifest titles final strings; stop automatically appending the brand.
2. Make `canonical`, `og:url`, hreflang, and structured-data URLs derive from one resolved canonical URL.
3. Migrate competitor and glossary pages through the shared metadata shell.
4. Keep the existing dynamic `/og/:template/:slug.png` route. It returned valid `image/png` for all three samples tested; replacing it with a static fallback is unnecessary.
5. Add `/partners`, partner profession pages, `/areas-served`, authors, and all 92 valid blog posts to appropriate sitemaps.
6. Validate existing structured data instead of excluding it from scope.
