This is a coherent combined task, but it has several safety gaps that should be corrected before building.

The biggest issue: the proposed smoke test toggles Serper on and calls recovery. Against the shared environment, that could initiate a real provider probe. That test must be isolated with fake transports.

Add these corrections:

```markdown
## Required Safety Corrections

### Control mutations

All Serper mutations must delegate to the canonical Serper control service/gateway. Routes may not update `serper_control` directly.

For enable/disable:

- Require `{ enabled: boolean, reason: string }`
- Require a non-empty reason
- Atomically update only `enabled` and write the audit record in one transaction
- Record actor, correlation ID, before/after value, timestamp, and policy version
- Enabling does not force the circuit to `closed`; an open circuit remains open until approved recovery
- Return the committed control and circuit state

A failed audit write must roll back the enabled mutation.

### Window reset

Window reset is a high-risk accounting action, not an ordinary dashboard refresh button.

Require:

- Non-empty reason
- Explicit confirmation
- Actor and correlation ID
- Expected current `windowStartedAt` or version for concurrency protection
- Atomic reset and audit
- Lifetime counters remain unchanged
- `enabled` and circuit state remain unchanged
- Resetting counters must not authorize traffic or close an open circuit

The UI must clearly warn that this changes local accounting and does not renew provider quota.

### Circuit alerts

Alert cooldown claims must be atomic across processes. A separate `getSystemSetting()` followed by `setSystemSetting()` is race-prone and can send duplicate messages.

Send alerts only after the circuit transition commits, and only on an actual state transition:

- `closed → open`
- `half_open → open`
- `half_open → closed`

Do not alert repeatedly while the circuit is already open.

Alert delivery must use the canonical SMTP/outbound authorization boundary and an approved internal-operational purpose/exception. It may not bypass the global outbound authority with a caller-controlled boolean.

Alert failures must:

- Never affect circuit processing
- Be recorded as sanitized delivery failures
- Never expose API keys, provider responses, queries, recipients, or contact data

Use fake SMTP in every test.

### Invalid-contact results

Audit logs are immutable, so returning every historical event will show duplicates and contacts that have already been repaired.

The route must:

- Return the latest invalid-contact event per contact by default
- Include an occurrence count and latest timestamp
- Determine whether the contact is still invalid using the canonical local validator
- Support `status=unresolved|resolved|all`, defaulting to `unresolved`
- Never return raw audit details or provider response bodies
- Safely validate `limit` and `offset`
- Avoid unsafe casts when joining textual `entityId` to contact IDs

Suggested response:

`{ total, rows: [{ contactId, firstName, lastName, email, reasonCode, stage, occurrences, lastOccurredAt, status }] }`

### UI safeguards

- Enable/disable requires a reason dialog
- Manual recovery requires a reason and displays that it enters `half_open`
- Window reset requires a warning, reason, and explicit confirmation
- Disable controls while a mutation is pending
- Refresh from the committed server response after every mutation
- Do not optimistically show Serper as enabled or recovered
- Display alert-delivery status separately from circuit status

## Test Corrections

Replace the proposed shared-environment smoke test with isolated route/service tests using:

- Isolated test database or transaction rollback
- Fake Serper transport
- Fake SMTP transport
- Fake authenticated admin and non-admin identities

Prove:

1. Non-admin access is rejected for every new route.
2. Malformed bodies and missing reasons are rejected.
3. Enable mutation and audit commit atomically.
4. Audit failure rolls back the enable mutation.
5. Enabling while the circuit is open leaves it open.
6. Window reset preserves lifetime totals and circuit/enabled state.
7. Concurrent open transitions claim only one alert.
8. Repeated failures while already open send no additional alert.
9. SMTP failure does not affect the circuit transition.
10. Alerts pass through the approved outbound authorization boundary.
11. Recovery enters half-open and uses a fake provider probe.
12. Invalid-contact results are deduplicated and default to unresolved.
13. Resolved contacts are excluded from the default view.
14. No test changes shared Serper state, sends email, or contacts Serper.

The pre-deploy test must never toggle the real shared control row, reset real counters, call the production recovery endpoint, write cooldown keys in shared settings, or send a real alert.
```
