625 — Operator Dashboard IA Rebuild: Grouped Sidebar + Command Center

Mode

Start in PLAN MODE ONLY.

Do not edit code until preflight is complete.

This task exists because the Operator Dashboard currently has 23 top-level tabs, and Wave 9 would push it to 25 by adding Lifecycle and SDR. That is not a command center. It is a cluttered diagnostic filing cabinet.

The goal is to replace the flat horizontal tab strip with a premium grouped navigation architecture that can scale.

Core Product Goal

The dashboard should answer:

1. What needs attention right now?
2. Are jobs/queues healthy?
3. Are leads moving through the lifecycle?
4. Are SDR/outreach systems working safely?
5. Are sends, bounces, blocks, and opt-outs healthy?
6. Is GHL syncing correctly?
7. Are conversion metrics improving?
8. Are AI/content systems healthy?

The operator should not scan 25 equal-weight tabs to find the answer.

Important Wave 9 Integration Rule

Wave 9 data/API work may continue, but the UI destination changes.

Allowed Wave 9 backend endpoints:

GET /api/operator/lifecycle-stage-counts
GET /api/operator/sdr-stats
GET /api/activation/readiness

Pipeline & Conversion → Lifecycle
SDR & Outreach → SDR

Build Phase Plan

Phase 1 — Navigation Shell + Grouped Sidebar

Goal:

Replace the flat horizontal 23-tab strip with grouped sidebar navigation while preserving all existing panels and values.

Scope:

* build grouped sidebar nav
* create section groups
* preserve existing tab content components
* preserve existing tab values internally if needed
* keep old tab state compatibility
* add Command Center landing item
* no backend changes
* no panel logic changes

Do not yet deeply redesign individual panels.

Phase 2 — Command Center Landing View

Goal:

Create a real daily operator overview.

Scope:

* summary cards
* attention queue
* lifecycle snapshot if endpoint exists
* SDR snapshot if endpoint exists
* conversion snapshot using existing Wave 8 endpoints
* GHL snapshot using existing Wave 7 endpoints
* system health snapshot using existing endpoints

No behavior mutations.

Phase 3 — Wave 9 Lifecycle + SDR Detail Panels

Goal:

Add detail views in their grouped homes.

Scope:

* Pipeline & Conversion → Lifecycle
* SDR & Outreach → SDR
* use Wave 9 endpoints
* no new top-level tabs

Phase 4 — Optional Cmd+K / Quick Switcher

Goal:

Fast navigation across all dashboard panels.

Only build if:

* a command palette already exists, or
* shadcn Command is available and can be added safely.

Scope:

* search panel labels
* jump to grouped nav item
* keyboard shortcut if app already supports shortcut patterns
* no data mutations

If command palette is not already supported, leave as follow-up.

Phase 5 — Cleanup / Deprecation Review

Goal:

Identify duplicate or low-value panels for future merge/hide.

Do not delete panels in this phase unless separately approved.

AI / Content

⸻

Compatibility Requirements

Preserve existing tab values where possible.

If current URLs or links use values like:

?tab=conversion
?tab=ghl-connection

then those must keep working.

If old tab values are replaced by grouped nav state, add a mapping layer:

conversion → group=pipeline, item=conversion
ghl-connection → group=integrations, item=ghl-connection
queue-metrics → group=system-health, item=queue-metrics

Do not break bookmarks or internal links.

⸻

Command Center Requirements

The Command Center landing view should not be another 25-panel dump.

It should show:

Top Status Row

* readiness / launch status
* queue/job health
* GHL sync health
* SDR health
* conversion health
* compliance/block health

Attention Queue

A prioritized list:

What needs attention now?

Examples:

* circuit breaker open
* DLQ jobs present
* sender utilization exceeded threshold
* high blocked attempts
* stuck leads above threshold
* no analytics events in recent window
* sequence family active but not firing

Snapshot Sections

* Lifecycle Pipeline Snapshot
* SDR Health Snapshot
* Conversion Snapshot
* GHL Sync Snapshot
* System Health Snapshot
* Compliance Snapshot

Each snapshot should have a “View details” link to the grouped detail item.

⸻

Do Not Do

Do not:

* add Lifecycle and SDR as flat top-level tabs
* delete existing panels
* rename tab values without compatibility
* rebuild every panel visually
* change backend behavior
* change contactability
* change consent
* change sequence enrollment
* change analytics collection
* change GHL sync logic
* expose PII
* create CSV exports
* add new sending/actions
* recreate Wave 7 or Wave 8

⸻

Kill Lines

Stop and report before build if:

* existing tab state cannot be mapped safely.
* tab values are externally linked and no compatibility mapping is possible.
* the sidebar refactor requires rewriting the entire 4,600-line dashboard file.
* panel rendering is too tightly coupled to the current Tabs component.
* existing Conversion or GHL panels would need to be rewritten.
* adding Command Center would duplicate entire existing panels instead of summarizing them.
* role guards would be weakened.
* PII would be exposed.
* new backend behavior would be required.
* Cmd+K requires a new app-wide keyboard system and would broaden scope.
* Lifecycle/SDR Wave 9 panels are not available yet and the build would fake data.
