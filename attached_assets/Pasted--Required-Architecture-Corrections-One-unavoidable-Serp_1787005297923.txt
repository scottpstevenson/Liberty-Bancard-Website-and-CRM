## Required Architecture Corrections

### One unavoidable Serper gateway

All Serper `/search` and `/places` network calls must pass through one canonical client/gateway. No service, worker, scheduler, or route may call Serper with raw `fetch`.

The gateway must:

1. Check the persisted global Serper control state immediately before network I/O.
2. Atomically claim budget for the current billing window.
3. Execute the provider request.
4. Classify and atomically record the result.
5. Update the shared circuit state.

Add a static pre-deploy scan that fails when production code invokes a Serper endpoint outside the approved adapter.

### Fail-closed global control

Add a persisted `SERPER_ENABLED`/control state covering every Serper consumer, including:

- Prospect enrichment
- Sunbiz enrichment
- SDR `/places` enrichment
- Manual/admin enrichment routes
- Scheduled and queued jobs

Missing, malformed, expired, or unreadable control state must block provider I/O. Deploy the initial state disabled.

This global control must not override narrower worker or Sunbiz pauses.

### Distributed circuit breaker

The circuit cannot be process-local. Persist shared state containing:

- `state`: `closed | open | half_open`
- `consecutiveFailures`
- `openedAt`
- `reasonCode`
- `lastFailureAt`
- `lastSuccessAt`
- `halfOpenProbeClaimedAt`
- `policyVersion`

Only one process may claim a half-open probe.

Classification:

- 401/403: open immediately
- Confirmed quota exhaustion: open immediately
- Sustained 429: open according to policy
- Timeout/network/5xx: increment threshold
- Valid 200 with zero results: provider success, zero data yield
- Query/entity validation failure: record separately; do not automatically classify as provider outage

### Billing-window accounting

Do not erase lifetime evidence every month.

Maintain separate:

- Lifetime totals
- Current billing-window totals
- `windowStartedAt`
- `windowEndsAt`
- Provider-reported balance, if available
- Local configured budget
- Data-yield totals

Calendar rollover may reset only window counters. It must not automatically close an open authentication/quota circuit or authorize unrestricted traffic.

At rollover, transition quota-related circuits to `half_open` and allow one bounded probe. A successful probe may close the circuit.

All counters and circuit transitions must be atomic across processes. Do not use read-modify-write JSON updates without locking or an atomic database operation.

### Admin recovery

Manual recovery requires:

- Authorized admin
- Non-empty reason
- Actor and correlation ID
- Audit event
- Transition to `half_open`, not directly to unrestricted `closed`
- One bounded diagnostic probe
- Automatic reopening if that probe fails

Return the committed control state, circuit state, billing window, and policy version.

### Tests

Use fake transports only. Prove:

1. Every `/search` and `/places` path blocks while disabled.
2. Missing/malformed/DB-error control state blocks calls.
3. Twenty configured failures open the shared circuit.
4. 401/403 and confirmed quota errors open immediately.
5. A 200 response with zero results counts as provider success but zero yield.
6. Concurrent processes cannot exceed the configured budget or claim multiple half-open probes.
7. Monthly rollover preserves lifetime totals and does not blindly close the circuit.
8. Manual override enters half-open and is fully audited.
9. New raw Serper fetches fail the static compliance scan.
10. No test contacts a real Serper endpoint.

### Deployment verification

After deployment:

1. Confirm the global Serper control is disabled.
2. Observe for at least 10 minutes.
3. Verify tracked `/search` calls and previously untracked `/places` calls are both zero.
4. Confirm existing queues continue safely without provider I/O.
5. Do not enable normal traffic until provider credentials/quota are confirmed and a capped canary passes.
