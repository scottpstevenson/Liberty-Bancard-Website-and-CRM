You are the senior production-readiness engineer for this application. Perform a complete go-live audit, then fix every issue you can safely fix. This is a real business platform that needs to be ready for production immediately—not a demo.

First, inspect the entire existing codebase, database schema/data, deployment configuration, environment-variable usage, integrations, scheduled jobs/crons, email provider setup, workflows, automations, UI, UX, authentication, permissions, logging, error handling, and API routes.

Use Claude as an independent reviewer where available: have it review the architecture, critical code paths, production risks, UI/UX issues, email/workflow logic, and missing edge cases. Reconcile its feedback with your own findings. Do not blindly rewrite working code.

Audit and fix all of the following:

1. Code and reliability
- Run the app and identify all build, type, lint, runtime, console, network, API, and database errors.
- Fix broken imports, dead routes, bad queries, unhandled promises, missing loading/error states, duplicate logic, insecure defaults, stale references, and broken links/buttons.
- Ensure forms validate properly, prevent duplicate submissions, show useful success/error feedback, and preserve entered data where appropriate.
- Check mobile, tablet, and desktop responsiveness.
- Confirm all navigation, filters, search, sorting, pagination, modals, dashboards, exports, uploads, and role-based screens work.
- Remove debug logs, temporary bypasses, placeholder actions, fake success messages, mocked production behavior, and unused code.

2. Authentication, permissions, and security
- Verify sign-up, sign-in, sign-out, password reset, session expiration, protected pages, admin access, and role permissions.
- Ensure users cannot view or modify data they do not own or have permission to access.
- Confirm secrets are only referenced through environment variables and never exposed in frontend code, logs, commits, or API responses.
- Add sensible rate limiting, input validation, authorization checks, error boundaries, and audit logging where missing.
- Do not create test accounts or leave test credentials behind.

3. Database and data hygiene
- Review every table and relationship for integrity, orphaned records, duplicate records, bad defaults, and missing constraints/indexes.
- Identify all demo, seed, test, placeholder, fake, sandbox, or sample data currently visible in the platform.
- Before deletion, create a backup/export or clearly document the exact records to be removed.
- Remove all demo/test/sample data from the live-facing app and database. Keep only real approved production data.
- Ensure empty states look polished and useful after cleanup—never like a broken or unfinished product.
- Confirm deletion/archiving behavior is safe, intentional, and recoverable where appropriate.

4. Email, sequences, workflows, and notifications
- Audit every transactional email, campaign, sequence, automation, trigger, template, sender identity, reply-to address, unsubscribe link, suppression behavior, and event trigger.
- Verify all email integrations, domains, API keys, SPF/DKIM/DMARC requirements, webhook handling, and bounce/complaint handling.
- Make sure no email can accidentally send to test contacts, internal staff, duplicates, unsubscribed contacts, or invalid addresses.
- Verify workflow entry/exit conditions, delays, branching, enrollment rules, re-enrollment prevention, stop conditions, tags/status changes, ownership assignment, and notifications.
- Confirm every sequence has correct copy, links, personalization fallbacks, sender/reply settings, scheduling windows, and compliance elements.
- Disable or delete abandoned, duplicate, experimental, draft, or unsafe workflows/sequences. Do not send a live blast during testing.

5. Scheduled jobs, crons, queues, and integrations
- Identify every cron job, scheduled task, queue worker, webhook, and background process.
- Confirm schedules are correct, timezone-safe, idempotent, monitored, and do not create duplicates.
- Test each job safely using isolated/preview execution where possible. Verify failure retries, error logs, alerting, and recovery behavior.
- Check all third-party integrations end to end. Confirm required credentials/configuration are present and missing credentials fail clearly rather than silently.
- Remove obsolete jobs, duplicate schedules, test webhooks, and development-only automation.

6. UI and UX
- Audit the entire app as if you are a first-time real user and a daily power user.
- Make the product clean, fast, intentional, and trustworthy. Fix visual inconsistency, spacing, typography, confusing labels, weak empty states, unclear CTAs, poor hierarchy, inaccessible contrast, and mobile usability issues.
- Do not add generic “AI dashboard” fluff, fake metrics, placeholder charts, or unnecessary screens.
- Ensure critical workflows take the fewest sensible clicks and are obvious without training.
- Make loading, empty, success, warning, and failure states polished and clear.

7. Go-live configuration
- Verify production deployment, custom domain, HTTPS, environment separation, database connection, backup strategy, error monitoring, analytics, sender domains, legal/footer links, privacy policy, terms, and support/contact paths.
- Verify production settings are not pointing to localhost, staging URLs, sandbox APIs, test payment/email providers, or test webhooks.
- Create a concise operational runbook for how to monitor the app, recover from common failures, manage users, review failed jobs, and safely roll back a deployment.

Rules:
- Do not leave test data, demo data, fake metrics, debug controls, or unfinished screens in the production application.
- Do not break existing real data, live workflows, or production integrations. Back up/document before deleting or changing data.
- Do not claim something works unless you actually tested it.
- If credentials, access, DNS changes, an external integration setting, or a business decision is needed from me, do not guess. Put it in a clearly labeled “Owner Action Required” list with exact steps.
- Prioritize fixing blockers first. Make reasonable safe fixes without waiting for approval.

At the end, deliver a detailed but executive-friendly Go-Live Audit Report with:
A. Overall launch status: GO / GO WITH CONDITIONS / NO-GO
B. What you tested, with pass/fail status
C. Every issue found, severity, root cause, and exact fix
D. Changes you made
E. Demo/test data removed and backup/location details
F. Cron/workflow/email verification results
G. Remaining owner actions, if any
H. A prioritized 24-hour launch checklist
I. A final list of URLs/screens/workflows that were manually verified

Do not stop at recommendations. Fix the code and configuration issues you can, verify the fixes, then report the results.
