Addendum to #695 — Voice / SMS / Ringless Go-Live Audit

Approved directionally, but do not build as a true in-app channel activation system.

The app cannot safely set or pause these flags:

SMS_ENABLED
VOICE_AI_ENABLED
RINGLESS_VM_ENABLED

They are Replit Secrets / environment variables and require manual operator action plus restart.

This task must build a readiness/approval gate, not programmatic activation.

⸻

1. Rename “enable” to approval/audit language

The route may be:

POST /api/activation/channel-enable/:channel

if preserving the proposed URL is easier, but the behavior must be:

server-side checklist passes
→ write immutable audit row: action = "enable_approved"
→ return manual Replit Secrets instructions
→ do NOT set env var
→ do NOT return enabled:true unless process.env already shows it enabled

Preferred response:

{
  approvedToEnable: true,
  auditId,
  currentlyEnabled: false,
  manualStep: "Set SMS_ENABLED=true in Replit Secrets and restart the app."
}

Kill line:

STOP if the route claims a channel is enabled when it only wrote an approval audit row.

⸻

2. Do not programmatically set or pause env flags

The app must not attempt to mutate Replit Secrets or environment variables.

Do not implement:

process.env.SMS_ENABLED = "true"
process.env.VOICE_AI_ENABLED = "true"
process.env.RINGLESS_VM_ENABLED = "true"

Do not implement fake pause/resume behavior for env flags.

Kill line:

STOP if server code tries to activate, disable, pause, or resume high-risk channel env flags.

⸻

3. Test batch must be dry-run only

The proposed test-batch route should not send SMS, voice calls, ringless voicemail, emails, GHL workflows, or sequence steps.

It should return up to 5 eligible test contacts for admin review:

POST /api/activation/channel-test-batch/:channel
→ evaluate contactability dry-run
→ return max 5 candidate contacts
→ write audit action = "test_batch_preview"
→ no outbound send

It does not need to require the channel env flag to be enabled, because this is a readiness preview.

Kill line:

STOP if test-batch sends or queues any outbound communication.

Kill line:

STOP if test-batch can return more than 5 contacts.

⸻

4. Checklist must inspect real channel/sequence metadata

Do not assume a field like:

sequence.channel

exists.

Before implementing checklist item “active template exists,” verify the actual source of truth:

* sequence channelsAllowed
* sequence step actionType
* template/channel metadata
* smart-router channel mapping

Channel mapping should treat:

sms → sms
voice → call / voice_ai if that is the real action type
ringless → voicemail_drop / ringless_vm if that is the real action type

Kill line:

STOP if checklist passes because of a guessed channel field that does not exist or does not reflect actual outbound step type.

⸻

5. Checklist result is server-owned

The client may render checklist results, but it cannot submit:

{ allPassed: true }

as proof.

Enable approval route must re-run:

evaluateChannelChecklist(channel)

server-side.

Kill line:

STOP if client-provided checklist state can approve a channel.

⸻

6. Audit log schema must match the real auth/user model

Before adding:

activatedBy integer FK users.id

verify the real authenticated user table and ID type.

If admin identity is Clerk/string-based, use the existing audit pattern instead of forcing an integer FK.

Suggested fields:

id
channel
action: checklist_viewed | enable_approved | disabled_recorded | test_batch_preview
checklistSnapshot jsonb
actorUserId nullable
actorEmail nullable
notes text
createdAt timestamp

Do not add a bad FK to the wrong user table.

Kill line:

STOP if channel_audit_log references a user table/id type that does not match the app's auth model.

⸻

7. Disable audit is optional unless there is a real disable workflow

The original task mentions enable/disable audit rows, but only defines enable and test-batch routes.

Either:

1. add a manual “record disable” audit route that does not change env flags, or
2. remove disable from this task’s done criteria.

Do not pretend the app disabled a channel unless the env flag actually changed.

⸻

Corrected build scope

Build:

1. channel_audit_log append-only table.
2. Server-side checklist evaluator.
3. Read-only checklist endpoint.
4. Approval-to-enable endpoint that writes audit and returns manual Replit Secrets instructions.
5. Dry-run test-batch preview capped at 5.
6. ActivationPanel compliance section.
7. Smoke tests and role guards.

Do not:

* flip env flags
* mutate Replit Secrets
* send SMS
* place voice calls
* send ringless voicemail
* enroll sequences
* queue outbound jobs
* auto-pause channels
* trust client checklist state
* add update/delete routes for audit rows
