677 — Homepage Top-of-Page Section Treatment + Hero Proof Stack Repair

Mode

PLAN / PREFLIGHT FIRST.

Do not build yet.

The previous mobile hero cleanup direction is not enough. The real issue is that the top of the homepage has no true section treatment separation. The hero, phone/compare row, proof strip, compliance text, and Statement Fee Audit card all read as one continuous white/paper-grid area.

This task must diagnose and plan a top-of-page architecture fix before code changes.

⸻

Current Problem

On mobile, the top of the homepage currently reads as one long floating grid:

1. Hero message
2. Upload / Book CTAs
3. PDF note
4. Phone number + Compare My Current Setup row
5. Floating proof strip:
    * Payment processing
    * Line-item breakdown
    * Real human support
6. Compliance paragraph
7. Statement Fee Audit card

The issue is not just that the phone/compare row is low contrast.

The bigger issue is:

Everything is sitting on the same white / paper-line background treatment.

The proof strip is floating. The compliance text is floating. Then the navy audit card appears immediately after, but it still feels like part of the same grid because there is no real section boundary.

The top of page needs fewer floating rows and stronger visual chaptering.

⸻

Goal

Create a clean top-of-page structure with deliberate section treatments.

The page should feel like:

Hero section
→ proof / trust bridge
→ sample review section
→ next content section

not:

Hero elements floating on white
→ utility row floating on white
→ proof row floating on white
→ compliance text floating on white
→ navy card floating on white

⸻

Return a plan before building.

Required Architecture Direction

The top of the mobile homepage should use this structure:

Section 1 — Clean Hero

Treatment:

clean white / no ledger grid / no paper lines

Contains:

* logo/header above from Navbar
* badge
* H1
* subheadline
* Upload CTA
* Book CTA
* short PDF/privacy note

Does NOT contain:

* phone/compare row
* floating proof strip
* compliance paragraph
* audit card

The hero should end cleanly after the CTA note.

⸻

Section 2 — Compact Trust Bridge

Treatment:

solid white or very subtle bg-muted/20
border-y border-border

Contains either:

Option A — compact service proof row:

Payment processing
Line-item review
Human support

or Option B — remove this row entirely if the new Services section already covers it.

Preferred:

Use a compact trust bridge only if it visually feels like a real band, not a floating row.

The bridge must have its own background/border treatment.

It cannot float loose on the same hero canvas.

⸻

Section 3 — Sample Statement Review Block

Treatment:

section-warm or bg-muted/30
border-b border-border
py-8

Contains:

* small label:
    Example statement review
* Statement Fee Audit card
* compliance note directly attached below the card

This block should make the audit card feel intentional:

“This is the sample output.”

not:

“Another floating object under the hero.”

The audit card should not be sitting immediately after a floating proof strip on the same white background.

⸻

Section 4 — Next Content

After the sample review block, the page should transition clearly into the next section.

Do not let the next section reuse the same background without a boundary.

⸻

Phone / Compare Row Decision

The current phone/compare row should not remain between the CTAs and the audit card on mobile.

Choose one:

Preferred

Hide it on mobile.

Reason:

* Upload and Book are already the primary actions.
* Phone is available in header / nav context.
* Compare is tertiary and should not interrupt the hero proof stack.

Acceptable

Move it below the sample review block as two compact action pills.

If kept, it must be:

* darker
* larger
* higher contrast
* visually grouped as pills/buttons
* not floating inline text

Kill line:

Stop if phone/compare remains as faint inline text between the CTAs and audit card on mobile.

⸻

Proof Strip Decision

The current proof strip should not remain as a loose row on the same white background.

Choose one:

Preferred

Move proof items into a real trust bridge band.

Acceptable

Hide it on mobile and rely on the new Services section.

Kill line:

Stop if Payment processing / Line-item breakdown / Real human support remains floating loose above the audit card.

⸻

Compliance Text Decision

The compliance text must stay, but it should not float between unrelated rows.

Move it so it is attached to the Statement Fee Audit card:

* directly under the card, or
* inside the card footer if the existing structure supports it

Kill line:

Stop if the compliance text remains a standalone paragraph above the audit card.

⸻

Background / Section Treatment Requirement

This is the core requirement.

The top of page must not use one continuous white/paper-grid treatment.

Required mobile treatment sequence:

Hero: clean white
Trust bridge: bordered white or muted band
Sample review: warm/muted section block
Next section: distinct background or border transition

Do not rely on the audit card’s navy header to create the section break. It is not enough.

Kill line:

Stop if hero, proof strip, compliance text, and audit card still share the same white/paper-grid background treatment.

⸻

Ledger / Paper Grid

Remove or neutralize ledger/paper-line/grid texture from the mobile hero and top proof stack.

Allowed:

* use very subtle texture later in mid-page sections
* keep desktop if it looks intentional

Not allowed:

* obvious graph-paper / worksheet lines behind the mobile hero stack
* top of page reading like accounting paper

Kill line:

Stop if the mobile top-of-page still looks like graph paper or a worksheet.

⸻

Desktop Handling

Desktop can remain mostly unchanged if it currently works.

Do not break desktop.

If moving wrappers affects desktop, create mobile-only structure using responsive classes.

Preferred:

Mobile-specific section treatment changes first.
Desktop unchanged unless the same issue is visible.
