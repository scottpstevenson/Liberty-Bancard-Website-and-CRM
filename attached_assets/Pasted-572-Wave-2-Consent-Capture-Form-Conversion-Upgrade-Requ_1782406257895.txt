What & Why

Wave 1A created the backend contactability engine and consent-tier enforcement. Wave 1B created operator visibility. Now Liberty needs the inbound side: every public form that captures a phone number must clearly and safely capture whether the user granted optional prior express written consent for automated call/text/voicemail channels.

This task upgrades public forms to capture PEWC evidence cleanly while improving conversion clarity.

This is not an automation enablement task. It only captures and stores consent evidence. Wave 1A remains the enforcement authority. Wave 7 will handle GHL permission sync.

⸻

Core Principle

Form submission is not PEWC by default.

A user who submits a form but does not check the PEWC box is a warm inbound lead, not an opted-out contact and not a fully automated-contact lead.

Unchecked PEWC means:

* consentTier = warm_no_pewc
* email/manual human follow-up may still be allowed if otherwise compliant
* SMS, AI voice, and ringless voicemail remain blocked by Wave 1A
* do not set opted_out
* do not set doNotContact
* do not set SMS STOP
* do not treat as DNC

Checked PEWC means:

* write structured consent evidence
* update contact to pewc_full_automation only when evidence is valid and tied to the submitted phone number
* Wave 1A can later allow automated channels only if all other gates pass

⸻

Compliance Rules

PEWC checkbox requirements

Every public form that captures a phone number should show an optional PEWC checkbox.

The checkbox must be:

* unchecked by default
* optional
* visually separate from required privacy/terms acknowledgement
* close to the phone field or submit button
* written in clear language
* tied to the exact submitted phone number
* versioned
* auditable

It must not be required to submit the form.

It must not say or imply that consent is required to purchase or receive the free review.

Counsel-review note

Use the existing/counsel-approved disclosure text if present in the repo.

If no final approved text exists, create a clearly named versioned disclosure constant with safe placeholder language and mark it as requiring legal review before SMS/voice/RVM enablement.

Do not invent aggressive legal claims.

Recommended baseline disclosure language for implementation placeholder:

“I agree Liberty Bancard may contact me at the phone number provided by call, text message, or prerecorded/artificial voice message, including using automated technology, about payment processing services and related offers. Consent is not required to purchase or receive a free review. Message and data rates may apply. I can opt out at any time.”

If Florida-specific or ringless-voicemail-specific language already exists in the repo, preserve the stronger existing language.

Data Requirements

Use Wave 1A fields and schema.

Do not add schema columns unless preflight proves required fields are missing.

For every PEWC decision on a submitted form, write or update evidence with:

* contactId if available
* consentedPhone
* disclosureVersion
* disclosureText
* formId
* ipAddress if available
* userAgent if available
* sourceUrl / landing page URL
* UTM parameters where existing data model supports them
* whether checkbox was checked
* timestamp
* event type/category that clearly distinguishes grant vs declined/not granted
* details JSONB for request metadata if needed

If the table only has top-level PEWC columns plus details JSONB, use top-level fields for the canonical evidence and details for extra metadata.

Do not store a declined/non-checked event in a way that can be mistaken for consent granted.

⸻

Consent Event Semantics

Use clear event names if the schema supports event type.

Recommended:

* pewc_granted
* pewc_declined
* pewc_revoked only for actual revocation/STOP/unsubscribe events, not unchecked form submission

If the schema does not support event type directly, store this in details.eventType.

Rules:

* Checked box → pewc_granted
* Unchecked box on submitted form → pewc_declined or pewc_not_granted
* SMS STOP or opt-out → separate opt-out flow, not part of this task unless already wired
* Form abandonment → analytics only, not consent audit

⸻

Contact Tier Updates

On successful public form submission with phone number:

If PEWC checked and valid

* write pewc_granted audit evidence
* update contact consentTier = pewc_full_automation
* preserve/derive lifecycleStage according to the form intent if existing patterns support it
* do not enable automation flags

If PEWC unchecked

* write pewc_declined / pewc_not_granted audit record only if the product wants a record that the disclosure was shown and not accepted
* set or preserve consentTier = warm_no_pewc for inbound forms
* do not set opted-out/DNC/STOP
* do not block manual human call task or email unless another suppression rule applies

If no phone number

* do not show PEWC checkbox unless the form captures phone later
* do not write PEWC evidence
* do not upgrade to PEWC

Backend Consent Evidence Handling

Prefer integrating consent capture into each existing form submission endpoint, because that ties consent evidence to contact creation/update atomically.

Add shared helper:

server/services/consent-evidence.ts

or nearest existing service layer.

Recommended helper:

recordPewcDecision({
  contactId,
  phone,
  checked,
  formId,
  sourceUrl,
  disclosureVersion,
  disclosureText,
  ipAddress,
  userAgent,
  utm,
  details
})

Behavior:

* validates phone exists before granting PEWC
* writes consentAuditLogs entry
* stores canonical top-level fields
* stores extra metadata in details JSONB
* updates contact consentTier
* does not set opted-out/DNC/STOP on unchecked
* fails safely if checked but phone is missing
* idempotency guard to avoid duplicate consent rows on retry/double-submit where possible

If no service layer pattern exists, implement minimal helper near existing public route handlers and document follow-up.

Kill Lines

Stop and report before build if:

* Wave 1A consent audit columns are missing.
* consentTier is missing on contacts.
* Existing form endpoints cannot identify/create a contact.
* A form captures phone but has no safe way to submit PEWC metadata to the server.
* Shared disclosure text cannot be used by both client and server without duplication.
* The task would require making PEWC checkbox required.
* Unchecked PEWC would be treated as opt-out, STOP, DNC, or doNotContact.
* A form would upgrade to pewc_full_automation without a phone number.
* A form would upgrade to pewc_full_automation without storing disclosureVersion and disclosureText.
* Consent evidence would be written only client-side.
* Analytics would send raw phone numbers.
* Thank-you page events would fire repeatedly on re-render.
* The task would enable SMS, AI voice, ringless voicemail, or GHL workflow automation.
* Adding /api/public/consent would create an unauthenticated abuse endpoint without existing rate limit protection.
* The change would rewrite UploadStatement.tsx, FreeAnalysis.tsx, GetStarted.tsx, or MerchantApplication.tsx wholesale instead of surgical upgrades.
