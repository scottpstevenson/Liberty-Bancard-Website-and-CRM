MASTER SUCCESS TEST

For every prospect or merchant, Liberty should always be able to answer:

1. Who are they?
2. What lifecycle state are they in?
3. What is the opportunity/merchant worth?
4. What happened most recently?
5. What are we waiting on?
6. What should happen next?
7. Should AI/automation do it or a person?
8. Who owns it?
9. When is it due?
10. Is communication permitted?
11. Did the action execute?
12. What was the outcome?
13. What revenue did it ultimately create or preserve?

If any of those cannot be answered reliably, that part of the operating system is not finished.

I would also change how you use Replit tasks

Don’t create another 50–70 isolated tasks immediately. Create one parent project per Wave, then create implementation tasks only after Replit audits that Wave.

For example, instead of pre-creating ten underwriting tickets, create “Wave 4 — Application to Approval Audit & Build”. Have Replit inspect the current code, identify what is truly missing, and then generate the exact child tasks. That prevents the same problem you just discovered: the roadmap saying “TODO” when half the functionality already exists.

The first active work queue I’d use now is:

A1 GHL/Utility Architecture → B1 Next Best Action → C2 Speed-to-Lead audit → C5 Statement Acquisition audit → D1 Pricing Engine → D2 Proposal Decisioning → E1 Application Completion → E2 Underwriting → F1/F2/F3 Boarding/Equipment/Activation → H1/H2/H4 Economics.

That gives you a much cleaner master backlog: completed foundation stays completed, partial functionality gets extended rather than rebuilt, and the real critical path stays obvious.
