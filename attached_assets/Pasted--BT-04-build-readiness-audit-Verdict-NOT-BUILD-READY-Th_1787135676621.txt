## Intended final authority model

| Concern                  | Canonical authority                                                                                         |
| ------------------------ | ----------------------------------------------------------------------------------------------------------- |
| Consent facts            | Append-only, validated consent event service/table                                                          |
| Event ordering           | `effective_at`, `received_at`, stable event key, actor/source authority, deterministic restrictive tie rule |
| Contact projections      | One transactional reducer deriving channel and purpose state                                                |
| Email eligibility        | Canonical contactability policy for email and declared purpose                                              |
| SMS eligibility          | Canonical contactability policy including verified PEWC evidence and SMS status                             |
| Human consent changes    | Field-specific manager/admin command with actor, reason, evidence, and restrictive authorization            |
| Public form consent      | Versioned disclosures and separate channel evidence; never implicit from unrelated fields                   |
| Outbound network effects | Provider boundary requiring an evaluated decision token or explicit audited exception capability            |
| GHL workflow enrollment  | Declared workflow channel/purpose manifest plus the same contactability authority                           |
| Background execution     | Durable job/occurrence authority with claim, idempotency, result, retry, and reconciliation                 |
| Audit evidence           | Append-only DB authority; sends may not claim success when required audit persistence fails                 |
| Migration authority      | Additive successor migration from the rechecked journal head; no `db:push`                                  |
| Runtime rollout          | Pause → migrate → verify → deploy → canary → reconcile → unpause                                            |

## Lifecycle and concurrency proof required

| Scenario                                              | Required behavior                                                            |
| ----------------------------------------------------- | ---------------------------------------------------------------------------- |
| Two public submissions update one contact             | Serialize/reduce deterministically; no lost update                           |
| Older consent arrives after newer suppression         | Older event remains in history but cannot re-enable the projection           |
| Equal effective times conflict                        | Restrictive result wins unless a formally stronger authority is defined      |
| Duplicate webhook/form event                          | Stable event key produces one logical transition                             |
| Public positive consent follows DNC/opt-out           | No automatic re-enable without an authorized reconfirmation transition       |
| PEWC checked                                          | Evidence and channel projection commit atomically before eligibility         |
| Audit insert fails                                    | No externally claimed success; retry or terminal evidence state              |
| Provider returns `{success:false}`                    | Persist failure, never `sent`                                                |
| Provider succeeds, process crashes before persistence | Resolve through provider idempotency/reconciliation; do not blindly repeat   |
| Worker completes some steps and one fails             | Do not mark the entire workflow successfully completed                       |
| Lease expires while worker remains active             | Fencing/version rejects stale completion                                     |
| Recurring win-back succeeds                           | Schedule the next legitimate occurrence without losing recurring eligibility |
| 429/timeout/5xx                                       | Typed retryable outcome with durable backoff                                 |
| Invalid address/number or revoked consent             | Terminal/quarantined for that channel and purpose                            |
| Statement submission triggers confirmation            | Exactly one canonical occurrence and one truthful outcome                    |
