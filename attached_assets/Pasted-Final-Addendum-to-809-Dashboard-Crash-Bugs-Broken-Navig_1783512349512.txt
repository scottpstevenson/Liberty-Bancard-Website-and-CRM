Final Addendum to #809 — Dashboard Crash Bugs & Broken Navigation

Approved to build.

Critical guard — do not blindly assume query data is an array

For every .map() / .filter() fix, use a safe normalized value:

const items = Array.isArray(data) ? data : [];

If the endpoint can legitimately return an object wrapper, unwrap intentionally:

const items = Array.isArray(data?.items) ? data.items : [];

Do not use unsafe patterns like:

(data as any[]).map(...)
data!.map(...)
data ?? []

unless the value is proven to be an array.

Loading / error / empty states

Each affected page should distinguish:

loading → skeleton/spinner/DataState loading
error → visible error state with retry if existing pattern supports it
empty array → empty state
invalid response shape → safe empty/error state, no crash

Do not convert every bad API response into a silent empty table.

Sunbiz / entity destructuring guard

Fix crashes around fields like:

principalCity
principalState
principalZip

Required behavior:

missing entity → render “Unknown” / “Not available”
partial entity → render available fields only
malformed entity → no crash

Do not destructure directly from a possibly-null object.

Bad:

const { principalCity } = entity;

Good:

const principalCity = entity?.principalCity ?? "Unknown";

Mobile navbar / tab fix

Reproduce the issue before patching.

Investigate:

z-index overlay collision
pointer-events issue
transparent drawer/sheet overlay blocking taps
button rendered disabled accidentally
nested Link/button swallowing click
route mismatch
mobile-only absolute/fixed element covering tabs

Do not “fix” this by globally disabling overlays, removing role guards, or changing the sidebar IA.

Scope protection

Allowed:

safe query defaults
Array.isArray guards
optional chaining
DataState loading/error/empty states
mobile tap/z-index fix
small route/button handler fixes

Not allowed:

dashboard redesign
new backend pagination system
changing CRM workflows
changing SDR logic
changing sequence logic
changing role permissions
removing error boundaries
hiding pages from nav to avoid crashes

Kill lines

STOP if any affected dashboard page still crashes on undefined/null/error response data.
STOP if `.map()` or `.filter()` is called on unverified query data.
STOP if Sunbiz/entity destructuring can still throw on null/undefined records.
STOP if the mobile navbar/tabs are “fixed” by weakening role guards or hiding routes.
STOP if API errors are silently rendered as successful empty states.
STOP if this task changes outreach, sequence, contactability, or GHL logic.
