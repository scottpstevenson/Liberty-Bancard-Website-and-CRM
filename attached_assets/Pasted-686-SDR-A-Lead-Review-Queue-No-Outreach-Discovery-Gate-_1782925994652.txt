686 — SDR A-Lead Review Queue + No-Outreach Discovery Gate

What & Why

Liberty already has the Merchant Lead Intelligence infrastructure mostly built: discovery sources, SDR merchant tables, deduplication, AI scoring, payment-stack detector, CRM promotion paths, feature flags, and dashboards.

The missing first product layer is a safe human-reviewed queue for newly discovered high-priority leads.

Before adding API keys or enabling nightly discovery, Liberty needs a screen/workflow where A/B priority discovered merchants can be reviewed, discarded, or manually promoted to CRM. This prevents the discovery system from becoming uncontrolled outreach.

This task must not activate discovery or outreach. It only wires the review layer.

Goal

Create or wire a dashboard review queue for high-priority discovered SDR merchants.

The queue should show newly discovered/scored leads before first contact.

Target flow:

sdr_merchants
→ enrichment / processor detection / scoring
→ sdr_lead_state priorityBucket = A or B
→ Review Queue
→ human approves / discards / promotes to CRM

No outreach happens in this task.

⸻

Done Looks Like

A dashboard screen exists for “Discovered Leads” or “A-Lead Review Queue.”

It shows high-priority SDR leads with:

* business name
* website
* city / metro
* vertical
* source
* detected processor or payment stack, if available
* lead score / priority bucket
* reason for score
* suggested pitch angle, if available
* last discovered / last enriched timestamp
* current stage
* actions: approve/promote, discard, suppress, view details

The queue defaults to uncontacted high-priority leads only:

priorityBucket IN ('A', 'B')
stage IN ('SCORED', 'QUALIFIED', 'ENRICHED')
not contacted
not discarded
not suppressed

Exact stage names may be adjusted to match the existing schema.

Human actions:

1. Approve / Promote to CRM
    * Creates or promotes the CRM contact/prospect using the existing canonical promotion path.
    * Does not send outreach.
    * Does not enroll sequence automatically.
    * Logs who approved and when.
2. Discard
    * Removes the lead from the active review queue.
    * Keeps an audit trail/status so it does not keep resurfacing.
3. Suppress
    * Marks the merchant/domain/business as not eligible for future outreach.
    * Should prevent future discovery jobs from re-adding the same business as active.
4. View Details
    * Opens lead detail drawer or page showing source data, website, scoring breakdown, detector results, contacts if any, and compliance status if available.

3. Promotion action

After promotion:

* create/update CRM contact/prospect
* preserve source attribution
* preserve SDR merchant ID linkage if supported
* do not send email
* do not send SMS
* do not enroll sequence
* do not create autonomous outreach task unless the existing path already creates a manual human task

If the existing promotion path automatically enrolls sequences, STOP and report before using it.

⸻

4. Discard / suppress actions

Discard should remove the lead from the active review queue without deleting the merchant record.

Suppress should prevent the same business/domain from resurfacing as active in future discovery.

If suppression infrastructure already exists, reuse it.

If no suppression mechanism exists, add the smallest schema/status change needed and document it.

⸻

If detector is built but not connected to discovery storage, do not fully rebuild it in this task. Instead:

* recommend follow-up task: Processor Detector Expansion + Discovery Wiring
