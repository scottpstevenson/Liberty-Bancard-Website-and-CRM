Corrections to #692 — Sales Prep + Statement Acquisition Command Center

Do not build the current plan until ownership is confirmed.

The task is approved directionally, but the current implementation is too contact-column heavy. Statement acquisition is a funnel and should be tracked as a request/status object, not only as contacts.statementStatus.

Required preflight before build

Confirm:

1. Whether contacts already has source/sourceCategory/sourceId fields.
2. Whether sdrLeadState.contactId already links promoted SDR leads to contacts.
3. Whether contacts.sdrSourceId is necessary or redundant.
4. Whether statement uploads currently create/update:
    * contact
    * deal
    * document
    * statement upload record
    * analysis status
5. Which table should own pre-deal statement request status.
6. Whether a task table already exists for manual CRM tasks.
7. Whether there is an existing AI output/cache table for generated sales prep.

Do not guess.

⸻

Preferred data model

Prefer a new statement_requests table instead of only adding statementStatus to contacts.

Suggested fields:

id
contactId
dealId nullable
sdrSourceId nullable
status: none/requested/uploaded/review_pending/review_complete/abandoned
uploadToken or uploadUrl
requestedAt
uploadedAt nullable
reviewedAt nullable
abandonedAt nullable
lastReminderTaskAt nullable
createdBy
createdAt
updatedAt

If the existing schema already has a better statement/upload table, use that instead.

Kill line:

STOP if statement acquisition status is stored only as a single text column on contacts with no request timestamp/history.

⸻

SDR source attribution

Only add contacts.sdrSourceId if no reliable join already exists.

If sdrLeadState.contactId already links SDR lead → contact, use that relationship instead of adding duplicate attribution.

Kill line:

STOP if this task creates duplicate SDR attribution fields when `sdrLeadState.contactId` already provides the relationship.

⸻

Request Statement route

Add:

POST /api/contacts/:id/request-statement

This route should:

* create a statement request record
* generate a pre-filled upload URL/token
* set status to requested
* write audit log
* optionally create a manual task
* not send email
* not send SMS
* not enroll sequence
* not run runStatementUploadChain
* not trigger GHL workflow

Kill line:

STOP if requesting a statement sends outbound communication or enrolls automation.

⸻

Upload completion must update the same status

When a statement is uploaded using the generated link, the upload flow must update the statement request to:

uploaded

or:

review_pending

depending on the existing analysis workflow.

It must not leave the request stuck at requested.

Kill line:

STOP if a successfully uploaded statement does not update the statement request/status object.

⸻

Sales Prep

Add lazy-loaded Sales Prep inside ContactDetail only for SDR-sourced contacts.

Sales Prep should generate:

* call opener
* processor angle
* likely objection
* recommended CTA
* statement ask

But it must be cached persistently, not only in memory.

Use an existing AI output/cache table if available, or add a small persistent store.

If OPENAI_API_KEY is missing or TEST_MODE=true, return a safe fixture.

Kill line:

STOP if ContactDetail page load triggers an OpenAI call automatically.

Kill line:

STOP if the same contact repeatedly triggers paid AI generation because no persistent cache exists.

⸻

Abandoned upload worker

The abandoned upload worker may create a manual CRM task/notification only.

It must not send email or SMS.

It must also prevent duplicate tasks.

Required:

* only act on requests still in requested
* only after configured age, default 3 days
* check if an open abandoned-statement task already exists
* update lastReminderTaskAt
* create at most one open task per request/contact
* write audit log

Kill line:

STOP if the abandoned upload worker can create duplicate reminder tasks every night for the same request.

⸻

Validation

Required validation:

npx tsc --noEmit --skipLibCheck
npx tsx scripts/test-sales-prep.ts
npx tsx scripts/smoke-role-guards.ts

Manual checks:

* SDR contact shows Sales Prep tab.
* Non-SDR contact does not show Sales Prep tab.
* Request Statement creates request/status + upload link.
* Request Statement does not send outbound communication.
* Upload completion updates request/status.
* Abandoned worker creates a manual task only.
* Abandoned worker does not duplicate tasks.
* AI sales prep is lazy-loaded and cached.
