Final Addendum to #867 — Inline Sequence Picker on Vertical Breakdown Table

Approved to build.

Goal

Replace manual JSON editing for vertical → sequence routing with an inline dropdown in the existing Enrollment Routing Settings table.

Operators should be able to map each vertical directly from the breakdown row.

Required behavior

In:

client/src/pages/dashboard/OperatorDashboard.tsx
NewLeadEnrollPanel
Enrollment Routing Settings table

Each vertical row should show:

vertical label
coverage/gap metrics
current mapped sequence
active sequence dropdown
save/update state

Selecting a sequence should call the existing endpoint:

POST /api/admin/pipeline/vertical-sequence-map

Do not create a new endpoint unless the existing one cannot support single-vertical updates.

UX requirements

Dropdown options must include only safe selectable sequences:

active sequences
sequence id
sequence name
family/category if available
channel label if available

Show current mapping if one exists.

For unmapped verticals, show:

Unmapped

After save:

show success state
refresh/revalidate Stage Health / enrollment policy data
do not trigger enrollment

If save fails:

show inline error
preserve selected value locally until retry/cancel

Server endpoint guard

No server changes are expected.

But verify the existing endpoint supports one of these safe payloads:

{
  vertical: string;
  sequenceId: number | null;
}

or:

{
  verticalSequenceMap: Record<string, number | null>;
}

If the endpoint only accepts the whole JSON map, the UI may read the current map, update one key, and submit the full map.

Do not alter endpoint semantics unless necessary.

Critical kill line

Saving a mapping must only update routing settings.

It must not:

enroll contacts
start a backfill
toggle autoEnrollNewLeadDeals
activate a sequence
change triggerType
send outreach
create deals
trigger GHL sync

Unknown / Uncategorized vertical

If the Stage Health table includes:

Unknown / Uncategorized

the row may display a dropdown, but saving should only be allowed if the backend supports a stable key such as:

unknown
uncategorized
__unknown__

Do not save a literal display label unless that is already the canonical vertical key.

Mapping table behavior

Keep the JSON textarea as either:

removed entirely if inline editing fully replaces it

or:

collapsed Advanced JSON editor

If kept, inline dropdown and JSON state must stay in sync.

Preferred: inline dropdown as primary, JSON collapsed as advanced/admin fallback.

Kill lines

STOP if selecting a sequence triggers enrollment.
STOP if saving a mapping toggles autoEnrollNewLeadDeals.
STOP if saving a mapping activates sequences or changes triggerType.
STOP if inactive/paused sequences are selectable.
STOP if unknown/null verticals are saved with an unstable display-only key.
STOP if the inline dropdown and JSON textarea can drift into conflicting states.
STOP if server-side role guards are weakened.
STOP if GHL sync, deal creation, or outbound send logic is touched.

Validation

Manual checks:

Open Operator Dashboard
Open Enrollment Routing Settings
Find an unmapped vertical
Select an active sequence
Save mapping
Confirm Stage Health refreshes
Confirm mapping appears in row
Confirm no enrollment job starts
Confirm autoEnrollNewLeadDeals value is unchanged
Confirm inactive sequences are not selectable

Add/extend a focused test if practical:

scripts/test-vertical-sequence-map-ui.ts

or cover via existing route tests.

Required validation:

npx tsx scripts/smoke-role-guards.ts
