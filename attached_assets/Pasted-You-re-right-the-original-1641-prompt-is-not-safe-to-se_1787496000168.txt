### P0-02 — Enforce complete relationship coverage

* immutable retain with merge-operation linkage;
* uniqueness conflict;
* archive-only;
* redirect-aware live processing;
* terminalize-and-recreate pending work;
* authority-owned handoff;

4. Statically inventories known non-FK contact columns and job payload schemas.
5. Exits non-zero for any missing or unclassified pointer.

Merge execution must refuse to run when its manifest version is incomplete or stale.

### P0-03 — Define genuinely safe undo

“Reversible” means reversible only while all affected local rows remain unchanged.

For every moved row, record:

* table/action identifier from the code manifest;
* stable source-row identity;
* original owner;
* original version or hash;
* post-merge version or hash;
* operation ID;
* disposition;
* conflict metadata without PII.

Undo must preflight the entire operation and fail atomically if:

* any transferred row changed after the merge;
* a new survivor dependency creates ambiguity;
* restoring a row violates a unique constraint;
* contact identity, GHL identity, or `recordClass` changed;
* sequence state advanced;
* another merge overlaps either contact;
* redirect state changed;
* restoration would relax consent or recreate a send.

No partial undo is allowed. Consent restrictions, completed sends and external-provider effects are non-reversible evidence.

## P1 CORRECTIONS

### Identity evidence

Create one canonical identity-observation service, distinct from consent subjects.

* Store normalization version, source, validity and timestamp.
* For phone observations, store country, E.164 result, endpoint type, ownership confidence and shared-business status.

### Classification consistency

Contacts with different `recordClass` values must be blocked.

If the existing public classification API cannot read using the active transaction, add only a narrow read-only transaction-aware compatibility function to `commercial-classification-authority.ts`.

### Consent preservation

`consent_subjects`, consent facts, histories and channel projections remain attached to their original subjects.

Add only an authority-owned, idempotent restrictive carry-forward handoff in `consent-authority.ts`.

* Preserve both original subjects and evidence.
* Never copy permissive consent.
* Never relax restrictions during undo.
* Do not use or modify `server/services/consent-merge.ts` as the BT-07 reducer.
* Identity observations must not become a second consent-normalization authority.

### GHL disposition matrix

Implement and test this explicit matrix:

* Neither contact has a GHL ID: local merge allowed.
* Survivor only has a GHL ID: local merge allowed; no provider call.
* Deprecated contact only has a GHL ID: block pending explicit admin reconciliation or create durable post-commit reconciliation work; never silently copy the ID.
* Both have the same nonempty ID: treat as an invariant violation/manual review.
* Both have distinct nonempty IDs: block execution.

No GHL call may occur inside the merge transaction.

### Redirects, sequences and jobs

Create a dedicated, cycle-safe contact redirect resolver. Do not hide redirect behavior inside generic `getContact()`.

The resolver must return the requested ID, effective ID, redirect chain and operation ID, with bounded traversal and self/cycle rejection.

For pending work:

* retain completed send history on the original contact with an operation link;
* do not rewrite immutable delivery evidence;
* terminalize unsafe pending work as `superseded_by_merge`;
* create replacement canonical work only through an existing durable idempotent command;
* define an explicit conflict policy when both contacts have an active enrollment in the same sequence.
