Final Addendum to #756 — Persist PCI Assessment Checklist

Approved to build.

This task should add simple current-state persistence only. Do not redesign PCI compliance logic or build audit/version history.

⸻

Required behavior

The PCI Assessment checklist must persist across:

page refresh
navigation away/back
different browser session
different admin user opening the same dashboard

The progress/completion score must be computed from persisted checklist state, not local component state.

⸻

Preferred persistence model

Before adding a new table, inspect whether the app already has a settings/system-settings style table suitable for small admin-owned JSON state.

Preferred options, in order:

1. Existing settings/system_settings-style table with JSON value
2. Minimal dedicated pci_assessment_state table

If using a settings-style record, store a stable key such as:

pci_assessment_checklist_state

Example value shape:

{
  checkedRequirementIds: string[];
  updatedAt: string;
  updatedBy?: string;
}

If using a dedicated table, keep it minimal:

id
requirementId
checked
updatedAt
updatedBy

Do not store requirement labels as the source of truth if stable requirement IDs already exist in the UI.

⸻

API requirements

Add read/update endpoints behind existing dashboard/admin auth.

Example shape:

GET /api/admin/pci-assessment
PATCH /api/admin/pci-assessment

or use the existing admin route convention if different.

The update endpoint should accept explicit checked state:

{
  requirementId: string;
  checked: boolean;
}

or a full checklist state if that matches the existing storage pattern.

⸻

Frontend requirements

Update PciAssessment.tsx so it:

loads persisted checklist state on mount
renders loading/error states safely
updates backend when a requirement is checked/unchecked
computes progress from persisted state
keeps the current UI/interaction model
does not reset to defaults after refresh

Use optimistic update only if rollback/error handling is present.

If save fails, show a visible error and do not imply the checklist was saved.

⸻

Out of scope

Do not:

change the actual PCI requirement list
change PCI scoring logic beyond reading persisted state
add audit/version history
add notifications
add external PCI integrations
redesign the page
change dashboard role permissions broadly

⸻

Kill Lines

STOP if checklist state still resets on refresh.
STOP if progress is still computed only from local component state.
STOP if checking an item shows success when the backend save failed.
STOP if this task changes the PCI requirement list.
STOP if this task builds full audit history/versioning.
STOP if unauthenticated or non-dashboard users can read/update PCI checklist state.

⸻

Validation

npx tsc --noEmit --skipLibCheck
npx tsx scripts/smoke-role-guards.ts

8. Confirm persisted state appears.
9. Uncheck one item.
10. Refresh again.
11. Confirm updated persisted state and progress score are correct.
12. Simulate save failure if practical and confirm visible error.
