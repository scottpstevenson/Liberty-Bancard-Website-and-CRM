Perfect. Here is the actual Liberty Bancard build spec for a Replit-powered AI SDR system synced to GoHighLevel.

The design should be:

Replit = app, orchestration, database, scoring, workers, dashboard
GoHighLevel = contacts, inbox, email, SMS, calls, calendars, AI chat, Voice AI

That split is the right one because Replit supports always-on app hosting, scheduled jobs, secrets, and app config, while HighLevel’s API and AI stack cover contacts, conversations, webhooks, calendars, Voice AI, and Conversation AI.  ￼

2. Replit deployment model

Use two deployment types:

A. Reserved VM deployment

Use this for the always-on app:
	•	API
	•	webhook receiver
	•	dashboard
	•	authenticated admin UI

Replit’s docs describe Reserved VM deployments as always-on cloud servers suited to apps that need steady availability.  ￼

B. Scheduled deployments

Use these for recurring jobs:
	•	lead-finder sweeps
	•	enrichment queue
	•	orchestration sweep every 5 minutes
	•	daily recap jobs
	•	stale-lead retry jobs
	•	nurture/reactivation jobs

Replit says Scheduled Deployments run a command on a schedule, then terminate, and are best for periodic tasks rather than continuous workers.  ￼

10. Orchestrator logic

Run orchestratorSweep every 5 minutes through a Scheduled Deployment. Replit scheduled jobs are designed for exactly this kind of periodic command execution.  ￼

Pseudo-code:

for each lead where next_action_at <= now():
  load merchant
  load contact
  load lead_state
  load latest lead_events
  load compliance_state

  if compliance blocks action:
    set next_action_type = "manual_review"
    set status_reason = "compliance_block"
    log event
    continue

  action = decideNextAction(lead)

  switch action.type:
    case "enrich":
      run enrichment
    case "qualify":
      run scoring
    case "send_email":
      push to GHL workflow or conversation
    case "send_sms":
      push to GHL workflow or conversation
    case "trigger_call":
      trigger GHL Voice AI path
    case "offer_booking":
      send booking prompt through GHL
    case "request_statement":
      send statement CTA
    case "move_nurture":
      update state and schedule future touch
    case "handoff_human":
      add GHL tag + note + assign owner

  write lead_events
  update lead_state

11. Lead advancement rules

Use these first-pass rules.

DISCOVERED

Next:
	•	enrich
	•	dedupe
	•	classify

ENRICHED / DEDUPED / CLASSIFIED

Next:
	•	score lead
	•	assign vertical
	•	assign priority

QUALIFIED

If email exists and email allowed:
	•	start email

If no email but SMS allowed:
	•	start SMS

If neither but callable:
	•	queue AI call

If low quality:
	•	move nurture

OUTREACH_EMAIL

If reply:
	•	move ENGAGED

If no reply after 3 attempts and SMS allowed:
	•	move OUTREACH_SMS

If open but no reply:
	•	send stronger CTA

OUTREACH_SMS

If reply:
	•	move ENGAGED

If no reply after 2 attempts and call allowed:
	•	move OUTREACH_CALL

OUTREACH_CALL

If interested or booked:
	•	move ENGAGED or MEETING_SET

If no answer 3 times:
	•	move NURTURE

ENGAGED

Classify intent:
	•	send_info
	•	pricing_question
	•	call_me
	•	later
	•	stop
	•	statement_ready
	•	book_meeting

MEETING_SET

Pause outreach.
Start reminders.

STATEMENT_REQUESTED

Send upload link.
Follow reminders.
If upload received:
	•	move STATEMENT_RECEIVED

PROPOSAL_SENT

If viewed:
	•	SMS or call follow-up
If not viewed:
	•	resend email with alternate subject after delay

12. Qualification model

Score every lead on four dimensions.

Fit score

Signals:
	•	vertical
	•	website quality
	•	business maturity
	•	contact quality
	•	consumer-facing model

Revenue score

Signals:
	•	number of locations
	•	likely ticket size
	•	service type
	•	recurring billing hints
	•	booking or ecommerce hints

Reachability score

Signals:
	•	direct email
	•	mobile phone
	•	web form
	•	business responsiveness
	•	owner/contact confidence

Priority score

Start with:

priority = fit_score + revenue_score + reachability_score

Then bucket:
	•	80–100 = A
	•	60–79 = B
	•	40–59 = C
	•	under 40 = nurture/dead

13. Reply intelligence

Every inbound message from GHL should be classified immediately.

Use these intent labels:

interested
send_info
pricing_question
call_me
later
not_interested
already_have_provider
wrong_person
stop
angry
booked
sent_statement

Map them like this:
	•	interested → booking CTA or statement CTA
	•	send_info → short value message + upload link
	•	pricing_question → explain review process, do not blast generic rates
	•	call_me → send booking link or schedule call
	•	later → snooze 30 days
	•	stop → immediate suppression
	•	sent_statement → validate and advance

16. Compliance engine

This should live in Replit before any send or call.

Check before SMS:
	•	consent present
	•	no STOP history
	•	no complaint block
	•	within quiet hours
	•	within daily attempt limit

Check before calls:
	•	callable number
	•	no DNC block
	•	within timezone/business hours
	•	within call attempt limit

Check before email:
	•	not unsubscribed
	•	not bounced
	•	under daily limit

For HighLevel’s U.S. SMS setup, A2P and consent handling are central requirements, and official guidance says consent cannot be forced as a condition of form submission.  ￼
