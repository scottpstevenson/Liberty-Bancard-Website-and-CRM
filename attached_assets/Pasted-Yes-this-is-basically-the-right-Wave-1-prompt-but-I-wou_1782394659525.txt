What I would fix before sending it

1. Do not say “every call writes an audit log”

Your prompt says:

write audit log on every call

But later says:

dry-run mode without writing an audit log

That is a contradiction.

Better:

Every enforcement-mode evaluation writes an audit log. Dry-run/read-only evaluations do not write outreach audit logs.

Otherwise, simply opening a contact detail page could pollute the compliance audit log.

⸻

2. Be careful with consentTier auto-derivation

This line is risky:

derive tier from existing consentSms, emailOptInAt, doNotContact, doNotAutoContact fields

Email opt-in does not equal PEWC for automated SMS/AI voice/ringless voicemail.

So the backfill must be conservative:

* doNotContact = true → do_not_contact
* global opt-out / unsubscribe → opted_out
* verified PEWC evidence exists → pewc_full_automation
* inbound form but no PEWC → warm_no_pewc
* scraped/imported/unknown → cold_no_consent

Do not upgrade old contacts to pewc_full_automation just because consentSms is true unless that field is proven to represent actual PEWC with evidence.

⸻

3. “Advance enrollment to next eligible step” is dangerous

This line should be changed:

on blocked result, write audit log and advance enrollment to next eligible step

That could accidentally skip a blocked SMS step and move into a ringless voicemail or AI voice step.

Better:

On blocked result, mark the step as blocked with reason. Only advance to a next step if that next step is independently evaluated and allowed. If no allowed step exists, pause the enrollment and create a manual review/manual call task.

571A — Wave 1A: Lifecycle Source of Truth + Backend Contactability Engine

Required Skills

* backend-architecture
* fullstack-js

What & Why

Every automated outreach decision in the Liberty Bancard platform must pass through one canonical backend permission gate before execution.

Currently, checkBeforeSend() in the SDR compliance engine covers the outbound SDR path only. It does not universally enforce doNotAutoContact, does not have canonical phoneType for phone-channel risk decisions, does not have canonical timezone for quiet hours, does not have canonical consentTier or lifecycleStage fields on contacts, and does not create one reusable permission verdict that other workers, routes, AI agents, or GHL sync can rely on.

This task creates the backend source of truth for lifecycle stage, consent tier, and channel eligibility.

This is not a dashboard rebuild. This is the backend rule engine that future admin dashboards, Channel Safety views, GHL sync, SDR sequences, AI agents, and automation workers must read from.

⸻

Core Principle

Replit owns contactability truth.

GHL may later execute workflows, but GHL must not be the source of truth for whether SMS, AI voice, ringless voicemail, email, or manual call tasks are allowed.

Required Evaluation Order

The function must evaluate in this order:

1. Contact exists
2. doNotContact
3. doNotAutoContact
4. global opt-out / suppression
5. channel-specific opt-out
6. internal DNC
7. consentTier
8. lifecycle stage restrictions, if any
9. email status for email
10. phone validity / phoneType for phone-based channels
11. SMS consent status for SMS
12. PEWC requirement for SMS, AI voice, and ringless voicemail
13. feature flag for requested channel
14. timezone / quiet hours
15. Florida-specific telephone solicitation risk rule
16. rate limits / sender limits
17. final allowed/blocked verdict

Hard rule:

* sms requires consentTier = pewc_full_automation.
* voice_ai requires consentTier = pewc_full_automation.
* ringless_vm requires consentTier = pewc_full_automation.
* doNotContact, doNotAutoContact, opted-out, and DNC states must block risky automation.
* Feature flags may make channels more restrictive, but must not override hard compliance blocks.
