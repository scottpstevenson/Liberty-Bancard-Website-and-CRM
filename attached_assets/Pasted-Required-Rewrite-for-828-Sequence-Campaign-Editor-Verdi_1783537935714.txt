828A — Shared Email Preview + Safe Body Editor

What & Why

Sequences and Campaigns currently expose stored HTML as raw tag soup. Add a safe write/preview editing experience and a shared preview modal without changing send logic, sequence activation, enrollment, compliance, or GHL sync.

Done Looks Like

* Sequence email/SMS body fields no longer default to unreadable raw HTML-only display.
* Body editor has either:
    * Write / Preview tabs, or
    * a minimal rich-text editor if already available in the project.
* Every step card has a Preview button.
* Preview renders sanitized HTML with sample merge-tag values.
* Preview clearly reflects the real send composition path.
* No real sends occur.

Critical Preview Accuracy Rule

Do not show branding, logos, CTAs, or footers in preview unless they are actually part of what the recipient will receive.

Allowed:

Render stored body HTML
Render sample signature/footer preview clearly labeled as preview-only
Render compliance footer stub without real unsubscribe token

Not allowed:

Preview shows Liberty logo/header while actual email does not
Preview generates real unsubscribe links client-side
Preview lets users remove the send-time compliance footer
Preview bakes CAN-SPAM footer into editable body content

Security Guard

Do not render unsanitized HTML directly.

If using dangerouslySetInnerHTML, sanitize first with an existing sanitizer if available. If no sanitizer exists, use a constrained renderer or sandboxed preview approach.

Kill line:

STOP if untrusted/stored HTML can execute scripts in the dashboard preview.

Merge Tag Preview

Use sample values:

{{firstName}} → Alex
{{companyName}} → Your Business
{{businessName}} → Your Business
{{bookingLink}} → https://calendly.com/liberty-bancard/intro

Escape sample values before insertion.

Do Not Change

sequence send logic
GHL send logic
unsubscribe/footer injection
contactability
daily cap
global kill switch
sequence activation policy
GHL workflow sync

⸻

828B — Campaign Step Editing Persistence

What & Why

Campaign steps are currently effectively read-only. Add edit support for campaign step subject/body/delay using the same safe editor/preview pattern from 828A.

Done Looks Like

* Campaign step cards have Edit and Preview actions.
* Edit opens inline form or modal.
* Subject, body, and delay can be edited.
* Save persists.
* Reload confirms persistence.
* No campaign send is triggered.
* No GHL workflow is created or modified.

API Guard

Before building UI, verify the campaign step update endpoint exists.

If it does not exist, add a minimal role-guarded update endpoint only for:

subject
body
delay

Do not add send, activate, enroll, or sync behavior.

Role Guard

Only roles already allowed to manage campaigns/sequences can edit.

Kill line:

STOP if agents gain new campaign/template editing permissions unintentionally.

Copy Rules

Allowed value props:

Not allowed:

pressure tactics
misleading subject lines

Each email should include:

proper HTML formatting

Branding Rule

Choose one source of truth for the Liberty logo/header:

Option A: stored template body includes logo/header
Option B: actual send-time wrapper includes logo/header

Do not do both.

Do not make preview show a logo if the real sent email does not include it.

Compliance Rule

Do not place unsubscribe links or physical address directly into editable template bodies.

Cold email compliance remains injected at send time by the #791 footer path.

Kill line:
