# LIBERTY BANCARD — PREFLIGHT + BUILD MODE

## MODE

PREFLIGHT + BUILD. Verify current ownership, correct the task and implement directly when safe. Do not stop at a plan unless the finding is false, canonical ownership differs materially, prerequisites are absent, evidence is required for a dangerous backfill, scope must split, or a kill line is reached. Do not create competing contact/business writers, use `db push`, weaken tests or backfill unverifiable provenance.

Required sequence: baseline → VFC → targeted searches → verified root cause → ownership → blast radius → data/auth/concurrency/external checks → verdict → corrected plan → kill lines → build → tests/gates → post-build searches → diff → final VFC → merge verdict.

- One canonical contact writer and one organization authority.

- Imports must be idempotent and fully reconcilable.

- No `db push` or inferred backfill.

**Primary findings:** `DAT-04`, `DAT-05`, `DAT-12`, `DAT-15`

- All production contact/prospect creation uses one batch-capable canonical command.
- Each source has an explicit prospect-first or direct-contact policy.
- Entity, classification, source event, primary pointer, import execution and row disposition are atomic where locally possible.
- Every import row resolves to inserted, updated, skipped, conflicted or failed exactly once.
- Historical backfill is conservative and records `legacy_unknown` when evidence is absent.
- `businesses` is the canonical organization authority with aliases/locations and explicit compatibility projections.
- No direct writer bypass remains.

### Out of Scope

- Contact merge logic, provider arbitration, navigation redesign and outbound activation.
- Destructive historical organization cleanup without a separately approved data plan.

### Proposed Implementation Steps

1. Inventory writers, imports, provenance and organization consumers.
2. Confirm/extend canonical command and source policy.
3. Add next migrations for lineage/accounting/organization compatibility.
4. Migrate callers and enforce atomic dispositions.
5. Add deterministic import reconciliation and conflict handling.
6. Promote canonical business projections and migrate consumers.
7. Add bounded backfill tooling and production-path tests.

- `shared/schema.ts`, migrations/journal
- contact/prospect/business storage and services
- CSV, registry, SDR, discovery, enrichment, form and GHL ingestion
- source-event, primary-pointer and import-execution owners
