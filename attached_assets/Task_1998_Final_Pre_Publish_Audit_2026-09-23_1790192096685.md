## Consolidated findings

### P1 01 Original verification contract was replaced

The corrected plan required the original VFC-01 through VFC-20 to be embedded verbatim and individually reported. `scripts/test-sfp-disposable-certification.ts` instead reuses the same IDs for a different matrix. For example, its VFC-13 tests a partial void transition, while original VFC-13 requires a genuinely concurrent same-key freeze. Its VFC-20 is a tautological `check(true, ...)`, not an executable original VFC-20 report-status test. This makes “71/71 across all 20 checks” true only for the replacement matrix, not for the accepted task contract.

**Required correction:** restore the original VFC matrix verbatim as the authoritative IDs. Keep the added classifier/geography tests under new non-conflicting IDs. Every original VFC must have a real test or explicit evidence path and PASS or FAIL result.

### P1 02 Same-key freeze concurrency is not correct or tested

`freezeCohortTx` sets `REPEATABLE READ` and then obtains `pg_advisory_xact_lock` before reading the idempotency row. In PostgreSQL, the lock query establishes the repeatable-read snapshot. A second caller can wait for the first caller while retaining a snapshot that predates the first commit; after acquiring the lock it cannot reliably observe the winner and return the original run. The disposable suite contains no concurrent `Promise.all` same-key freeze test.

**Required correction:** redesign claim serialization so the waiting caller starts its authoritative repeatable-read snapshot only after ownership is settled, or implement bounded retry on serialization/unique-conflict using a fresh transaction that reads the winner. Add a real two-connection concurrent test proving exactly one newly frozen run, one replay response, one run row, one member set, one decision set, and no generic 500 or failed-row downgrade.

### P1 03 Frozen evidence is still mutable at the database boundary

The member and decision triggers are `BEFORE UPDATE OR DELETE`, not `INSERT`, so direct SQL can append rows to a frozen run. The shared trigger function resolves `COALESCE(OLD.cohort_run_id, NEW.cohort_run_id)`, which checks the old run first and can permit moving a row from a mutable run into a frozen destination. `sfp_funnel_snapshots`, now the reconciliation record of authority, has no frozen-run immutability trigger. The run trigger does not protect every frozen request/identity field such as `request_payload`, `release_sha`, and `actor_id`.

**Required correction:** guard INSERT, UPDATE, and DELETE for members, decisions, and funnel snapshots; reject writes when either source or destination run is frozen, voided, or superseded; protect the complete frozen run manifest and provenance; and add direct-SQL negative tests for post-freeze insert, update, reassignment, and delete.

### P1 04 Suppression and bounce handling does not satisfy the subject-aware contract

The selector labels scope from whether a sampled row has an email, not from the authority and scope of the rule that fired. A contact-level `do_not_auto_contact` can therefore be persisted as email-scoped. Only one representative subject is stored although the business exclusion is derived from all contacts. The decision schema does not persist the required suppression authority or evidence reference, and reason is only embedded in a general disposition string. Most importantly, the code terminally excludes a business when all currently known non-null emails are bounced or invalid, even though free discovery may find another address and contacts with no email may remain. That is not deterministic proof that no usable candidate can remain.

**Required correction:** model and persist rule-derived scope, subject ID or normalized hash, authority, reason, and evidence reference for every affected subject. Use a child evidence table or equivalent normalized structure when multiple subjects support one business decision. Only exclude the business for an authoritative business-wide rule or a proven no-usable-subject condition. Otherwise retain the business for discovery or route it to review while excluding only the affected contact or candidate. Add mixed-contact, null-email, all-current-email-bounced, unknown-scope, and business-wide-authority tests.

### P1 05 Migration and Drizzle schema do not agree and the database cap is absent

Migration 0282 adds five `sfp_cohort_runs` columns: `source_snapshot_hash`, `source_high_water_business_id`, `source_business_count`, `source_txid`, and `source_snapshot_captured_at`. `shared/schema.ts` declares none of them even though its own comment states production schema is also governed through the Drizzle declaration. The journal entry exists and the Replit deploy command runs `npm run db:migrate`, so this is not a claim that 0282 is unjournaled; it is a verified SQL/model parity defect and future schema-push drift risk. The required database constraint enforcing `sfp_programs.max_cohort_size BETWEEN 1 AND 100` is also absent.

**Required correction:** add all five columns to `sfpCohortRuns`, add the 1-to-100 check constraint to migration and Drizzle schema, and add a schema-parity test against a disposable migrated database. Verify fresh apply, upgrade apply, and apply twice.

### P1 06 Preview and read-only route boundaries are incomplete

`GET /api/lead-ops/sfp/runs` calls `listCohortRuns`, which calls `ensureProgram()` and can create a program row during a GET. The funnel preview accepts an arbitrary numeric `maxPreview` without the required 1-to-100 route and service enforcement. The freeze route validates the bound, but the preview path does not.

**Required correction:** make every SFP GET path mutation-free, including run listing; return an empty list or explicit not-configured response without creating data. Validate `maxPreview` as an integer from 1 through 100 in both route and service. Add no-write GET tests and preview boundary tests for 0, 1, 100, 101, negative, fractional, NaN, and omitted values.

### P1 07 Void and supersede operations are not fully atomic

`voidCohortRun` and `supersedeCohortRun` read, mutate, and write the audit record in separate statements without one transaction. A failed audit insert can leave lifecycle state changed without its audit receipt. Supersede does not reject self-supersession and does not lock and revalidate the replacement through the original update, so a concurrent void of the replacement can leave a run pointing at a replacement that is no longer usable.

**Required correction:** perform lifecycle validation, row locks, conditional state transition, and audit receipt in one transaction. Reject self-supersession, require same-program replacement, and revalidate replacement frozen/non-voided/non-superseded at mutation time. Add race, rollback, and self-reference tests.

### P2 01 Public snapshot identity is incomplete

The service persists `source_txid`, but `SfpCohortRun` and `_mapRun` omit it. The certification calls the public snapshot surface complete without checking this field.

**Required correction:** expose `sourceTxid` consistently in the service type, mapper, API response typing, UI diagnostics if displayed, and certification.

### P2 02 Test execution evidence is incomplete

The disposable suite is registered, but ordinary pre-deploy runs mark disposable suites `delegated_unverified` when `TEST_DATABASE_URL` is unavailable. No GitHub status or workflow run exists for the audited SHA. This audit could run the dependency-free SFP suite, but dependency installation repeatedly failed on Replit's package firewall with HTTP 502 for `pg-protocol`, so TSC, migration-integrity, manifest, UI, and disposable-Postgres commands could not be independently rerun here. This is not a code failure, but the claimed pass remains unverified.

**Required correction:** after the code corrections, run the original VFC suite in deterministic-integration CI with a freshly provisioned disposable PostgreSQL database, retain raw logs/artifacts tied to the final SHA, and make a delegated/unverified mandatory suite fail the release gate rather than appear as a local success.
