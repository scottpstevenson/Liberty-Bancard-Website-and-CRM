Endpoint shape

Extend:

GET /api/admin/pipeline/stage-health

Add:

breakdownByVertical: Array<{
  vertical: string | null;
  label: string;
  totalDeals: number;
  enrolled: number;
  noActiveEnrollment: number;
  noSequenceMapped: number;
  noEmail: number;
  dncBlocked: number;
  optedOutBlocked?: number;
  suppressed?: number;
  contactabilityBlocked?: number;
  mappedSequenceId?: number | null;
  mappedSequenceName?: string | null;
}>

Include Unknown / Uncategorized for null/empty verticals. Do not drop them.

Counting rules

For each New Lead deal with a linked contact:

totalDeals = all New Lead deals in that vertical
enrolled = has active/completed relevant sequence enrollment
noActiveEnrollment = totalDeals - enrolled
noSequenceMapped = no eligible/default sequence mapping exists
noEmail = no usable real email for email sequence
dncBlocked = do_not_contact / DNC blocked
optedOutBlocked = opted out / unsubscribed
suppressed = auto-enrollment suppressed from #859, if available

A deal can appear in more than one reason bucket if that matches current diagnostic logic, but totalDeals, enrolled, and noActiveEnrollment must remain clearly reconciled.

Mapping editor guard

The vertical → sequence mapping editor may pre-populate rows from breakdownByVertical, but saving mappings must continue to use the existing policy/settings path.

Allowed:

display current mapped sequence
show missing mapping warning
let admin choose a sequence for that vertical
save mapping through existing New Lead enrollment policy endpoint/settings

Not allowed:

auto-create mappings without admin confirmation
auto-enroll contacts when a mapping is selected
activate sequences
modify sequence triggerType
