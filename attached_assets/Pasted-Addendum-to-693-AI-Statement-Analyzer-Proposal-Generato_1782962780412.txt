Addendum to #693 — AI Statement Analyzer + Proposal Generator

Approved directionally, but do not build the current version until these corrections are applied.

1. Confirm real file access inside Step 5

Before wiring analyzeStatement, confirm what the BullMQ analysis worker receives:

* dealId
* documentId
* uploaded file path
* file URL
* file buffer
* mime type

Do not assume fileBuffer is available.

Correct design:

analysis worker receives dealId/documentId
→ loads document metadata
→ resolves local file path or storage URL
→ reads the file only for analysis
→ releases buffer after extraction

Kill line:

STOP if `analyzeStatement(dealId, fileBuffer, mimeType)` is called with a fake, unavailable, or stale buffer.

⸻

2. OpenAI extracts; server calculates

OpenAI should extract raw statement fields only.

Server-side code must calculate:

effectiveRate = totalFees / monthlyVolume
libertyEstimatedFees = monthlyVolume * configuredTargetRate
estimatedSavingsMonthly = totalFees - libertyEstimatedFees
estimatedSavingsAnnual = estimatedSavingsMonthly * 12

Do not let OpenAI invent math.

Kill line:

STOP if effective rate or savings math is accepted from AI without deterministic server-side recalculation.

⸻

3. Do not hard-code 1.85% as a universal promise

Do not hard-code:

1.85% flat

inside the analyzer as a guaranteed Liberty rate.

Use a clearly named config value, for example:

LIBERTY_TARGET_EFFECTIVE_RATE_BPS

If unset, use a safe default only in TEST_MODE.

All UI/proposal language must say:

estimated
draft
rep review required
based on extracted statement data

If savings are zero or negative, show:

No clear savings detected from the extracted statement.

Kill line:

STOP if the proposal promises guaranteed savings or presents the estimated rate as a final approved offer.

⸻

4. Add strict JSON schema validation

Create a StatementAnalysisExtractionSchema using Zod or the existing validation pattern.

Required flow:

AI response
→ parse JSON
→ validate schema
→ normalize numbers
→ calculate derived fields
→ persist analysis

If parsing or validation fails:

analysisStatus = failed
audit log written
worker continues

Kill line:

STOP if prose, malformed JSON, or partial AI output can be stored as completed analysis.

⸻

5. Use existing proposal storage if present

Before adding proposal fields to deals.analysisData, inspect the existing statement proposal schema:

shared/schema.ts:4002–4028

Preferred ownership:

deals.analysisData = structured fee extraction + computed metrics
statement_proposals = draft proposal HTML / proposal snapshot / rep-facing draft

Do not create duplicate proposal storage if an existing proposal table already fits.

Kill line:

STOP if this task creates duplicate proposal storage while an existing statement proposal table can own the draft.

⸻

6. Keep generateDealBlueprint

Do not replace the existing blueprint step.

Correct sequence:

statement uploaded
→ document row exists
→ deal.analysisStatus = pending
→ BullMQ analysis job
→ generateDealBlueprint keeps running
→ analyzeStatement runs as an additional structured analysis step
→ deal.analysisStatus = complete only after required analysis succeeds

If structured analysis fails, mark structured analysis failed and write audit log without killing the entire worker.

Kill line:

STOP if generateDealBlueprint is removed or replaced instead of extended.

⸻

7. Proposal must be draft-only

The analyzer may create a proposal draft attached to the deal.

It must not:

* send email
* send SMS
* enroll a sequence
* trigger GHL workflow
* auto-send a proposal
* mark proposal as approved

Proposal status should be:

draft

with:

requiresRepReview = true

Kill line:

STOP if proposal generation causes outbound communication or creates an approved/final proposal.

⸻

8. Smoke tests must not call live OpenAI

scripts/test-statement-analyzer.ts must run in fixture mode.

Allowed:

SKIP_AI=true
TEST_MODE=true
mock extractor response
synthetic text buffer

Not allowed:

live GPT-4o vision call
real merchant statement
external PDF fetch

Kill line:

STOP if statement analyzer tests require live OpenAI or external files.

⸻

Build:

1. server/services/statement-analyzer.ts

3. Deterministic server-side fee/savings math

* hard-code guaranteed savings
* trust AI math
* store malformed AI output as complete
* require live OpenAI in tests
