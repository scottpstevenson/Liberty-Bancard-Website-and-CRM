829 — Vertical Bulk Enrollment for Sequences

What & Why

The “Enroll Contact in Sequence” dialog currently only supports searching for one contact at a time. Reps need a safe way to enroll all eligible contacts in a canonical vertical, such as all Salon/Spa contacts into the SDR-10 sequence, without bypassing the existing enrollment gates.

Bulk enrollment must use the same per-contact safety checks as single enrollment. It must not directly batch-insert enrollments.

Confirmed Implementation Facts

* Single enrollment route lives in server/routes/campaigns.ts:
    * POST /api/sequence-enrollments
* Existing single-enrollment gates:
    * sequence must be status === "active"
    * canEnrollContactInSequence(contactId, seq) must pass
    * worker still enforces global pause, daily cap, bounce guard, and full contactability at execution time
* Existing enroll dialog is in:
    * client/src/pages/dashboard/Sequences.tsx, dialog around line 1158
    * existing enrollMutation around lines 270–291
* Canonical vertical source:
    * server/services/sdr/lead-finder.ts
    * normalizeDiscoveryVertical()
* Bulk endpoint belongs in:
    * server/routes/campaigns.ts
* Do not add this to server/routes/sequences.ts.

Done Looks Like

* Enroll dialog has two modes:
    * Single Contact
    * By Vertical
* By Vertical mode shows:
    * canonical vertical dropdown
    * matching contact count
    * first 5 preview contacts
    * eligibility/skipped breakdown
    * explicit confirmation step
* Bulk enrollment queues/enrolls only contacts that pass the same gates as single enrollment.
* Paused/inactive sequences reject bulk enrollment before any DB write.
* Running the same bulk action twice does not create duplicate enrollments.
* Result toast/report shows:
    * queued
    * skipped already enrolled
    * skipped not eligible/contactability/DNC/opt-out
    * skipped missing contact info if applicable
* No sequence is activated.
* No email/SMS/voice/ringless/GHL send is triggered.
* No sequence worker/contactability/GHL/compliance logic is changed.

Critical Enrollment Rule

Do not direct batch-insert enrollments.

Bulk enrollment must either:

call the same shared per-contact enrollment helper used by POST /api/sequence-enrollments

or extract the single-route logic into a shared function and call it for each contact.

Required per-contact gates:

1. Load sequence.
2. Reject if sequence.status !== "active".
3. Check existing active/completed enrollment for same contact + sequence.
4. Call canEnrollContactInSequence(contactId, seq).
5. Only then create enrollment.

Do not call storage.createSequenceEnrollment() until the above gates pass.
