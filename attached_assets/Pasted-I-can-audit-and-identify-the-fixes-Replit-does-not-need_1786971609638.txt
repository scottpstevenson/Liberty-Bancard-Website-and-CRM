## 4. Predeploy wrapper must also be repaired

The transcript shows the new server failed with:

```text
EADDRINUSE: address already in use 0.0.0.0:5000
```

But the wrapper saw the already-running server’s health endpoint and continued. That means the gate may have tested an older, unowned process.

Update `scripts/run-pre-deploy.sh` to:

* fail before startup if port 5000 is already occupied
* permit reuse only through an explicit opt-in
* verify the running server’s reported SHA equals `RELEASE_SHA`
* verify the newly started PID remains alive after health becomes ready
* terminate only the process the wrapper started
