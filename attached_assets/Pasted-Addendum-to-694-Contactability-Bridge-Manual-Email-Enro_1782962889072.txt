Addendum to #694 — Contactability Bridge + Manual Email Enrollment

Approved directionally, but do not build until these corrections are applied.

1. Use sdrLeadState.contactId, not contacts.sdrSourceId

Do not add or rely on:

contacts.sdrSourceId
sdr_source_id

The existing SDR → CRM attribution is:

sdrLeadState.contactId = contacts.id

An SDR-sourced contact is any contact with a related sdrLeadState row by contactId.

Kill line:

STOP if this task adds `contacts.sdrSourceId` or relies on a non-existent `sdrSourceId` field.

Update grep checks accordingly:

grep -n "sdrLeadState\|contactId" server/routes/sequences.ts server/routes/contacts.ts

⸻

2. Insert the gate into the canonical enrollment path

Do not create a raw parallel enrollment path that directly calls:

storage.createSequenceEnrollment(contactId, sequenceId)

unless that is already the canonical enrollment method and includes duplicate checks, schedule setup, audit behavior, and sequence eligibility.

Preferred implementation:

manual route
→ load contact
→ detect SDR-sourced via sdrLeadState.contactId
→ require confirmed === true
→ verify selected sequence is email-only
→ evaluateContactability({ channel: "email", mode: "enforcement" })
→ canEnrollContactInSequence(...)
→ existing canonical enrollment service/path

Kill line:

STOP if the new SDR enrollment route bypasses the existing canonical sequence enrollment logic.

⸻

3. Email-only means every outbound sequence step is email

For SDR-sourced contacts, SMS, voice, and ringless must be blocked regardless of contact flags.

Do not infer email-only from the sequence name.

Allowed:

sequence has explicit channel = "email"

or:

all sequence steps/templates are email-only

If the route cannot prove a sequence is email-only, block it.

Kill line:

STOP if an SDR contact can be enrolled into a sequence containing SMS, voice, ringless, task-call, or voicemail steps.

⸻

4. Require explicit manual confirmation server-side

The route must require:

confirmed === true

validated server-side, not just in UI.

If missing:

400 Explicit confirmation required

Kill line:

STOP if an SDR contact can be enrolled without explicit confirmed:true in the request body.

⸻

5. Full contactability gate before enrollment

Before enrolling any SDR-sourced contact, call the full contactability engine:

evaluateContactability({
  contactId,
  channel: "email",
  mode: "enforcement",
  campaignType: "sdr_outreach"
})

First verify the actual function signature and result shape in server/services/contactability.ts; do not invent field names.

If blocked:

* write audit log first
* return 403
* do not enroll

Kill line:

STOP if a blocked contactability result returns 403 without first writing an audit log.

⸻

6. Prevent duplicate active enrollments

Before enrolling, check whether the contact is already actively enrolled in the selected sequence.

If already enrolled, return a clear response:

{ alreadyEnrolled: true }

or a 409.

Kill line:

STOP if repeated button clicks can create duplicate active sequence enrollments.

⸻

7. Status endpoint must be read-only

Add or reuse:

GET /api/contacts/:id/contactability-status

This route may call the contactability engine in advisory/dry-run mode if supported.

It must not:

* enroll
* mutate contact state
* create tasks
* create audit noise except optional read audit if already standard

Kill line:

STOP if loading ContactDetail mutates compliance/enrollment state.

⸻

8. UI belongs in Sales Prep / ContactDetail, but must be hidden when blocked

For SDR-sourced contacts:

* show Outreach Eligibility card
* show allowed/blocked badge
* show reason
* show email-only sequence dropdown only when allowed
* require confirmation dialog before POST

For non-SDR contacts:

* do not show SDR manual enrollment UI unless existing non-SDR enrollment UI already supports it

⸻

9. Tests must use stable blocked fixtures

Do not rely only on quiet-hours tests because they can be time-sensitive.

Use deterministic blocked cases:

* DNC
* opted out
* doNotContact
* PEWC restricted if fixture exists

Quiet-hours may be tested with a mocked clock only.

⸻

Corrected build scope

Build:

1. SDR-sourced detection via sdrLeadState.contactId.
2. Manual confirmed email-only enrollment route or extension of canonical route.
3. Full evaluateContactability enforcement before enrollment.
4. Block SMS/voice/ringless sequences for SDR contacts.
5. Audit log on blocked enrollment.
6. Duplicate enrollment protection.
7. Read-only contactability status endpoint.
8. ContactDetail/Sales Prep outreach eligibility UI.
9. Smoke tests for blocked, allowed, no-confirmation, non-email sequence, duplicate enrollment.

Do not:

* add contacts.sdrSourceId
* enable SMS
* enable voice
* enable ringless
* auto-enroll on promotion
* bypass canonical enrollment logic
* enroll without confirmed:true
