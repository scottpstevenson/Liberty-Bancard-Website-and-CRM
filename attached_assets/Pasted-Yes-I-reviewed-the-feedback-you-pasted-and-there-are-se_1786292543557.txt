5. Migration should be strangler-pattern, not rip-and-replace
For Replit best practice, I would avoid deleting old architecture immediately.
Use this pattern:
Phase 1 — Observe
New path exists but old path remains active.
Phase 2 — Shadow
New service calculates what it would do but does not execute.
Compare outputs.
Phase 3 — Limited cohort
5–10% or internal/test entities use new path.
Phase 4 — Majority
Increase traffic after metrics validate.
Phase 5 — Disable legacy
Old architecture becomes inactive.
Phase 6 — Remove
Only remove old code after a defined stability period.
