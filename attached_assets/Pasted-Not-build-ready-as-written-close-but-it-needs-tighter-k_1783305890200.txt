Final Addendum to #752 — Import & Enrichment Pipeline Bugs

Approved to build only with these scope guards.

This task is a reliability/data-integrity fix, not a redesign.

Core rule

For every import attempt:

totalRows = createdCount + duplicateCount + invalidCount + skippedCount

There must be no invisible dropped rows.

If the current schema does not separately support invalidCount / skippedCount, add the smallest safe persistence change needed, or store the breakdown in the existing import metadata JSON if available.

Do not fake reconciliation by forcing bad rows into the CRM.

⸻

Part A — Import reconciliation and Outscraper-shaped files

Required behavior

A realistic Outscraper-style file with columns like:

Name
Telephone
Category
Rating
Address
Website
Email

must import usable rows when they have at least enough identity/contact data to pass the existing lead validation rules.

The import result and import history must show:

total rows
new rows
duplicate rows
invalid rows
skipped rows, if applicable

Required debugging

Before changing validation, trace where the valid Outscraper rows disappear:

header normalization

summary aggregation
import history persistence

Fix the exact stage that is dropping rows.

Kill lines

STOP if the fix only changes displayed counts while valid Outscraper rows still do not import.
STOP if invalid rows are force-inserted just to improve the success rate.
STOP if existing email/phone/company dedupe rules are changed.
STOP if the importer silently drops rows without classifying them as created, duplicate, invalid, or skipped.
STOP if import history still cannot explain every row in the uploaded file.

Part B — Sunbiz enrichment batch failure isolation

Required behavior

Batch enrichment must not 500 because one record has bad/missing enrichment data.

Each record should return one of:

success
partial_success
skipped
failed

A failed individual record should include a safe reason, for example:

missing_officers
no_matching_entity
invalid_business_name
sunbiz_lookup_failed
unexpected_parse_error

The batch response should still complete with a summary:

attempted
succeeded
partial
failed
skipped

Required hardening areas

Add defensive handling around:

empty or missing officers list
missing principal address
missing registered agent
unexpected Sunbiz result shape
single-record enrichment exceptions
batch loop exceptions

Kill lines

STOP if one bad Sunbiz record can still crash the whole batch with a 500.
STOP if failures are swallowed without being reported per record.
STOP if the enrichment service marks failed records as successfully enriched.
STOP if this task adds a new enrichment provider.
STOP if this task changes the UI layout instead of fixing backend reliability/reporting.
