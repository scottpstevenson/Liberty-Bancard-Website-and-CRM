Required Addendum to 680 — Homepage Section Rhythm Repair

Approve the direction, but apply these corrections before build.

⸻

Verdict

Proceed with #680 after this addendum is incorporated.

The task correctly identifies the real problem: the homepage has too many white / near-white sections, and the mobile hero proof stack reads like one continuous worksheet canvas.

However, five details must be tightened before implementation.

⸻

1. Phone row cannot remain faint inline text

The task says:

Phone number remains visible in the hero; "Compare My Current Setup" is hidden on mobile

That is acceptable only if the phone row is redesigned for legibility.

Current issue:

954-266-8214

is too light, too small, and reads like metadata.

Required:

* hide Compare on mobile
* keep phone only if it becomes clearly legible
* style it as a compact secondary action, not faint inline text

Acceptable mobile treatment:

Call 954-266-8214

with:

* darker text
* stronger icon contrast
* medium font weight
* enough spacing from the PDF note
* no low-contrast gray inline row

Kill line:

Stop if the phone number still appears as faint gray inline text on mobile.

⸻

2. Do not duplicate data-testid values when duplicating the audit card

The task says to duplicate the Statement Fee Audit card JSX into a new mobile-only sample review section.

This is safe only if duplicated data-testid values are avoided.

Important: CSS-hidden desktop/mobile elements still exist in the DOM. If the hero right-column audit card is hidden lg:flex, it is still in the DOM on mobile. A duplicated mobile audit card can create duplicate test IDs.

Required:

* either extract a local render helper/component that accepts a testIdPrefix
* or ensure the mobile duplicate uses unique test IDs
* or omit test IDs from the cloned internal rows if not needed

Use unique names like:

card-statement-audit-mobile
text-statement-audit-mobile-effective-rate
text-statement-audit-mobile-fixed-fees

Do not duplicate existing desktop audit-card test IDs.

Kill line:

Stop if mobile sample review creates duplicate data-testid values with the hidden desktop hero audit card.

⸻

3. Trust strip tint must be visibly different, not technically different

The plan changes trust strip to:

bg-primary/5 border-y border-primary/15

This may still be too subtle on real mobile screens.

Requirement:

The trust strip must visibly read as a band at 390px.

Start with:

bg-primary/5 border-y border-primary/15

but if screenshot still reads white, increase to one of:

bg-primary/10 border-y border-primary/20

or an equivalent light blue-tinted band that is clearly visible but still premium.

Kill line:

Stop if the trust strip still reads as the same white field as the hero/sample-review area.

⸻

4. Verify md:section-navy actually works

The plan uses:

bg-background border-y border-border md:bg-primary md:border-y-0 md:section-navy

If section-navy is a custom CSS class, the responsive variant md:section-navy may not compile depending on how Tailwind/custom classes are configured.

Required:

* visually verify desktop Choose Path is still dark navy
* if md:section-navy does not apply, use explicit responsive utility classes or a responsive wrapper
* do not rely on class names alone

Kill line:

Stop if desktop Choose Path loses its dark navy treatment.

⸻

5. “No adjacent same background” must be visual, not class-name-only

The validation says:

Zero consecutive sections sharing the same background treatment

This must be judged by screenshots, not just class names.

For example:

bg-background
bg-card
bg-primary/5
bg-background bg-dots
bg-background bg-grid

can technically be different but visually read as the same white section.

Required validation:

At 390px, confirm the visual rhythm reads as:

Hero clean white
→ sample review muted/warm block
→ trust band visible
→ pain warm
→ stats navy
→ services white
→ what-you-get warm
→ how-it-works white
→ calculator warm
→ choose-path white/bordered
→ verticals warm
→ why-liberty white
→ reviews warm
→ risk-reversal dark
→ FAQ warm
→ callback tinted
→ final CTA dark

Kill line:

Stop if any two adjacent sections visually blend together, even if their class names differ.

⸻

Approved Direction After Addendum

With these corrections, #680 is approved.

Do not expand scope into copy rewrites or content redesign.

Do not touch:

* hero H1/subheadline
* CTA destinations
* CTA tracking
* upload/booking flow
* StickyMobileCTA trigger logic
* Services section copy
* testimonials
* backend/API/GHL/analytics/forms

This is a section rhythm and mobile hero architecture task only.
