834 — Controlled Warm/Hot Deal Backfill + Future Orphan Prevention

What & Why

153,887 contacts were bulk-imported but only 967 have linked deals. Preflight confirmed the root cause: the CSV import pipeline only created deals for hot contacts with score ≥70. Warm contacts with scores 45–69 were silently skipped, even though the existing scoring model classifies them as pipeline-worthy.

This task adds a controlled admin deal-backfill system for orphan contacts and a gated future-orphan guard so newly scored/imported warm/hot contacts do not remain outside the Sales Pipeline.

This is a CRM deal-recovery task only.

It must not trigger outreach, sequence enrollment, GHL workflows, SMS, voice, ringless voicemail, or campaign sends.

Confirmed Facts

* Existing import deal creation path is server/routes/imports.ts:1793–1801.
* Existing import path calls storage.createDeal() only.
* Existing import path does not call autoEnrollFromTrigger().
* Existing import path only creates deals for tier === "hot".
* Existing richer mass-deal path is POST /api/contacts/mass-create-deals in server/routes/imports.ts:1157.
* Warm threshold is score ≥45.
* Hot threshold is score ≥70.
* Cold threshold is score ≥20.
* Scoring fields already exist on contacts: lead_score, last_scored_at.
* autoCreateDealsForWarmContacts does not exist yet and must be added as a system setting.
* server/routes/admin.ts is the correct home for new admin endpoints.
* server/routes/imports.ts should not be modified for this backfill.

Non-Negotiable Safety Rule

Do not call:

autoEnrollFromTrigger()

from this task.

Backfill creates missing deals only.

Forbidden side effects:

sequence enrollment
sequence activation
email send
SMS send

ringless voicemail

campaign send
outreach automation

Done Looks Like

* Admin can preview orphan-contact deal candidates before mutation.
* Admin can run a confirmed deal backfill after preview.
* Runs ≥100 eligible contacts require typed confirmation: CREATE DEALS.
* Backfill processes in resumable batches.
* Progress is persisted to the database after every batch.
* Warm contacts with score 45–69 can receive deals.
* Hot contacts with score ≥70 can receive deals.
* Cold contacts below 45 are skipped.
* Anonymous contacts are skipped.
* Placeholder-email-only contacts are skipped.
* Existing deals are skipped.
* Repeat runs create no duplicate deals.
* Admin can view current backfill status.
* Admin can cancel a running backfill.
* Future orphan prevention is gated by autoCreateDealsForWarmContacts, default false.
* Review-mode orchestrator records candidates only and does not mutate production data.
* No outreach is triggered.
