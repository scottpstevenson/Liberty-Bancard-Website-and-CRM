Final Addendum to #864 — Prevent CSV Import From Overwriting Opt-Out Status

Approved to build.

Core requirement

CSV import/upsert logic must preserve restrictive consent state.

If an existing contact is already opted out, unsubscribed, DNC, or email-suppressed, a new CSV row must not overwrite that contact back to subscribed/contactable.

Consent merge rule

Use monotonic consent merging:

most restrictive value wins

Allowed:

subscribed/contactable → opted_out
subscribed/contactable → do_not_contact
unknown → opted_out
unknown → do_not_contact

Not allowed:

opted_out → subscribed
unsubscribed → active
do_not_contact → false
optedOutEmail true → false
suppressed → unsuppressed

Fields protected

Protect all equivalent fields if present:

emailStatus
consentTier
optedOutEmail
doNotContact
do_not_contact
doNotAutoContact
emailOptOut / email_opt_out if present

Also preserve New Lead auto-enrollment suppression metadata from #859 if present.

Import behavior

When an import row matches an existing contact:

Existing contact already opted out

If existing contact has any restrictive value:

emailStatus = unsubscribed / opted_out / bounced if treated as non-contactable
consentTier = opted_out / do_not_contact
optedOutEmail = true
doNotContact = true

Then:

preserve existing restrictive fields
do not downgrade consent
count row as optOutPreserved
call suppressNewLeadAutoEnrollmentForContact(contactId, "csv_import_existing_opt_out_preserved")

CSV row says opted out

If the CSV itself contains opt-out/DNC/unsubscribe values, then the import may apply them:

set restrictive consent fields
call suppressNewLeadAutoEnrollmentForContact(contactId, "csv_import_opt_out")
count as optOutApplied

CSV row says subscribed/contactable

If existing contact is already opted out, ignore the CSV’s less-restrictive value.

Count as:

optOutPreserved

Import summary

Add a new visible summary counter:

optOutPreserved

Recommended summary fields:

created
updated
duplicates
invalid
skipped
optOutApplied
optOutPreserved

If the existing summary only supports limited fields, add optOutPreserved without breaking the existing total reconciliation.

Required reconciliation:

totalRows = created + updated + duplicateRows + invalidRows + skippedRows

If optOutPreserved is a sub-count of updated, label it clearly as such:

Updated: 500
Opt-out preserved: 12 of updated rows

Do not double-count it as a separate top-level row outcome unless the whole import accounting is updated accordingly.

Suppression hook

Use:

suppressNewLeadAutoEnrollmentForContact(contactId, reason)

Call it when:

existing opt-out is detected and preserved
CSV row applies a new opt-out
CSV row applies DNC/do-not-contact

Do not call it for every imported row.

Files / locations

Find the actual universal CSV import upsert path. It may be in:

server/services/csv-import.ts
server/routes/imports.ts
server/routes/contacts.ts
server/services/imports/*

Patch the central merge/upsert logic, not only one UI route.

Kill lines

STOP if CSV import can change optedOutEmail from true to false.
STOP if CSV import can change doNotContact from true to false.
STOP if CSV import can change consentTier from opted_out/do_not_contact to subscribed/contactable.
STOP if CSV import can change emailStatus from unsubscribed/opted_out to active/subscribed.
STOP if suppression is only counted in the UI but not preserved in backend upsert logic.
STOP if suppressNewLeadAutoEnrollmentForContact is not called when an existing opt-out is detected.
STOP if import accounting becomes unreconciled.
STOP if this task changes contactability rules, sequence worker send logic, CAN-SPAM footer logic, or GHL sync.

Validation

Add:

scripts/test-csv-import-opt-out-preservation.ts

Test cases:

1. existing optedOutEmail=true + CSV optedOutEmail=false → remains true
2. existing doNotContact=true + CSV doNotContact=false → remains true

10. import totals remain reconciled
