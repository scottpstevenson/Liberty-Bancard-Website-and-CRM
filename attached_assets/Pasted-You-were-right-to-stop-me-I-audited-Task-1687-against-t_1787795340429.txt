## Merge-blocking task defects

1. **The prescribed pre-deploy path is unsafe for this audit.**

[`scripts/run-pre-deploy.sh`](https://github.com/scottpstevenson/Liberty-Bancard-Website-and-CRM/blob/78ae07e8c5ffb643467a93dc42b95834d65289a8/scripts/run-pre-deploy.sh) kills whatever owns port 5000, launches the app using inherited database/Redis configuration, and does not establish the disposable test boundaries required by Task #1687.

The task must explicitly prohibit running this wrapper against the normal Replit environment. It should instead reproduce the isolation used by [GitHub CI](https://github.com/scottpstevenson/Liberty-Bancard-Website-and-CRM/blob/78ae07e8c5ffb643467a93dc42b95834d65289a8/.github/workflows/ci.yml) through [`scripts/run-ci-suites.ts`](https://github.com/scottpstevenson/Liberty-Bancard-Website-and-CRM/blob/78ae07e8c5ffb643467a93dc42b95834d65289a8/scripts/run-ci-suites.ts).

2. **Release verification does not prove worker identity.**

[`scripts/verify-release-identity.ts`](https://github.com/scottpstevenson/Liberty-Bancard-Website-and-CRM/blob/78ae07e8c5ffb643467a93dc42b95834d65289a8/scripts/verify-release-identity.ts) checks the local checkout and public `/api/health` SHA only. It does not verify:

* Authenticated live health
* Relevant worker SHAs
* Worker topology
* Deployment metadata

Task #1687 needs a defined worker-identity procedure. The existing script cannot satisfy its completion criteria by itself.

3. **Existing runtime checks can report skipped checks as success.**

[`scripts/test-live-health.ts`](https://github.com/scottpstevenson/Liberty-Bancard-Website-and-CRM/blob/78ae07e8c5ffb643467a93dc42b95834d65289a8/scripts/test-live-health.ts) exits successfully when the server is unreachable. [`scripts/test-build-identity.ts`](https://github.com/scottpstevenson/Liberty-Bancard-Website-and-CRM/blob/78ae07e8c5ffb643467a93dc42b95834d65289a8/scripts/test-build-identity.ts) similarly skips live checks gracefully.

The certification wrapper must convert unreachable, skipped, missing-SHA, or stale-SHA results into `UNVERIFIED`, `ACCESS_REQUIRED`, or `DEPLOYMENT_REQUIRED`—never `PASS`.

4. **The authoritative 39-row register is not identified.**

The supplied register contains 39 rows, but the repository contains multiple historical evidence documents and register copies. The task does not specify the exact authoritative input.

It needs:

* Exact source filename/path
* The 39 expected row IDs
* A validator enforcing 39 unique rows
* Exactly one approved status per row
* Evidence date, expiry/recurrence, and owner fields
* Failure on missing, duplicate, or extra rows

5. **The browser certification is not executable as specified.**

[`scripts/smoke-role-guards.ts`](https://github.com/scottpstevenson/Liberty-Bancard-Website-and-CRM/blob/78ae07e8c5ffb643467a93dc42b95834d65289a8/scripts/smoke-role-guards.ts) is an HTTP status smoke test, not a comprehensive authenticated CRM browser suite. The live repository does not contain a complete Playwright CRM journey covering the Task #1687 requirements.

VG-04 must define the exact routes, fixtures, users, CSRF handling, expected states, screenshots, and provider fakes. Otherwise an executor could incorrectly treat role-smoke results as full UI certification.

6. **Production read-only access lacks a technical enforcement boundary.**

The task says “bounded read-only aggregates,” but does not require database-level enforcement. Add:

* `BEGIN READ ONLY`
* A strict `statement_timeout`
* Reviewed `SELECT` statements only
* Hard result limits
* Redacted or aggregated output
* No migrations, procedures, backfills, writes, `EXPLAIN ANALYZE`, or pre-deploy runner
* Query errors reported as failures—not zero counts
