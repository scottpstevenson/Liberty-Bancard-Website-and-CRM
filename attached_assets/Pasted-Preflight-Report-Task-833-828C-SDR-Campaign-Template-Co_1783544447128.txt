True Root Cause / What This Task Actually Needs
The content source already exists. The task is:

A dry-run script that queries the live DB to find which sequence/campaign step rows have empty or stub body/bodyTemplate/subject, maps them to available content in vertical-email-sms-templates.ts, flags which have no content source, and exports a backup JSON before touching anything.
An apply script that imports from existing content files (VERTICAL_OUTREACH_TEMPLATES and/or VERTICAL_SEQUENCES) to populate empty/stub rows, skips active sequences by default, logs every write, and never triggers sends or enrollment.
Any verticals not covered by the existing templates need new copy written in the apply script's content map — not as a separate step.

What the dry-run script must do:

Connect to DB via import { db } from "../server/db" (or pool)
Query all follow_up_sequences + their sequence_steps — report: name, status (active/paused), step count, empty subject count, empty body count, stub body count (strings matching: "TODO", "Placeholder", "Insert copy", "Hi {{firstName}}" with no CTA/value prop, body length < 100 chars)
Query all campaigns + their campaign_steps — same inventory on subject / bodyTemplate
For each empty/stub step, check if getVerticalTemplate(vertical) returns content — flag those without a match as "no content source / needs manual copy"

Export backup JSON to scripts/backfill-backup-<timestamp>.json before any mutation — include sequenceId/campaignId, stepId, name, status, subject, body/bodyTemplate, delayDays, delayHours, createdAt, updatedAt
Print full report to stdout. Exit without writing any DB records.
What the apply script must do:

Re-run the same target detection (or read from backup file)
Import VERTICAL_OUTREACH_TEMPLATES, getVerticalTemplate from server/services/vertical-email-sms-templates.ts
For each eligible empty/stub step:
Sequence steps: call updateSequenceStep(stepId, { subject, body }) — use body field
Campaign steps: call updateCampaignStep(stepId, { subject, bodyTemplate }) — use bodyTemplate field
Skip any step with non-stub existing content
Skip active sequences unless --include-active CLI flag is passed; log all active sequences that were skipped
Never touch status, enrolledAt, GHL fields, or any send queue
Log every changed record (id, sequence/campaign name, step order, before/after subject)
Do NOT activate sequences, enroll contacts, or trigger any send
