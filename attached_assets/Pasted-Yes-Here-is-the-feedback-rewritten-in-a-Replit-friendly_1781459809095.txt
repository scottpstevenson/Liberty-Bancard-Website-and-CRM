Liberty Bancard Replit Feedback / Implementation Review

Project Identity Clarification

This application should be treated as the internal AI operating system for Liberty Bancard, a merchant services sales and management company.

It is not a payment processor.

It is not a virtual terminal.

It should not store card numbers, run transactions, batch payments, issue refunds, or function like Square, Stripe, Clover, NMI, Authorize.net, or a gateway terminal.

The app’s purpose is to help Liberty Bancard:

* Generate merchant leads
* Run AI-assisted SDR outreach
* Qualify businesses
* Collect merchant statements
* Analyze pricing
* Generate proposals
* Manage the sales pipeline
* Onboard approved merchants
* Manage documents and support
* Track residuals
* Recruit partners and ISOs
* Retain merchants after onboarding

The core business goal is to become a scalable merchant services company that can compete against Square and Stripe on pricing, service, free terminal incentives, and hands-on onboarding.

High-Level Product Feedback

The platform already has a strong foundation. The public website, CRM, AI enrichment, proposal engine, onboarding foundation, partner portal, GHL sync, and operator dashboard are mostly in place.

The next stage should focus less on adding new broad features and more on closing the operational gaps that prevent the system from scaling.

The most important Replit focus areas are:

1. Fix all conversion paths so leads can actually book, upload statements, and enter the CRM correctly.
2. Complete the autonomous AI SDR orchestration loop.
3. Clean up GHL sync integrity, especially missing ghlContactId records.

Centralize Compliance Checks

Before any outbound action, call one compliance guard.

Example conceptual flow:

const allowed = await complianceService.canContact({
  contactId,
  channel: "sms",
  workflow: "auto_repair_sequence",
});
if (!allowed.ok) {
  await auditLog.create({
    type: "OUTREACH_BLOCKED",
    reason: allowed.reason,
    contactId,
  });
  return;
}

No email, SMS, call, voicemail, or workflow enrollment should bypass this check.
