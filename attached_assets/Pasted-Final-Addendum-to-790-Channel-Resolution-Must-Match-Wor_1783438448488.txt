Final Addendum to #790 — Channel Resolution Must Match Worker Execution

Approved to build.

This is a pre-enrollment safety gate. Keep it strictly scoped to autoEnrollFromTrigger() and tests.

Critical correction

Do not rely only on a single “primary channel” from triggerConfig.outboundChannels unless that is proven to be the same source used by processSequenceEnrollments.

Before implementing, inspect how the sequence worker determines the actual outbound channel for each step.

The pre-enrollment gate must evaluate the same channel set that the worker could execute.

Required channel-resolution behavior

For each matching active sequence, determine all outbound channels that could be used by that sequence.

Use the existing worker semantics, including:

triggerConfig.outboundChannels
channelsAllowed
sequenceSteps.actionType
worker default channel behavior

Expected examples:

email-only sequence → evaluate email
SMS sequence → evaluate sms
voice_ai sequence → evaluate voice_ai
ringless/voicemail_drop sequence → evaluate ringless_vm
mixed-channel sequence → evaluate every outbound channel before enrollment

If the sequence contains multiple outbound channels, the contact must pass all required channel gates before enrollment is created.

Do not allow this failure mode:

sequence contains email + sms
pre-enrollment only checks email
contact enrolls despite no SMS consent
worker blocks later

That still creates unsafe outbound intent.

Contactability call guard

Use the actual evaluateContactability signature from server/services/contactability.ts.

Do not invent unsupported args if campaignType is not part of the real signature.

If additional metadata is needed for audit context, pass it only through supported fields or write it in the separate audit log entry.

Audit behavior

When pre-enrollment contactability blocks:

do not create sequenceEnrollments row
log/audit auto_enrollment_blocked_contactability
include contactId
include sequenceId
include triggerType
include blocked channel
include reason
include consentTier/lifecycleStage if available

If evaluateContactability already writes a consent audit log internally, avoid noisy duplicate consent logs, but still create a sequence/auto-enrollment-specific audit record if that is the existing pattern.

Preserve execution gates

The existing worker gates must remain:

Gate (a) step-0/contactability pre-send gate
Gate (b) per-step contactability gate

This task adds a pre-write enrollment gate only.

Kill lines

STOP if autoEnrollFromTrigger only checks email for a sequence that can execute SMS, voice, or ringless steps.
STOP if autoEnrollFromTrigger creates an enrollment for any contact that fails contactability for any outbound channel used by the sequence.
STOP if Gate (a) or Gate (b) is removed, weakened, or bypassed.
STOP if manual confirmed enrollment behavior changes.
STOP if a new enrollment row is created for a blocked auto-enrollment attempt.
STOP if this task activates any sequence or sends outbound.

Required tests

Add/extend tests proving:

1. opted-out contact is blocked before enrollment write
2. missing-email contact is blocked for email sequence
3. missing-phone/no-consent contact is blocked for SMS-capable sequence
4. eligible contact is enrolled for email-only sequence
5. mixed-channel sequence requires every channel to pass
6. processSequenceEnrollments still re-checks contactability before send
