SEO Principles

1. Visible content first, schema second

Structured data must describe visible page content.

Do not add schema for content that is not visible to users.

Do not add misleading LocalBusiness, FAQ, review, rating, office, location, or trust markup.

2. Do not fake local presence

For /locations/:city/:industry pages:

* Do not create LocalBusiness schema with a city-specific address unless Liberty actually has a verified physical office/branch at that address.
* Prefer Organization/LocalBusiness schema for the real Liberty Bancard entity.
* Prefer Service schema with areaServed for city/region targeting when Liberty serves that market but does not have a physical location there.
* If the existing SEO helper only supports LocalBusiness, adapt it safely or create a Service/areaServed helper.

3. FAQ schema is optional/supportive, not the main SEO win

FAQ content can help users and page relevance.

FAQPage schema may be kept if it accurately mirrors visible FAQ content, but do not treat it as a guaranteed rich-result or ranking feature.

4. Thin-page guard must be careful

Do not blindly 404 existing pages just because they are short.

For programmatic pages:

* If a route is invalid or has no meaningful city/industry match, exclude it from sitemap and return 404.
* If a route is valid but thin, improve content and internal linking first.
* If a page cannot be made useful, recommend noindex or sitemap exclusion before destructive route removal.
* Do not create mass 404s for URLs that may already be indexed without explicitly documenting the impact.

5. Conversion routes must stay indexable

Do not accidentally block:

* homepage
* /free-smart-terminal
* /beat-square-stripe
* /0-percent-processing
* /free-analysis
* /upload-statement
* /get-started
* /merchant-application
* /compare/*
* /industries/*
* valid /locations/:city/:industry
* /partners
* valid glossary/blog/FAQ routes

Dashboard/admin/auth/private routes should not be indexed.

8. Programmatic Thin-Page Guard

The guard should consider:

* valid city exists
* valid industry exists
* route combination is allowed
* page has enough unique visible content
* page has city/industry-specific metadata
* page has internal links
* page has at least one conversion CTA
* page is not generated solely from an empty/default template

Implementation guidance:

* Exclude invalid/thin routes from sitemap.
* Return 404 only for invalid route combinations or pages with no meaningful content source.
* For valid but weak pages, prefer improving the template/content or adding a warning/report rather than mass 404.
* Document any excluded routes.

Do not create a brittle character-count-only gate. Use content length as one signal, not the only signal.
