### What you should set up

You need one reusable test-infrastructure pattern, not a permanent shared database for every task:

| Environment        | Purpose                                              | Recommendation                                                      |
| ------------------ | ---------------------------------------------------- | ------------------------------------------------------------------- |
| GitHub Actions     | Required merge verification                          | Already provisions disposable PostgreSQL 16 and Redis               |
| Replit development | Let Replit run stateful suites before returning work | Add a separate test-only PostgreSQL database as `TEST_DATABASE_URL` |
| Production         | Real application data                                | Never use for testing                                               |

The test database must:

* Be a completely separate database—not a schema inside production.
* Have a name containing `test` or `ci`, which Liberty’s guards require.
* Contain synthetic fixtures only.
* Be safe to migrate, truncate, reset, and destroy.
* Never share production credentials or copied production data.
* Be isolated per concurrent task/run when multiple branches are testing.

For test commands only, the process should point both variables at the disposable database:

```bash
NODE_ENV=test \
DATABASE_URL="$TEST_DATABASE_URL" \
TEST_DATABASE_URL="$TEST_DATABASE_URL" \
npx tsx scripts/run-ci-suites.ts --capability deterministic-integration
```

Do not permanently replace Replit’s normal `DATABASE_URL`. The override should apply only to the test process.
