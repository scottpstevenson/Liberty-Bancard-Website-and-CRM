Final Addendum to #791 — CAN-SPAM Footer Injection

Approved to build with these corrections.

This task is required before automated cold email outreach can be enabled.

Core verdict

The correct fix is platform-level footer injection at send time, not a manual emailComplianceVerified flag as the primary solution.

Every automated cold outreach email must include:

unsubscribe / opt-out link
physical mailing address
sender identity

and cold sends must be blocked if the platform cannot generate those elements.

⸻

Critical correction 1 — HMAC token must include a parseable payload

Do not generate a token that is only:

HMAC(contactId + "|" + email)

A raw HMAC digest cannot be decoded to find the contact.

Use a signed token format that includes a non-sensitive payload plus a signature.

Preferred token shape:

base64url(payload).signature

Payload example:

{
  "contactId": 123,
  "purpose": "email_unsubscribe"
}

Signature:

HMAC-SHA256(base64url(payload), UNSUBSCRIBE_TOKEN_SECRET)

Acceptable simpler format:

contactId.signature

where:

signature = HMAC-SHA256("email_unsubscribe:" + contactId, UNSUBSCRIBE_TOKEN_SECRET)

Do not put the contact’s email address in plaintext inside the token.

If email binding is required, use a hash of normalized email, not raw email:

emailHash = sha256(normalizedEmail)

But simplest/cleanest is contactId + purpose-scoped HMAC.

⸻

Critical correction 2 — No insecure fallback secret in production

Do not use this in production:

process.env.SESSION_SECRET || "liberty-unsub-key"

That creates predictable unsubscribe tokens if the env var is missing.

Required behavior:

UNSUBSCRIBE_TOKEN_SECRET set → generate unsubscribe links
UNSUBSCRIBE_TOKEN_SECRET missing in production → block cold email send
TEST_MODE=true → may use deterministic test secret

Acceptable fallback order:

UNSUBSCRIBE_TOKEN_SECRET
SESSION_SECRET
test-only fallback when TEST_MODE=true

Kill line:

STOP if production can generate unsubscribe tokens using a hardcoded fallback secret.

⸻

Critical correction 3 — Footer requires public base URL

The unsubscribe link must be absolute in the email body.

Use a configured public URL such as:

PUBLIC_APP_URL
APP_BASE_URL

Example:

https://libertybancard.com/unsubscribe?t=<token>

If no public base URL is configured for production cold outreach, block the cold send with a clear audit reason:

sequence_send_blocked_no_unsubscribe_base_url

Do not inject relative links like:

/unsubscribe?t=...

into outbound email.

⸻

Critical correction 4 — Missing mailing address should not cause retry spam

If compliance_mailing_address is unset, the cold email step must not send.

But the worker must also avoid retrying the same blocked step every cycle and writing the same audit log repeatedly.

Required behavior:

block send
do not mark step sent
do not advance enrollment
record clear blocked/deferred reason
avoid duplicate audit spam for the same enrollment/step/reason

Use the existing worker status pattern if available:

paused
blocked
deferred
requires_configuration

Do not mark the enrollment permanently failed if this is a fixable admin configuration issue.

⸻

Cold outreach scope

Use conservative detection.

Cold outreach is:

sequence.sequenceFamily === "cold-email-manual-call"
OR triggerType IN ("contact_created", "form_submitted")

If uncertain whether a sequence is commercial/cold, prefer injecting the footer rather than omitting it.

Transactional examples that should not require the cold footer:

closed_won
onboarding_step
merchant_welcome
no_show
support/ticket operational emails

Do not break transactional email sends.

⸻

Footer injection point

Inject after the normal signature:

interpolated body
+ getEmailSignatureHtml("sales")
+ getComplianceFooterHtml(...)

Only for cold outreach email sends.

The footer helper should HTML-escape or sanitize system-setting values, especially:

mailing address
company name
sender display text

Do not inject unsanitized admin-configured text into HTML.

⸻

Unsubscribe endpoint requirements

Add public endpoint:

GET /unsubscribe?t=<signed-token>

Required behavior:

valid token → set contacts.optedOutEmail = true
already opted out → still show success confirmation
invalid token → show safe invalid/expired message, do not update contact
write audit log on valid unsubscribe
do not require auth
do not expose contact details

The endpoint must be idempotent.

Audit action:

contact_email_unsubscribed_via_link

Include:

contactId
source: "email_footer"
timestamp

Do not log the raw token.

⸻

Existing contactability must remain authoritative

This task does not replace contactability.

Required:

optedOutEmail=true still blocks via contactability
sequence worker still checks contactability before send
pre-enrollment gate from #790 still remains

Kill line:

STOP if opted-out contacts can receive email after clicking unsubscribe.

⸻

Admin settings requirement

Add or reuse a system setting:

compliance_mailing_address

Add admin UI somewhere appropriate, such as:

System Settings
GHL Settings
Go-Live Controls

Show warning if empty:

Cold email outreach blocked — mailing address required.

Also warn if unsubscribe token/base URL config is missing.

⸻

Tests required

Extend scripts/test-sequence-compliance.ts or add a targeted test proving:

cold outreach email body includes unsubscribe link
cold outreach email body includes physical mailing address
cold outreach send is blocked when compliance_mailing_address is missing
cold outreach send is blocked when unsubscribe token secret/base URL is missing in production-like mode
transactional sequence does not receive cold footer
valid unsubscribe token sets optedOutEmail=true
invalid unsubscribe token does not update contact
opted-out contact remains blocked by contactability

Tests must not send real email.

Use:

TEST_MODE=true SKIP_AI=true DRY_RUN=true

⸻

Kill lines

STOP if any automated cold sequence email can send without an unsubscribe link.
STOP if any automated cold sequence email can send without a physical mailing address.
STOP if cold email sends with a hardcoded production unsubscribe secret.
STOP if cold email sends with a relative or missing unsubscribe URL.
STOP if /unsubscribe can opt out a contact without a valid signed token.
STOP if invalid tokens reveal contact existence or private details.
STOP if opted-out contacts can still receive email.
STOP if transactional sequence emails are broken by this change.
STOP if the worker repeatedly logs the same missing-address block every cycle with no dedupe/defer state.
STOP if any real email is sent during validation.

⸻
