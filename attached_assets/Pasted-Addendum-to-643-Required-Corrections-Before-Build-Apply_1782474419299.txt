Addendum to 643 — Required Corrections Before Build

Apply these corrections to the existing 643 prompt before building.

1. Sticky dock must have a scroll threshold

The dock should not appear on initial hero load while the hero CTAs are visible.

Requirement:

StickyMobileCTA appears only after the hero CTA area scrolls out of view, or after a verified scroll threshold.

Do not show duplicate Upload/Book actions on first paint.

If implementing with IntersectionObserver, observe the hero CTA block and show the dock only when that block is no longer visible.

2. Bottom padding must be based on actual dock height

Do not guess bottom spacing.

Add a mobile bottom spacing contract:

Home main/content wrapper must reserve bottom padding equal to sticky dock height + safe-area inset + at least 24px.

If dock height changes, content should still clear it.

Acceptance:

At 390px, the bottom of every card, form field, CTA, and final section can scroll fully above the dock.

3. Header clipping fix should not be magic-number-only

Increasing pt-28 may help, but it is fragile because the compliance strip can wrap differently by device/font.

Preferred:

* define a mobile header offset variable or measured layout value if feasible
* otherwise use a conservative mobile offset that covers the two-line compliance strip at 390px
* add scroll-margin-top to Home sections
* validate by scrolling to every section start

Kill line:

Stop if section headings are still clipped behind the header after natural scroll or anchor-style navigation.

4. Chat should be hidden/minimized on Home mobile if it cannot coexist cleanly

Do not keep fighting the bubble placement.

If chat still overlaps content after repositioning, then on Home mobile:

hide the floating chat bubble while the sticky dock is visible

or expose chat from a smaller secondary affordance.

Priority order:

1. readable content
2. upload conversion dock
3. chat bubble

Chat must not cover CTAs, calculator fields, report rows, terminal cards, testimonial cards, or final CTA.

5. Sticky dock must not remain three equal columns

The current prompt says this, but make it a hard kill line.

Kill line:

Stop if the mobile dock still visually reads as three equal tabs: Call | Book | Upload.

Upload must be the primary action.

Preferred hierarchy:

Primary: Upload Statement — Free
Secondary: Call
Secondary: Book

6. Terminal table must be fully removed on mobile

The desktop table can remain, but mobile must not render the four-column table at all.

Requirement:

Use md:hidden stacked setup cards for mobile and hidden md:block for the desktop table.

Kill line:

Stop if a four-column terminal setup table is visible at 390px or 430px.

7. Strategy cards and vertical cards must not simply become hidden content

Accordions are fine, but the first mobile view must still show enough value.

For Strategy:

* show one-line summary per accordion trigger
* keep CTA inside the expanded panel
* default-expand the most important option only if it does not add too much height

For Verticals:

* show top 2–3 priority industries
* collapse or link out to the rest
* do not stack all six full cards

8. Reviews mobile section must remove duplicate/low-value content

Mobile should show:

one strong testimonial card
one compact CTA to view more / case studies

Do not show three testimonial cards plus three outcome cards stacked.

9. Platform Preview should be desktop-only

Confirmed requirement:

Platform Preview / CRM dashboard screenshot section should be hidden on mobile.

It is not part of the mobile merchant conversion path.

10. “Desktop pixel-identical at 1024px+” needs a practical interpretation

Because global components are touched, desktop should be visually unchanged for content sections at 1024px+.

But mobile-only dock/chat/header fixes may change behavior below desktop breakpoints.

Acceptance:

Home content layout at 1024px, 1280px, and 1440px remains unchanged except for global overlay bug fixes if they are visible.

11. Validation must include real overlay states

Screenshots must include:

* dock hidden on hero first paint
* dock visible after scroll
* chat + dock together
* calculator focused/keyboard state if possible
* bottom of terminal card/table section
* bottom of final CTA
* section heading immediately after scrolling to it

12. Final report must include before/after screenshot count

Final report must state:

Approximate 390px screenshot count before: 25+
Approximate 390px screenshot count after: __

Target remains:

10–14 meaningful screenshots

If still above 18, task is not complete unless there is a clear product reason.
