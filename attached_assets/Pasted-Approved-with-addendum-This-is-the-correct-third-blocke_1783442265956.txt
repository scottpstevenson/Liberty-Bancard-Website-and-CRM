Final Addendum to #792 — Global Outreach Kill Switch + Send Caps

Approved to build.

This task is required before semi-auto or full-auto outreach.

Critical correction 1 — Kill switch must not rely on stale cache

Do not use a 60-second cache for the global outbound pause unless there is explicit cache invalidation when the setting changes.

Required behavior:

admin toggles pause
sequence worker sees pause before next send attempt

Acceptable:

no cache for outboundGlobalPaused
very short cache, e.g. 1-5 seconds
cache invalidated immediately on PATCH /api/system/outbound-settings

Not acceptable:

admin pauses outreach
worker keeps sending for up to 60 seconds

Kill line:

STOP if the global kill switch can remain stale long enough for additional sequence sends after pause is enabled.

⸻

Critical correction 2 — Daily cap must be durable and atomic

Do not use only an in-memory send counter.

Daily send caps must survive worker restart and must be safe if multiple workers/ticks run.

Preferred approach:

durable outbound_send_counters table
keyed by date + channel + scope
atomic increment/reservation

Example fields:

date
channel
scope
count
updatedAt

Acceptable alternative:

query/audit count of successful sequence email sends for the current day

Only use system settings for static config like:

outbound_global_paused
outbound_global_paused_reason
outbound_daily_email_cap

Do not store a fragile daily mutable counter in a generic settings blob unless the update is atomic.

Kill line:

STOP if two concurrent worker ticks can both see sendsToday below cap and send past the cap.

⸻

Cap scope clarification

The daily cap should apply to automated cold outreach email sends by default.

Use the same cold-outreach scope from #791:

sequenceFamily === "cold-email-manual-call"
OR triggerType IN ("contact_created", "form_submitted")

Do not accidentally throttle merchant onboarding, support/ticket, or other transactional sequence emails unless the product explicitly wants a true all-email emergency cap.

Global pause may block all sequence outbound sends. Daily cap should be cold outreach email only unless separately configured.

⸻

Send reservation behavior

To avoid race conditions:

check cap
reserve/increment atomically before send attempt
if send fails before provider acceptance, release/decrement if practical
if send succeeds, keep count

If the current worker is single-threaded and no race exists, document that. But still prefer durable counting because this is a go-live safety control.

⸻

Block/defer behavior

When global pause or daily cap blocks a step:

do not mark sent
do not advance enrollment
do not permanently fail enrollment
defer/paused/blocked using an existing valid status
record reason
avoid repeated audit spam for the same enrollment + step + reason

Required audit actions:

sequence_step_skipped_global_pause
sequence_step_deferred_daily_cap

⸻

Admin endpoint guard

Endpoints:

GET /api/system/outbound-settings → admin/manager
PATCH /api/system/outbound-settings → admin only

The GET response should expose safe status only:

{
  outboundGlobalPaused: boolean;
  outboundGlobalPausedReason?: string | null;
  outboundDailyEmailCap: number;
  coldEmailSendsToday: number;
  coldEmailRemainingToday: number;
}

Do not expose secrets, provider credentials, or channel env values.

⸻

UI placement

Preferred location:

Go-Live Controls / Activation Panel

This is more appropriate than hiding the kill switch only in Operator Dashboard.

Display:

Global outbound pause toggle
Pause reason
Daily cold email cap
Sends today
Remaining today

⸻

Kill lines

STOP if sequence-worker sends while DB-persisted outboundGlobalPaused is true.
STOP if pause state resets on server restart.
STOP if a stale cache lets sends continue after pause is enabled.
STOP if automated cold email can exceed the configured daily cap.
STOP if the send cap is in-memory only.
STOP if cap checks are not concurrency-safe.
STOP if SMS/voice/ringless is enabled by this task.
STOP if GHL credentials or channel env flags are changed.
STOP if contactability or opt-out suppression is weakened.
