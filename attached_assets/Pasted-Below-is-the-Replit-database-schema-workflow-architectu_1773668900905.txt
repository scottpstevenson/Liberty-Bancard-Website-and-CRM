Below is the Replit database schema + workflow architecture I’d give your dev team for Liberty Bancard.

The goal is simple:

Replit = brain + data model + orchestration
GoHighLevel = action layer + CRM + conversations + booking

⸻

1. System design principle

Use Replit for:
	•	lead discovery
	•	dedupe
	•	enrichment
	•	scoring
	•	orchestration
	•	compliance logic
	•	analytics
	•	routing
	•	AI decisioning

Use GHL for:
	•	contacts
	•	opportunities
	•	email sends
	•	SMS sends
	•	voice AI entry
	•	calendars
	•	chat widget
	•	workflows
	•	rep visibility

So the system becomes:

Sources -> Replit DB -> Scoring/Rules/AI -> GHL Actions -> Webhooks back to Replit

4. Worker architecture in Replit

These are the services I’d create.

1. lead_finder_worker

Finds net new businesses.

Responsibilities:
	•	run nightly searches by vertical + geo
	•	import Google Maps/Yelp/etc.
	•	normalize raw business data
	•	create businesses or queue dedupe
	•	create lead_sources
	•	enqueue enrichment jobs

Runs:
	•	nightly
	•	plus optional daytime micro-jobs

⸻

2. dedupe_worker

Canonical identity engine.

Responsibilities:
	•	compare incoming lead against existing businesses
	•	merge or attach alias if match found
	•	create new business if no match
	•	link source records properly

Matching logic:
	•	exact domain
	•	exact phone
	•	google place id
	•	fuzzy normalized name + city/state
	•	address similarity

⸻

3. enrichment_worker

Builds merchant profile.

Responsibilities:
	•	website lookup
	•	email discovery
	•	phone validation
	•	business category cleanup
	•	processor detection
	•	ad activity detection
	•	social profile discovery

Writes to:
	•	contacts
	•	enrichment_runs
	•	processor_signals
	•	ad_signals

⸻

4. scoring_worker

Creates the score and routing decision.

Responsibilities:
	•	calculate weighted score
	•	generate score reasoning
	•	classify into hot/warm/nurture/hold
	•	create/update sdr_pipeline
	•	decide next action time

Example routing:
	•	hot -> immediate outreach
	•	warm -> same-day queue
	•	nurture -> delayed sequence
	•	hold -> re-enrich later

⸻

5. ghl_sync_worker

Sync between Replit and GoHighLevel.

Responsibilities:
	•	create/update contact in GHL
	•	create opportunity
	•	add tags/custom fields
	•	enroll workflows if needed
	•	sync back ghl ids into Replit

Rule:
Replit creates truth. GHL reflects action state.

⸻

6. sdr_orchestrator

This is the main brain.

Runs every 5 minutes.

Responsibilities:
	•	scan sdr_pipeline for leads due for action

	•	choose channel
	•	choose sending identity

	•	log result in outreach_attempts

This is your highest-value service.

5. Example end-to-end workflow

Flow 1: New lead from Google Maps
	1.	lead_finder_worker pulls “med spa tampa fl”
	2.	Raw record enters system
	3.	dedupe_worker checks against canonical business
	4.	New businesses row created
	5.	lead_sources row created
	6.	enrichment_worker finds website, email, phone
	7.	processor_signals detects Square
	8.	ad_signals shows active Facebook ads
	9.	scoring_worker gives 91 score, band hot
	10.	sdr_pipeline row created with next_action_type=email
	11.	ghl_sync_worker creates contact + opportunity in GHL
	12.	sdr_orchestrator sends Email 1 from lowest-load identity
	13.	outreach_attempts row created
	14.	GHL webhook returns open/reply later
	15.	intent_classifier_worker classifies reply
	16.	If interested, stage moves to engaged
	17.	Meeting booked
	18.	Statement requested
	19.	Statement uploaded
	20.	Proposal sent
	21.	Closed won
	22.	Onboarding starts

⸻

Flow 2: STOP via SMS
	1.	SMS reply received via webhook
	2.	inbound_webhook_worker stores inbound message
	3.	intent_classifier_worker marks as stop
	4.	suppression_list adds phone + contact + business block
	5.	sdr_pipeline.current_stage = suppressed
	6.	all future channels blocked

That has to be instant and global.

7. Orchestrator rules

These are the rules your devs should implement first.

Email escalation example
	•	if hot and not contacted -> Email 1 now
	•	if no reply after 48h -> SMS 1
	•	if no reply after 96h -> Email 2
	•	if no reply after 144h and phone valid -> AI call
	•	if still no reply -> breakup email
	•	then move to nurture

If engaged
	•	if reply intent = interested -> book meeting CTA
	•	if reply intent = pricing_question -> send short answer + meeting link
	•	if reply intent = statement_ready -> send upload link immediately
	•	if reply intent = call_me -> queue AI/human callback
	•	if reply intent = stop -> suppress globally

Meeting rules
	•	meeting booked -> pause outbound
	•	meeting completed -> request statement same day
	•	no-show -> no-show recovery sequence
	•	statement not uploaded after day 2/5/7 -> reminders

8. Scoring logic example

Use a versioned function.

total_score =
fit_score * 0.25 +
revenue_score * 0.20 +
reachability_score * 0.15 +
priority_score * 0.15 +
processor_score * 0.15 +
growth_score * 0.10

Example scoring bands
	•	85–100 hot
	•	70–84 warm
	•	55–69 nurture
	•	<55 hold

Example score reasoning json

{
  "fit": "Med spa target vertical",
  "revenue": "200+ reviews and premium treatment menu",
  "reachability": "Validated email and phone present",
  "processor": "Square checkout script detected",
  "growth": "Active Facebook ads detected"
}

This will help your reps trust the model.

9. Canonical dedupe logic

This is critical.

Use a weighted match approach.

Strong matches
	•	same website domain
	•	same phone
	•	same google_place_id

Medium matches
	•	same normalized name + city/state
	•	same normalized address
	•	same facebook page

Fuzzy score idea
	•	domain match = 50
	•	phone match = 40
	•	google_place_id = 60
	•	normalized name similarity = up to 25
	•	address similarity = up to 20

If score >= threshold, merge.

On merge:
	•	preserve canonical business
	•	attach alias
	•	add source row
	•	only overwrite fields if new source is stronger/fresher

10. Compliance logic

Before every email/SMS/call, check:
	•	is contact/business suppressed?
	•	is phone/email hard bounced?
	•	did they reply STOP or unsubscribe?
	•	are we inside local quiet hours?
	•	are daily send caps hit?
	•	has this identity exceeded complaint threshold?
	•	is lead already closed or active customer?

Timezone inference order:
	1.	explicit location timezone
	2.	state/city mapping
	3.	GHL timezone if present
	4.	fallback based on area code

15. Bottom line

Your Liberty Bancard system should not be built like a normal CRM.

It should be built like an autonomous sales operating system:
	•	canonical merchant identity
	•	enrichment memory
	•	weighted scoring
	•	inbox rotation
	•	global compliance
	•	orchestrated next-best action
	•	full feedback loop from GHL back into Replit

That is the structure that lets this scale cleanly instead of turning into a mess once volume rises.
