The server-side filter is appropriate, but two assumptions are unsafe: “manual” cannot mean every value other than sla, and no standalone tasks.source index has been proven.

Corrections to send back

1. Audit existing source values before defining “Manual.”
Run:
SELECT source, COUNT(*)
FROM tasks
WHERE deleted_at IS NULL
GROUP BY source
ORDER BY source NULLS FIRST;
Do not define Manual as:
source <> 'sla' OR source IS NULL
That would silently classify future automated sources such as import, workflow,
system, or another SLA automation as Manual.
Use the actual canonical rule confirmed by the audit:
- If manual tasks currently use NULL only:
  source IS NULL
- If manual tasks explicitly use "manual":
  source IS NULL OR source = 'manual'
Any other source must not be mislabeled Manual.
2. Do not claim an existing tasks.source index without evidence.
The SLA partial unique index contains source in its predicate, but that does not
necessarily provide a usable general index for:
WHERE source = 'sla'
or
WHERE source IS NULL
Provide pg_indexes / schema evidence for a standalone applicable index.
Do not add a migration in this UI/filter task unless EXPLAIN shows the query is
actually slow at production volume. Remove the unsupported “leverages the existing
DB index” claim if no such index exists.
3. Reject invalid source values instead of silently ignoring them.
GET /api/tasks?source=garbage should return 400 using a small Zod/enum validation.
Silently treating an invalid filter as “all” can expose a much broader dataset than
the caller intended and makes cache/debug behavior ambiguous.
4. Preserve dealId behavior explicitly.
If dealId is present, document whether source is:
- intentionally ignored, or
- combined with the deal filter.
Do not accidentally accept ?dealId=123&source=sla while silently ignoring source.
If the dealId route remains unchanged, reject or clearly document unsupported
combined filtering.
5. Keep selection reset behavior from Task #926.
Changing source changes the server dataset. Immediately clear:
- selected task IDs
- select-all state
- any open bulk-action state

Keep the query key deterministic:
