Liberty Bancard Go-Live Activation Plan

Primary objective

Activate the first live revenue loop safely:

lead -> SDR outreach -> reply -> booked call -> statement request -> proposal -> close

Success definition for first launch

The system is considered live only when all of the below happen on real leads:
	•	leads are bridged into businesses
	•	sdr_merchants are created
	•	orchestrator selects leads without duplication
	•	at least 1 outbound email is successfully sent
	•	replies are captured and classified
	•	at least 1 lead is moved to human handoff or booked call
	•	no major compliance, deliverability, or data integrity failures occur

⸻

Phase 0: Launch rules

Before touching anything, make these rules official.

System rules
	•	New SDR pipeline is the only active outbound engine
	•	Legacy senders must be disabled
	•	businesses becomes canonical business entity
	•	sdr_merchants becomes canonical SDR execution entity
	•	First live motion is email only
	•	First cohort is 50–100 leads max
	•	First cohort should be one vertical, one geography
	•	Human review required before first live send

Kill switch rules

Pause all outbound if any of these happen:
	•	bounce rate exceeds 5%
	•	complaint/unsubscribe rate spikes unexpectedly
	•	duplicate send detected
	•	GHL webhook failures persist
	•	reply classification misroutes critical responses
	•	inbox reputation drops materially
	•	stage transition logic fails
	•	merchants receive messages without compliant consent logic where required

Phase 2: Data activation checklist

A. Bridge contacts into SDR pipeline

Do not bridge all 152K initially.

Pilot bridge scope
	•	50–100 high-confidence leads
	•	one vertical
	•	one geographic market
	•	ideally records with best email quality and clear business identity

Bridge actions
	•	map legacy contacts to canonical businesses
	•	create aliases and locations where needed
	•	create sdr_merchants
	•	initialize sdr_lead_state
	•	preserve original source attribution
	•	preserve consent/compliance fields where applicable

Acceptance criteria
	•	no duplicate canonical businesses for same entity
	•	no orphan SDR merchants
	•	lead source preserved
	•	stage initialized correctly
	•	records visible in SDR dashboard

⸻

B. Bridge Sunbiz hot/warm leads

Do this only after the contact pilot works.

Acceptance criteria
	•	enriched Sunbiz leads map cleanly to businesses
	•	dedupe rules prevent contact overlap
	•	no duplicate sends against already-bridged contacts
	•	source type remains traceable

Phase 3: First live outbound pilot

Pilot structure
	•	channel: email only
	•	cohort size: 50–100
	•	batch size: low
	•	vertical: one only
	•	geography: one only
	•	sending identity: one inbox
	•	review mode: manual approval before first send

Run order

Step 1: Dry run

Run orchestrator without sending:
	•	verify selection logic
	•	inspect excluded leads
	•	inspect scoring output
	•	inspect stage assignment
	•	inspect compliance gating

Step 2: Live send

Send first wave:
	•	monitor send success
	•	monitor bounce behavior
	•	monitor webhook capture
	•	monitor reply threading
	•	monitor classification labels

Step 3: Human follow-up verification

Ensure positive replies:
	•	create tasks or alerts
	•	move to correct stage
	•	book calls or request statements
	•	do not stall in inbox/thread state
