790 — Pre-Enrollment Contactability Gate for Auto Outreach

790 — Add Pre-Enrollment Contactability Gate to autoEnrollFromTrigger

What & Why

Preflight for #789 found that autoEnrollFromTrigger() creates sequence enrollment records before contactability is evaluated. Contactability is enforced later inside processSequenceEnrollments, so sends are blocked at execution time, but ineligible contacts can still be auto-enrolled.

For automated outreach, enrollment creation itself must be gated so the system does not create outbound intent for contacts that are opted out, missing required contact info, suppressed, bounced, or ineligible for the sequence channel.

Done Looks Like

* autoEnrollFromTrigger() evaluates contactability before writing an enrollment record.
* Contacts that fail contactability are not enrolled.
* Blocked auto-enrollment attempts are logged/audited with a clear reason.
* Existing manual enrollment behavior is unchanged.
* Existing sequence worker execution-time contactability gates remain in place.
* No SMS, voice, ringless, GHL workflow, or email is sent during validation.

Required Changes

In server/services/sequence-worker.ts, update autoEnrollFromTrigger() so that before createSequenceEnrollment or equivalent write:

1. Load the target sequence and steps.
2. Determine required outbound channel(s).
3. Run evaluateContactability or the existing canonical enforcement path.
4. If blocked, do not create the enrollment.
5. Log/audit blocked reason.
6. If allowed, create the enrollment as before.

Important

Keep the existing execution-time gates inside processSequenceEnrollments.

This task adds a pre-enrollment gate. It does not replace send-time enforcement.

Kill Lines

STOP if autoEnrollFromTrigger can create an enrollment for an opted-out contact.
STOP if autoEnrollFromTrigger can create an enrollment for a contact missing required email/phone for the sequence channel.
STOP if execution-time contactability gates are removed or weakened.
STOP if manual confirmed enrollment behavior changes.
STOP if SMS/voice/ringless gates are weakened.
STOP if this task activates any sequence or sends outbound messages.

792 — Global Outreach Kill Switch and Send Caps

792 — Add Global Outreach Kill Switch and Sequence Worker Send Caps

What & Why

Preflight for #789 found that globalPaused only affects the SDR orchestrator and is in-memory. The sequence worker does not check it, so an admin may believe outreach is paused while sequence sends continue.

The sequence worker also lacks platform-level daily send caps/throttles. Automated outreach needs a durable global pause and basic send caps before it can run unattended.

Done Looks Like

* A durable global outbound pause exists and is checked by the sequence worker before sending.
* Pause state survives server restart.
* Admin/manager can see whether outbound is paused.
* Sequence worker respects the pause before email/SMS/voice/ringless steps.
* Daily send caps exist for automated email outreach.
* Cap hits pause/skip further sends with a clear reason.
* No SMS/voice/ringless behavior is enabled by this task.

Required Changes

Add or reuse a persisted system setting such as:

outbound_global_paused: true/false
outbound_daily_email_cap: number

Before any sequence step send, the worker must check:

global outbound pause
channel enabled
daily cap remaining
contactability
opt-out/suppression
bounce status

If paused or capped, do not send. Mark/log the step as skipped/deferred with reason.
